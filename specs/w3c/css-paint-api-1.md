## 1. Introduction

The paint stage of CSS is responsible for painting the background,
content and highlight of a box based on that box's size (as generated by
the layout stage) and computed style.

This specification describes an API which allows developers to paint a
part of a box in response to size / computed style changes with an
additional
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image) function.

 In a future version of the spec, support could be added
for defining the clip, global alpha, filter on a portion of a box (for
example on the background layers).

## 2. Paint Worklet

The
[`paintWorklet`](#dom-css-paintworklet) attribute allows access to the
[`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet) responsible for all the classes which are related to
painting.

The
[`paintWorklet`](#dom-css-paintworklet)'s [worklet global scope
type](https://html.spec.whatwg.org/multipage/worklets.html#worklet-global-scope-type) is
[`PaintWorkletGlobalScope`](#paintworkletglobalscope).

The
[`paintWorklet`](#dom-css-paintworklet)'s [worklet destination
type](https://html.spec.whatwg.org/multipage/worklets.html#worklet-destination-type) is `"paintworklet"`.

```
partial namespace CSS {
 [SameObject] readonly attribute Worklet paintWorklet;
};
```

A
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) is a global execution context of the
[`paintWorklet`](#dom-css-paintworklet).

A
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) has a
[`devicePixelRatio`](#dom-paintworkletglobalscope-devicepixelratio) property which is identical to the
Window.[`devicePixelRatio`](https://drafts.csswg.org/cssom-view-1/#dom-window-devicepixelratio) property.

```
[Global=(Worklet,PaintWorklet),Exposed=PaintWorklet]
interface PaintWorkletGlobalScope : WorkletGlobalScope {
 undefined registerPaint(DOMString name, VoidFunction paintCtor);
 readonly attribute unrestricted double devicePixelRatio;
};
```

The
[`PaintRenderingContext2DSettings`](#dictdef-paintrenderingcontext2dsettings) contains the settings for the rendering context
associated with the paint canvas. The
[`PaintRenderingContext2DSettings`](#dictdef-paintrenderingcontext2dsettings) provides a supported subset of canvas rendering context
2D settings. In the future, it may be extended to support color
management in paint canvas.

```
dictionary PaintRenderingContext2DSettings {
 boolean alpha = true;
};
```

Note: The shape of the class should be:

```
class MyPaint {
 static get inputProperties() { return ['--foo']; }
 static get inputArguments() { return ['<color>']; }
 static get contextOptions() { return {alpha: true}; }

 paint(ctx, size, styleMap) {
 // Paint code goes here.
 }
}
```

## 3. Concepts

A [paint definition] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) about the author defined
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image) (which can be referenced by the
[\<paint()\>](#funcdef-paint) function). It consists of:

- [class constructor]
 which is the class
 [constructor](https://tc39.github.io/ecma262/#sec-constructor).

- [paint function] which is the
 paint
 [Function](https://drafts.csswg.org/css-syntax-3/#function) [callback
 function](https://webidl.spec.whatwg.org/#dfn-callback-function) type.

- [constructor valid flag].

- [input properties]
 which is a [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`.

- A [PaintRenderingContext2DSettings
 object].

A [document paint definition] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the
[document](https://dom.spec.whatwg.org/#clone-a-node-document) about the author defined
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image) function (which can be referenced by
the paint function). It consists of:

- A [input properties] which is a
 [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`.

- A [input argument
 syntaxes] which is a
 [list](https://infra.spec.whatwg.org/#list) of [syntax
 definitions](https://drafts.css-houdini.org/css-properties-values-api-1/#syntax-definition).

- A [PaintRenderingContext2DSettings
 object].

## 4. Registering Custom Paint

The
[document](https://dom.spec.whatwg.org/#clone-a-node-document) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [document paint
definitions]. Initially this map is empty; it is
populated when
[`registerPaint(name, paintCtor)`](#dom-paintworkletglobalscope-registerpaint) is called.

A
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [paint definitions]. Initially this map is empty;
it is populated when
[`registerPaint(name, paintCtor)`](#dom-paintworkletglobalscope-registerpaint) is called.

A
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [paint class instances]. Initially this map is empty;
it is populated when [draw a paint
image](#draw-a-paint-image)
is invoked by the user agent.

Instances of paint classes in the [paint class
instances](#paint-class-instances) map may be disposed and removed from the map by the
user agent at any time. This may be done when a
[\<paint()\>](#funcdef-paint) function no longer is used, or the user agent
needs to reclaim memory.

When the
[`registerPaint(``name``, ``paintCtor``)`] method is called, the user agent *must* run
the following steps:

1. If the `name` is an empty string,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps.

2. Let `paintDefinitionMap` be
 [`PaintWorkletGlobalScope`](#paintworkletglobalscope)'s [paint
 definitions](#paint-definitions) map.

3. If `paintDefinitionMap`\[`name`\]
 [exists](https://infra.spec.whatwg.org/#map-exists)
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 \"[`InvalidModificationError`](https://webidl.spec.whatwg.org/#invalidmodificationerror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException) and abort all these steps.

4. Let `inputProperties` be an empty `sequence<DOMString>`.

5. Let `inputPropertiesIterable` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`paintCtor`, \"inputProperties\").

6. If `inputPropertiesIterable` is not undefined, then set
 `inputProperties` to the result of
 [converting](https://webidl.spec.whatwg.org/#web-idl-arguments-list-converting) `inputPropertiesIterable` to a
 `sequence<DOMString>`. If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), rethrow the exception and abort all these steps.

7. Filter `inputProperties` so that it only contains
 [supported CSS
 properties](https://drafts.csswg.org/cssom-1/#supported-css-property) and [custom
 properties](https://drafts.csswg.org/css-variables-2/#custom-property).

 The list of CSS properties provided by the input
properties getter can either be custom or native CSS properties.

 The list of CSS properties may contain shorthands.

 In order for a paint image class to be forwards
compatible, the list of CSS properties can also contains currently
invalid properties for the user agent. For example
`margin-bikeshed-property`.

8. Let `inputArguments` be an empty `sequence<DOMString>`.

9. Let `inputArgumentsIterable` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`paintCtor`, \"inputArguments\").

10. If `inputArgumentsIterable` is not undefined, then set
 `inputArguments` to the result of
 [converting](https://webidl.spec.whatwg.org/#web-idl-arguments-list-converting) `inputArgumentsIterable` to a
 `sequence<DOMString>`. If an exception is thrown, rethrow the
 exception and abort all these steps.

11. Let `inputArgumentSyntaxes` be an
 [empty](https://infra.spec.whatwg.org/#list-empty)
 [list](https://infra.spec.whatwg.org/#list).

12. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `item` in `inputArguments`
 perform the following substeps:

 1. Attempt to [consume a syntax
 definition](https://drafts.css-houdini.org/css-properties-values-api-1/#consume-a-syntax-definition) from `item`. If failure was
 returned,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps. Otherwise, let
 `parsedSyntax` be the returned [syntax
 definition](https://drafts.css-houdini.org/css-properties-values-api-1/#syntax-definition).

 2. [Append](https://infra.spec.whatwg.org/#list-append) `parsedSyntax` to
 `inputArgumentSyntaxes`.

13. Let `contextOptionsValue` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`paintCtor`, \"contextOptions\").

14. Let `paintRenderingContext2DSettings` be the result of
 [converting](https://webidl.spec.whatwg.org/#web-idl-arguments-list-converting) `contextOptionsValue` to a
 [`PaintRenderingContext2DSettings`](#dictdef-paintrenderingcontext2dsettings). If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), rethrow the exception and abort all these steps.

 Setting `paintRenderingContext2DSettings.alpha` is
 `false` allows user agents to anti-alias text in addition to
 performing \"visibility\" optimizations, e.g. not painting an image
 behind the paint image as the paint image is opaque.

15. If the result of
 [IsConstructor](https://tc39.github.io/ecma262/#sec-isconstructor)(`paintCtor`) is false,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps.

16. Let `prototype` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`paintCtor`, \"prototype\").

17. If the result of
 [Type](https://tc39.github.io/ecma262/#sec-ecmascript-data-types-and-values)(`prototype`) is not Object,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps.

18. Let `paintValue` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`prototype`, \"paint\").

19. Let `paint` be the result of
 [converting](https://webidl.spec.whatwg.org/#web-idl-arguments-list-converting) `paintValue` to the
 [Function](https://drafts.csswg.org/css-syntax-3/#function) [callback
 function](https://webidl.spec.whatwg.org/#dfn-callback-function) type. Rethrow any exceptions from the conversion.

20. Let `definition` be a new [paint
 definition](#paint-definition) with:

 - [class
 constructor](#paint-definition-class-constructor) being `paintCtor`.

 - [paint
 function](#paint-definition-paint-function) being `paint`.

 - [constructor valid
 flag](#paint-definition-constructor-valid-flag) being **true**.

 - [input
 properties](#paint-definition-input-properties) being `inputProperties`.

 - [PaintRenderingContext2DSettings
 object](#paint-definition-paintrenderingcontext2dsettings-object) being
 `paintRenderingContext2DSettings`.

21. [Set](https://infra.spec.whatwg.org/#map-set)
 `paintDefinitionMap`\[`name`\] to
 `definition`.

22. [Queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task) to run the following steps:

 1. Let `documentPaintDefinitionMap` be the associated
 [document's](https://dom.spec.whatwg.org/#clone-a-node-document) [document paint
 definitions](#document-paint-definitions)
 [map](https://infra.spec.whatwg.org/#ordered-map).

 2. Let `documentDefinition` be a new [document paint
 definition](#document-paint-definition) with:

 - [input
 properties](#document-paint-definition-input-properties) being `inputProperties`.

 - [input argument
 syntaxes](#document-paint-definition-input-argument-syntaxes) being `inputArgumentSyntaxes`.

 - [PaintRenderingContext2DSettings
 object](#document-paint-definition-paintrenderingcontext2dsettings-object) being
 `paintRenderingContext2DSettings`.

 3. If `documentPaintDefinitionMap`\[`name`\]
 [exists](https://infra.spec.whatwg.org/#map-exists), run the following steps:

 1. Let `existingDocumentDefinition` be the result of
 [get](https://infra.spec.whatwg.org/#map-get)
 `documentPaintDefinitionMap`\[`name`\].

 2. If `existingDocumentDefinition` is `"invalid"`,
 abort all these steps.

 3. If `existingDocumentDefinition` and
 `documentDefinition` are not equivalent, (that is
 [input
 properties](#document-paint-definition-input-properties), [input argument
 syntaxes](#document-paint-definition-input-argument-syntaxes), and [PaintRenderingContext2DSettings
 object](#document-paint-definition-paintrenderingcontext2dsettings-object) are different), then:

 [Set](https://infra.spec.whatwg.org/#map-set)
 `documentPaintDefinitionMap`\[`name`\]
 to `"invalid"`.

 Log an error to the debugging console stating that the same
 class was registered with different `inputProperties`,
 `inputArguments`, or `paintRenderingContext2DSettings`.

 4. Otherwise,
 [set](https://infra.spec.whatwg.org/#map-set)
 `documentPaintDefinitionMap`\[`name`\] to
 `documentDefinition`.

 The list of input properties should only be looked up
once, the class doesn't have the opportunity to dynamically change its
input properties.

 In a future version of the spec, the author could have
the ability to receive a different type of RenderingContext. In
particular the author may want a WebGL rendering context to render 3D
effects. There are complexities in setting up a WebGL rendering context
to take the [`PaintSize`](#paintsize) and
[`StylePropertyMap`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymap) as inputs.

## 5. Paint Notation

``` prod
paint() = paint( <ident>, <declaration-value>? )
```

The [\<paint()\>](#funcdef-paint) function is an additional notation to
be supported by the
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image) type.

```
<style>
 .logo { background-image: paint(company-logo); }
 .chat-bubble { background-image: paint(chat-bubble, blue); }
</style>
```

For the
[cursor](https://drafts.csswg.org/css-ui-4/#propdef-cursor) property, the
[\<paint()\>](#funcdef-paint) function should be treated as an [invalid
image](https://drafts.csswg.org/css-images-4/#invalid-image) and fallback to the next supported
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image).

At [computed
value](https://drafts.csswg.org/css-cascade-5/#computed-value) time the
[\<paint()\>](#funcdef-paint) function does *not* need to match the grammar
registered by
[`registerPaint()`](#dom-paintworkletglobalscope-registerpaint). Instead this will result in an [invalid
image](https://drafts.csswg.org/css-images-4/#invalid-image) when the parsing occurs inside [draw a paint
image](#draw-a-paint-image).

## 6. The 2D rendering context

```
[Exposed=PaintWorklet]
interface PaintRenderingContext2D ;
PaintRenderingContext2D includes CanvasState;
PaintRenderingContext2D includes CanvasTransform;
PaintRenderingContext2D includes CanvasCompositing;
PaintRenderingContext2D includes CanvasImageSmoothing;
PaintRenderingContext2D includes CanvasFillStrokeStyles;
PaintRenderingContext2D includes CanvasShadowStyles;
PaintRenderingContext2D includes CanvasRect;
PaintRenderingContext2D includes CanvasDrawPath;
PaintRenderingContext2D includes CanvasDrawImage;
PaintRenderingContext2D includes CanvasPathDrawingStyles;
PaintRenderingContext2D includes CanvasPath;
```

 The
[`PaintRenderingContext2D`](#paintrenderingcontext2d) implements a subset of the
[`CanvasRenderingContext2D`](https://html.spec.whatwg.org/multipage/canvas.html#canvasrenderingcontext2d) API. Specifically it doesn't implement the
[`CanvasImageData`](https://html.spec.whatwg.org/multipage/canvas.html#canvasimagedata),
[`CanvasUserInterface`](https://html.spec.whatwg.org/multipage/canvas.html#canvasuserinterface),
[`CanvasText`](https://html.spec.whatwg.org/multipage/canvas.html#canvastext), or
[`CanvasTextDrawingStyles`](https://html.spec.whatwg.org/multipage/canvas.html#canvastextdrawingstyles) APIs.

A
[`PaintRenderingContext2D`](#paintrenderingcontext2d) object has a [output
bitmap]. This is
initialised when the object is created. The size of the [output
bitmap](#paintrenderingcontext2d-output-bitmap) is the [concrete object
size](https://drafts.csswg.org/css-images-3/#concrete-object-size) of the object it is rendering to.

A
[`PaintRenderingContext2D`](#paintrenderingcontext2d) object also has an
[alpha] flag,
which can be set to true or false. Initially, when the context is
created, its alpha flag must be set to true. When a
[`PaintRenderingContext2D`](#paintrenderingcontext2d) object has its alpha flag set to false, then its alpha
channel must be fixed to 1.0 (fully opaque) for all pixels, and attempts
to change the alpha component of any pixel must be silently ignored.

The size of the [output
bitmap](#paintrenderingcontext2d-output-bitmap) does not necessarily represent the size of the actual
bitmap that the user agent will use internally or during rendering. For
example, if the visual viewport is zoomed the user agent may internally
use bitmaps which correspond to the number of device pixels in the
coordinate space, so that the resulting rendering is of high quality.

Additionally the user agent may record the sequence of drawing
operations which have been applied to the [output
bitmap](#paintrenderingcontext2d-output-bitmap) such that the user agent can subsequently draw onto a
device bitmap at the correct resolution. This also allows user agents to
re-use the same output of the [output
bitmap](#paintrenderingcontext2d-output-bitmap) repeatably while the visual viewport is being zoomed
for example.

Whenever `"currentColor"` is used as a color in the
[`PaintRenderingContext2D`](#paintrenderingcontext2d) API, it is treated as opaque black.

The code below will produce a solid
black rectange.

```
registerPaint('currentcolor', class {
 paint(ctx, size) {
 ctx.fillStyle = 'currentColor';
 ctx.fillRect(0, 0, size.width, size.height);
 }
});
```

When the user agent is to [create a PaintRenderingContext2D
object] for a given `width`,
`height`, and `paintRenderingContext2DSettings`,
it *must* run the following steps:

1. Create a new
 [`PaintRenderingContext2D`](#paintrenderingcontext2d).

2. [Set bitmap
 dimensions](https://html.spec.whatwg.org/multipage/canvas.html#concept-canvas-set-bitmap-dimensions) for the context's [output
 bitmap](#paintrenderingcontext2d-output-bitmap) to the rounded values of `width` and
 `height`.

3. Set the
 [`PaintRenderingContext2D`](#paintrenderingcontext2d)'s
 [alpha](#paintrenderingcontext2d-alpha) flag to
 `paintRenderingContext2DSettings`'s
 [`alpha`](#dom-paintrenderingcontext2dsettings-alpha).

4. Return the new
 [`PaintRenderingContext2D`](#paintrenderingcontext2d).

 The initial state of the rendering context is set
inside the [set bitmap
dimensions](https://html.spec.whatwg.org/multipage/canvas.html#concept-canvas-set-bitmap-dimensions) algorithm, as it invokes [reset the rendering context
to its default
state](https://html.spec.whatwg.org/multipage/canvas.html#reset-the-rendering-context-to-its-default-state) and clears the [output
bitmap](#paintrenderingcontext2d-output-bitmap).

### 6.1. Drawing a CSSImageValue

The
[`CanvasImageSource`](https://html.spec.whatwg.org/multipage/canvas.html#canvasimagesource) typedef is extended to also include the
[`CSSImageValue`](https://drafts.css-houdini.org/css-typed-om-1/#cssimagevalue) type to be used as an image source.

For interfaces which use the
[`CanvasDrawImage`](https://html.spec.whatwg.org/multipage/canvas.html#canvasdrawimage) mixin:

- When a
 [`CanvasImageSource`](https://html.spec.whatwg.org/multipage/canvas.html#canvasimagesource) object represents an
 [`CSSImageValue`](https://drafts.css-houdini.org/css-typed-om-1/#cssimagevalue), the result of invoking the value's underlying image
 algorithm must be used as the source image for the purposes of
 [`drawImage`](https://html.spec.whatwg.org/multipage/canvas.html#dom-context-2d-drawimage).

 This should eventually be moved to the canvas section
of the HTML specification. See [Issue
819](https://github.com/w3c/css-houdini-drafts/issues/819).

## 7. Drawing an image

If a [\<paint()\>](#funcdef-paint) function image for a
[box](https://drafts.csswg.org/css-display-4/#box) is within the visual viewport, the user agent *must*
display an image output from an invocation of the [draw a paint
image](#draw-a-paint-image) algorithm.

 The user agent doesn't have to run [draw a paint
image](#draw-a-paint-image) each frame for a
[\<paint()\>](#funcdef-paint) function within the visual viewport. It can cache
results, (potentially using additional invalidation steps) to display
the correct image output.

 The user agent can optionally defer drawing images
which are outside the visual viewport.

If an author updates a style inside a
`requestAnimationFrame`, e.g.

```
requestAnimationFrame(function() {
 element.styleMap.set('--custom-prop-invalidates-paint', 42);
});
```

And the `element` is inside the visual viewport, the user agent is
required to [draw a paint
image](#draw-a-paint-image) and display the result for the current frame.

The [draw a paint
image](#draw-a-paint-image) function is invoked by the user agent during the
[object size
negotiation](https://drafts.csswg.org/css-images-3/#object-size-negotiation) algorithm which is responsible for rendering an
[\<image\>](https://drafts.csswg.org/css-images-3/#typedef-image), with
`snappedConcreteObjectSize` defined as follows. Let
`concreteObjectSize` be the [concrete object
size](https://drafts.csswg.org/css-images-3/#concrete-object-size) of the
[box](https://drafts.csswg.org/css-display-4/#box). The `snappedConcreteObjectSize` is usually
the same as the `concreteObjectSize`. However, the user agent
may adjust the size such that it paints to pixel boundaries. If it does,
the user agent should adjust the `snappedConcreteObjectSize`
by the proportional change from its original size such that the
[\<paint()\>](#funcdef-paint) function can adjust the drawing accordingly.

For the purposes of the [object size
negotiation](https://drafts.csswg.org/css-images-3/#object-size-negotiation) algorithm, the paint image has no [natural
dimensions](https://drafts.csswg.org/css-images-3/#natural-dimensions).

 In a future version of the spec, the author could have
the ability to specify the [natural
dimensions](https://drafts.csswg.org/css-images-3/#natural-dimensions) of the paint image. This will probably be exposed as a
callback allowing the author to define static [natural
dimensions](https://drafts.csswg.org/css-images-3/#natural-dimensions) or dynamically updating the [natural
dimensions](https://drafts.csswg.org/css-images-3/#natural-dimensions) based on computed style and size changes.

The [`PaintSize`](#paintsize)
object represents the size of the image that the author should draw.
This is the `snappedConcreteObjectSize` given by the user
agent.

 See [CSS Images 3 § 4.4 Examples of CSS Object
Sizing](https://drafts.csswg.org/css-images-3/#object-sizing-examples)
for examples on how the [concrete object
size](https://drafts.csswg.org/css-images-3/#concrete-object-size) is calculated.

The [draw a paint
image](#draw-a-paint-image) function may be speculatively invoked by the user agent
at any point, with any `snappedConcreteObjectSize`. The
resulting image is not displayed.

 User agents may use any heuristic to speculate a
possible future value for `snappedConcreteObjectSize`, for
example speculating that the size remains unchanged.

 Although the image is not displayed, it may still be
cached, and subsequent invocations of
[\<paint()\>](#funcdef-paint) may use the cached image.

```
[Exposed=PaintWorklet]
interface PaintSize {
 readonly attribute double width;
 readonly attribute double height;
};
```

When the user agent wants to [draw a paint image] of a
[\<paint()\>](#funcdef-paint) function for a `box` into its
appropriate stacking level (as defined by the property the CSS property
its associated with), given `snappedConcreteObjectSize` it
*must* run the following steps:

1. Let `paintFunction` be the
 [\<paint()\>](#funcdef-paint) function on the `box`
 which the user agent wants to draw.

2. Let `name` be the first argument of the
 `paintFunction`.

3. Let `documentPaintDefinitionMap` be the associated
 [document's](https://dom.spec.whatwg.org/#clone-a-node-document) [document paint
 definitions](#document-paint-definitions) map.

4. If `documentPaintDefinitionMap`\[`name`\] does
 not
 [exist](https://infra.spec.whatwg.org/#map-exists), let the image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

5. Let `documentDefinition` be the result of
 [get](https://infra.spec.whatwg.org/#map-get)
 `documentPaintDefinitionMap`\[`name`\].

6. If `documentDefinition` is `"invalid"`, let the image
 output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

7. Let `inputArgumentSyntaxes` be
 `documentDefinition`'s [input argument
 syntaxes](#document-paint-definition-input-argument-syntaxes).

8. Let `inputArguments` be the
 [list](https://infra.spec.whatwg.org/#list) of all the `paintFunction` arguments
 *after* the \"paint name\" argument.

9. If `inputArguments` do not match the registered grammar
 given by `inputArgumentSyntaxes`, let the image output be
 an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

 :::
 (#example-a43f39b7) This step may fail in the
 following cases:
 ```
 // paint.js
 registerPaint('failing-argument-syntax', class {
 static get inputArguments() { return ['<length>']; }
 paint(ctx, size, styleMap, args) { /* paint code here. */ }
 });
 ```

 ```
 <style>
 .example-1 {
 background-image: paint(failing-argument-syntax, red);
 }
 .example-2 {
 background-image: paint(failing-argument-syntax, 1px, 2px);
 }
 </style>
 <div class=example-1></div>
 <div class=example-2></div>
 <script>
 CSS.paintWorklet.addModule('paint.js');
 </script>
 ```

 `example-1` produces an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) as `"red"` does not match the registered grammar.

 `example-2` produces an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) as there are too many function arguments.
 :::

10. Let `workletGlobalScope` be a
 [`PaintWorkletGlobalScope`](#paintworkletglobalscope) from the the paint
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet)'s [global
 scopes](https://html.spec.whatwg.org/multipage/worklets.html#concept-worklet-global-scopes), following the rules defined in [§ 7.1 Global Scope
 Selection](#global-scope-selection).

 The user agent *may* also [create a worklet global
 scope](https://html.spec.whatwg.org/multipage/worklets.html#create-a-worklet-global-scope) at this time, given the paint
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet).

11. Run [invoke a paint
 callback](#invoke-a-paint-callback) given `name`,
 `inputArguments`, `snappedConcreteObjectSize`,
 `workletGlobalScope` optionally [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel).

 If the user agent runs [invoke a paint
 callback](#invoke-a-paint-callback) on a thread [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel), it should select a paint worklet global scope
 which can be used on that thread.

When the user agent wants to [invoke a paint
callback] given `name`, `inputArguments`,
`snappedConcreteObjectSize`, and
`workletGlobalScope`, it *must* run the following steps:

1. Let `paintDefinitionMap` be
 `workletGlobalScope`'s [paint
 definitions](#paint-definitions) map.

2. If `paintDefinitionMap`\[`name`\] does not
 [exist](https://infra.spec.whatwg.org/#map-exists), run the following steps:

 1. [Queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task) to run the following steps:

 1. Let `documentPaintDefinitionMap` be the
 associated
 [document](https://dom.spec.whatwg.org/#clone-a-node-document)'s [document paint
 definitions](#document-paint-definitions) map.

 2. [Set](https://infra.spec.whatwg.org/#map-set)
 `documentPaintDefinitionMap`\[`name`\]
 to `"invalid"`.

 3. The user agent *should* log an error to the debugging
 console stating that a class wasn't registered in all
 [`PaintWorkletGlobalScope`](#paintworkletglobalscope)s.

 2. Let the image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

 This handles the case where there could be a paint
 worklet global scope which didn't receive the
 [`registerPaint(name, paintCtor)`](#dom-paintworkletglobalscope-registerpaint) for `name` (however another global scope
 did). A paint callback which is invoked on the other global scope
 could succeed, but wont succeed on a subsequent frame when [draw a
 paint image](#draw-a-paint-image) is called.

3. Let `definition` be the result of
 [get](https://tc39.github.io/ecma262/#sec-get-o-p)
 `paintDefinitionMap`\[`name`\].

4. Let `paintClassInstanceMap` be
 `workletGlobalScope`'s [paint class
 instances](#paint-class-instances) map.

5. Let `paintInstance` be the result of
 [get](https://tc39.github.io/ecma262/#sec-get-o-p) `paintClassInstanceMap`\[\|name\]\|. If
 `paintInstance` is null, run the following steps:

 1. If the [constructor valid
 flag](#paint-definition-constructor-valid-flag) on `definition` is false, let the
 image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

 2. Let `paintCtor` be the [class
 constructor](#paint-definition-class-constructor) on `definition`.

 3. Let `paintInstance` be the result of
 [Construct](https://tc39.github.io/ecma262/#sec-construct)(`paintCtor`).

 If
 [construct](https://tc39.github.io/ecma262/#sec-construct) throws an exception, set the
 `definition`'s [constructor valid
 flag](#paint-definition-constructor-valid-flag) to false, let the image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image) and abort all these steps.

 4. [Set](https://infra.spec.whatwg.org/#map-set)
 `paintClassInstanceMap`\[`name`\] to
 `paintInstance`.

6. Let `inputProperties` be `definition`'s [input
 properties](#paint-definition-input-properties).

7. Let `styleMap` be a new
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) populated with *only* the [computed
 value](https://drafts.csswg.org/css-cascade-5/#computed-value)'s for properties listed in
 `inputProperties`.

8. Let `renderingContext` be the result of [create a
 PaintRenderingContext2D
 object](#create-a-paintrenderingcontext2d-object) given:

 - \"width\" - The width given by
 `snappedConcreteObjectSize`.

 - \"height\" - The height given by
 `snappedConcreteObjectSize`.

 - \"paintRenderingContext2DSettings\" - The
 [PaintRenderingContext2DSettings
 object](#paint-definition-paintrenderingcontext2dsettings-object) given by `definition`.

 The `renderingContext` is not be re-used
 between invocations of paint. Implicitly this means that there is no
 stored data, or state on the `renderingContext` between
 invocations. For example you can't setup a clip on the context, and
 expect the same clip to be applied next time the paint method is
 called.

 Implicitly this also means that
 `renderingContext` is effectively \"neutered\" after a
 paint method is complete. The author code may hold a reference to
 `renderingContext` and invoke methods on it, but this
 will have no effect on the current image, or subsequent images.

9. Let `paintSize` be a new
 [`PaintSize`](#paintsize)
 initialized to the width and height defined by
 `snappedConcreteObjectSize`.

10. At this stage the user agent may re-use an image from a previous
 invocation if `paintSize`, `styleMap`,
 `inputArguments` are equivalent to that previous
 invocation. If so let the image output be that cached image and
 abort all these steps.

 :::
 In the example below, both `div-1` and `div-2` have paint functions
 which have equivalent javascript arguments. A user-agent can cache
 the result of one invocation and use it for both elements.
 ```
 // paint.js
 registerPaint('simple', class {
 paint(ctx, size) {
 ctx.fillStyle = 'green';
 ctx.fillRect(0, 0, size.width, size.height);
 }
 });
 ```

 ```
 <style>
 .div-1 {
 width: 50px;
 height: 50px;
 background-image: paint(simple);
 }
 .div-2 {
 width: 100px;
 height: 100px;

 background-size: 50% 50%;
 background-image: paint(simple);
 }
 </style>
 <div class=div-1></div>
 <div class=div-2></div>
 <script>
 CSS.paintWorklet.addModule('paint.js');
 </script>
 ```
 :::

11. Let `paintFunctionCallback` be `definition`'s
 [paint
 function](#paint-definition-paint-function).

12. [Invoke](https://webidl.spec.whatwg.org/#invoke-a-callback-function) `paintFunctionCallback` with arguments
 «`renderingContext`, `paintSize`,
 `styleMap`, `inputArguments`» and
 \"\`rethrow\`\", and with `paintInstance` as the
 [callback this
 value](https://webidl.spec.whatwg.org/#dfn-callback-this-value).

 If `paintFunctionCallback` does not complete within an
 acceptable time (as determined by the user agent, i.e. it is a
 \"long running script\") the user agent *may* terminate the script,
 let the image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image), and abort all these steps.

 User agents could provide tooling within their
 debugging tools to show authors how expensive their paint classes
 are. User agents could also how an \"unresponsive script\" dialog in
 this case if appropriate.

13. The image output is to be produced from the
 `renderingContext` given to the method.

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw) the let the image output be an [invalid
 image](https://drafts.csswg.org/css-images-4/#invalid-image).

 The contents of the resulting image are not designed to
be accessible. Authors can communicate any useful information through
the standard accessibility APIs.

### 7.1. Global Scope Selection

When the user agent needs to select a
[`PaintWorkletGlobalScope`](#paintworkletglobalscope) from the paint
[`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet)'s [global
scopes](https://html.spec.whatwg.org/multipage/worklets.html#concept-worklet-global-scopes)
[list](https://infra.spec.whatwg.org/#list) it *must*:

- Select from at *least* two
 [`PaintWorkletGlobalScope`](#paintworkletglobalscope)s, unless the user agent is under memory constraints.

- *Not* re-use the same
 [`PaintWorkletGlobalScope`](#paintworkletglobalscope) more than 1000 times in a row.

 The 1000 limit was picked as a high upper bound, this
 limit may improve (downwards) over time.

 These rules exist to ensure that authors do not rely on
being able to store state on the global object or non-regeneratable
state on the class. See [the discussion in the worklets specification
about code
idempotence](https://html.spec.whatwg.org/multipage/worklets.html#worklets-idempotent).

## 8. Examples

### 8.1. Example 1: Colored Circle

The example below makes use of the fact that
[\<paint()\>](#funcdef-paint) functions are able to be animated. E.g. when the
textarea is focused in the example below, the `--circle-color` property
will transition from `deepskyblue` to `purple`.

This ability isn't limited to just transitions, it also applies to CSS
animations, and the Web Animations API.

```
<!DOCTYPE html>
<style>
 #example {
 --circle-color: deepskyblue;

 background-image: paint(circle);
 font-family: sans-serif;
 font-size: 36px;
 transition: --circle-color 1s;
 }

 #example:focus {
 --circle-color: purple;
 }
</style>

<textarea id="example">
 CSS is awesome.
</textarea>

<script>
 CSS.registerProperty({
 name: '--circle-color',
 syntax: '<color>',
 initialValue: 'black',
 inherits: false
 });
 CSS.paintWorklet.addModule('circle.js');
</script>
```

```
// circle.js
registerPaint('circle', class {
 static get inputProperties() { return ['--circle-color']; }
 paint(ctx, geom, properties) {
 // Change the fill color.
 const color = properties.get('--circle-color');
 ctx.fillStyle = color.cssText;

 // Determine the center point and radius.
 const x = geom.width / 2;
 const y = geom.height / 2;
 const radius = Math.min(x, y);

 // Draw the circle \o/
 ctx.beginPath();
 ctx.arc(x, y, radius, 0, 2 * Math.PI, false);
 ctx.fill();
 }
});
```

### 8.2. Example 2: Image Placeholder

It is possible for an author to use paint to draw a placeholder image
while an image is being loaded.

```
<!DOCTYPE html>
<style>
#example {
 --image: url('#someUrlWhichIsLoading');
 background-image: paint(image-with-placeholder);
}
</style>

<div id="example"></div>

<script>
 CSS.registerProperty({
 name: '--image',
 syntax: '<image> | none',
 initialValue: 'none',
 });
 CSS.paintWorklet.addModule('image-placeholder.js');
</script>
```

```
// image-placeholder.js
registerPaint('image-with-placeholder', class {
 static get inputProperties() { return ['--image']; }
 paint(ctx, geom, properties) {
 const img = properties.get('--image');

 switch (img.state) {
 case 'ready':
 // The image is loaded! Draw the image.
 ctx.drawImage(img, 0, 0, geom.width, geom.height);
 break;
 case 'pending':
 // The image is loading, draw some mountains.
 drawMountains(ctx);
 break;
 case 'invalid':
 default:
 // The image is invalid (e.g. it didn't load), draw a sad face.
 drawSadFace(ctx);
 break;
 }
 }
});
```

### 8.3. Example 3: Arcs

```
<!DOCTYPE html>
<style>
#example {
 width: 200px;
 height: 200px;

 background-image:
 paint(arc, purple, 0.4turn, 0.8turn, 40px, 15px),
 paint(arc, blue, -20deg, 170deg, 30px, 20px),
 paint(arc, red, 45deg, 220deg, 50px, 10px);
}
</style>

<div id="example"></div>

<script>
 CSS.paintWorklet.addModule('arc.js');
</script>
```

```
// arc.js
registerPaint('arc', class {
 static get inputArguments() {
 return [
 '<color>',
 '<angle>', // startAngle
 '<angle>', // endAngle
 '<length>', // radius
 '<length>', // lineWidth
 ];
 }

 paint(ctx, geom, _, args) {
 ctx.strokeStyle = args[0].cssText;

 // Determine the center point.
 const x = geom.width / 2;
 const y = geom.height / 2;

 // Convert the start and end angles to radians.
 const startAngle = this.convertAngle(args[1]) - Math.PI / 2;
 const endAngle = this.convertAngle(args[2]) - Math.PI / 2;

 // Convert the radius and lineWidth to px.
 const radius = this.convertLength(args[3]);
 const lineWidth = this.convertLength(args[4]);

 ctx.lineWidth = lineWidth;

 ctx.beginPath();
 ctx.arc(x, y, radius, startAngle, endAngle, false);
 ctx.stroke();
 }

 convertAngle(angle) {
 switch (angle.unit) {
 case 'deg':
 return angle.value * Math.PI / 180;
 case 'rad':
 return angle.value;
 case 'grad':
 return angle.value * Math.PI / 200;
 case 'turn':
 return angle.value * Math.PI / 0.5;
 default:
 throw Error(`Unknown angle unit: ${angle.unit}`);
 }
 }

 convertLength(length) {
 switch (length.type) {
 case 'px':
 return length.value;
 default:
 throw Error(`Unkown length type: ${length.type}`);
 }
 }
});
```

### 8.5. Example 5: Drawing outside an element's area

It is possible to draw outside an element's area by using the
[border-image](https://drafts.csswg.org/css-backgrounds-3/#propdef-border-image) property.

```
<style>
#overdraw {
 --border-width: 10;

 border-style: solid;
 border-width: calc(var(--border-width) * 1px);

 border-image-source: paint(overdraw);
 border-image-slice: 0 fill;
 border-image-outset: calc(var(--border-width) * 1px);

 width: 200px;
 height: 200px;
}
</style>
<div id="overdraw"></div>
<script>
 CSS.paintWorklet.addModule('overdraw.js');
</script>
```

```
// overdraw.js
registerPaint('overdraw', class {
 static get inputProperties() { return ['--border-width']; }
 paint(ctx, geom, properties) {
 const borderWidth = parseInt(properties.get('--border-width'));
 ctx.shadowColor = 'rgba(0,0,0,0.25)';
 ctx.shadowBlur = borderWidth;

 ctx.fillStyle = 'rgba(255, 255, 255, 1)';
 ctx.fillRect(borderWidth,
 borderWidth,
 geom.width - 2 * borderWidth,
 geom.height - 2 * borderWidth);
 }
});
```

## 9. Security Considerations

There are no known security issues introduced by these features.

## 10. Privacy Considerations

- The timing of paint callbacks can be used as a high-bandwidth channel
 for detecting \"visited\" state for links.
 ([details](https://github.com/w3c/css-houdini-drafts/issues/791)) This
 is not a fundamentally new privacy leak, as visited state leaks from
 many interactions, but absent any further mitigations, this is a
 particularly high-bandwidth channel of the information.

 No official mitigations are planned at this time, as this privacy leak
 needs to be addressed more directly to fix all such channels.

## 11. Changes

Changes since the [9 August 2018 CR
publication](https://www.w3.org/TR/2018/CR-css-paint-api-1-20180809/):

- Filtered the list of input properties to a paint worklet to be only
 known or custom properties.

- Added alpha flag to
 [`PaintRenderingContext2D`](#paintrenderingcontext2d) to control whether the rendering surface is forced

- Fix definition for the size of the output bitmap:
