## 1. Introduction

*This section is not normative.*

The layout stage of CSS is responsible for generating and positioning
[fragments](https://drafts.csswg.org/css-break-3/#fragment) from the [box
tree](https://drafts.csswg.org/css-display-4/#box-tree).

This specification describes an API which allows developers to layout a
[box](https://drafts.csswg.org/css-display-3/#box) in response to computed style and [box
tree](https://drafts.csswg.org/css-display-4/#box-tree) changes.

For a high level overview of this API, see the
[EXPLAINER](https://github.com/w3c/css-houdini-drafts/blob/main/css-layout-api/EXPLAINER.md).

## 2. Layout API Containers

A new [alternative](https://www.w3.org/TR/css-values-3/#comb-one) value
is added to the
[\<display-inside\>](https://drafts.csswg.org/css-display-4/#typedef-display-inside) production:
`layout(`[`<ident>`](https://drafts.csswg.org/css-values-4/#typedef-ident)`)`.

[layout()]
: This value causes an element to generate a [layout API
 container](#layout-api-container) box.

A [layout API container] is the box generated by an element with a
[\<display-inside\>](https://drafts.csswg.org/css-display-4/#typedef-display-inside) [computed
value](https://drafts.csswg.org/css-cascade-5/#computed-value)
[layout()](#valdef-display-layout).

A [layout API
container](#layout-api-container) establishes a new [layout API formatting
context] for its contents. This is the same as establishing a block
formatting context, except that the layout provided by the author is
used instead of the block layout. For example, floats do not intrude
into the layout API container, and the layout API container's margins do
not collapse with the margins of its contents.

[Layout API
containers](#layout-api-container) form a containing block for their contents [exactly
like block containers
do](https://www.w3.org/TR/CSS2/visudet.html#containing-block-details).
[\[CSS21\]](#biblio-css21 "Cascading Style Sheets Level 2 Revision 1 (CSS 2.1) Specification")

 In a future level of the specification there may be a
way to override the containing block behaviour.

The
[overflow](https://drafts.csswg.org/css-overflow-3/#propdef-overflow) property applies to [layout API
containers](#layout-api-container). This is discussed in [§ 5.3
Overflow](#interaction-overflow).

As the layout is entirely up to the author, properties which are used in
other layout modes (e.g. flex, block) may not apply. For example an
author may not respect the
[margin](https://drafts.csswg.org/css-box-4/#propdef-margin) property on children.

The HTML below shows an example of
setting the
[display](https://drafts.csswg.org/css-shapes-2/#valdef-shape-inside-display) to a
[layout()](#valdef-display-layout) function, if the CSS Layout API is supported.

```
<!DOCTYPE html>
<style>
@supports (display: layout(centering)) {
 .centering-layout { display: layout(centering); }
}
</style>
<div class="centering-layout"></div>
```

### 2.1. Layout API Container Painting

[Layout API
Container](#layout-api-container) children paint exactly the same as inline blocks
[\[CSS21\]](#biblio-css21 "Cascading Style Sheets Level 2 Revision 1 (CSS 2.1) Specification"),
except that the order in which they are returned from the layout method
(via
[`childFragments`](#dom-fragmentresultoptions-childfragments)) is used in place of raw document order, and
[z-index](https://drafts.csswg.org/css2/#propdef-z-index) values other than
[auto](https://drafts.csswg.org/css2/#valdef-z-index-auto) create a stacking context even if
[position](https://drafts.csswg.org/css-position-3/#propdef-position) is
[static](https://drafts.csswg.org/css-position-3/#valdef-position-static).

### 2.2. Box Tree Transformations

The inflow children of a [layout API
container](#layout-api-container) can act in different ways depending on the value of
[layout
options\'](#document-layout-definition-layout-options)
[`childDisplay`](#dom-layoutoptions-childdisplay) (set by `layoutOptions` on the class).

If the value of [layout
options\'](#document-layout-definition-layout-options)
[`childDisplay`](#dom-layoutoptions-childdisplay) is `"block"` the
[display](https://drafts.csswg.org/css-display-4/#propdef-display) value of that child is
[blockified](https://drafts.csswg.org/css-display-4/#blockify). This is similar to children of [flex
containers](https://drafts.csswg.org/css-flexbox-2/#flex-container) or [grid
containers](https://drafts.csswg.org/css-grid-2/#grid-container). See
[\[css3-display\]](#biblio-css3-display "CSS Display Module Level 3").

If the value of [layout
options\'](#document-layout-definition-layout-options)
[`childDisplay`](#dom-layoutoptions-childdisplay) is `"normal"`, no
[blockification](https://drafts.csswg.org/css-display-4/#blockify) occurs. Instead children with a
[\<display-outside\>](https://drafts.csswg.org/css-display-4/#typedef-display-outside) [computed
value](https://drafts.csswg.org/css-cascade-5/#computed-value) of
[inline](https://drafts.csswg.org/css-display-3/#valdef-display-inline) (a [root inline
box](https://drafts.csswg.org/css-inline-3/#root-inline-box)) will produce a single
[`LayoutFragment`](#layoutfragment) representing each line when
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) is called.

 This allows authors to adjust the available inline size
of each line, and position each line separately.

Children of a [`LayoutChild`](#layoutchild) which represents [root inline
box](https://drafts.csswg.org/css-inline-3/#root-inline-box) also have some additional transformations.

- A
 [block-level](https://drafts.csswg.org/css-display-4/#block-level) box inside a
 [inline-level](https://drafts.csswg.org/css-display-4/#inline-level) box is
 [inlinified](https://drafts.csswg.org/css-display-4/#inlinify) I.e. its
 [\<display-outside\>](https://drafts.csswg.org/css-display-4/#typedef-display-outside) is set to
 [inline](https://drafts.csswg.org/css-display-3/#valdef-display-inline).

- A
 [float](https://drafts.csswg.org/css-page-floats-3/#float) inside a
 [inline-level](https://drafts.csswg.org/css-display-4/#inline-level) box is not taken out of flow. Instead it must be
 treated as inflow, and be
 [inlinified](https://drafts.csswg.org/css-display-4/#inlinify).

In both of the above cases the children become [atomic
inlines](https://drafts.csswg.org/css-display-4/#atomic-inline).

 User agents would not perform any \"inline splitting\"
or fragmenting when they encounter a
[block-level](https://drafts.csswg.org/css-display-4/#block-level) box.

Note: In the example below \"inline-span\" would be represented as a
single [`LayoutChild`](#layoutchild) with both \"block\" and \"float\" being [atomic
inlines](https://drafts.csswg.org/css-display-4/#atomic-inline).

```
<span id="inline-span">
 Text
 <div id="block"></div>
 <div id="float"></div>
 Text
</span>
```

## 3. Layout Worklet

The
[`layoutWorklet`](#dom-css-layoutworklet) attribute allows access to the
[`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet) responsible for all the classes which are related to
layout.

The
[`layoutWorklet`](#dom-css-layoutworklet)'s [worklet global scope
type](https://html.spec.whatwg.org/multipage/worklets.html#worklet-global-scope-type) is
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope).

```
partial namespace CSS {
 [SameObject] readonly attribute Worklet layoutWorklet;
};
```

The
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) is the global execution context of the
[`layoutWorklet`](#dom-css-layoutworklet).

```
[Global=(Worklet,LayoutWorklet),Exposed=LayoutWorklet]
interface LayoutWorkletGlobalScope : WorkletGlobalScope {
 undefined registerLayout(DOMString name, VoidFunction layoutCtor);
};
```

Web developers can feature detect by:

```
if ('layoutWorklet' in CSS) {
 console.log('CSS Layout API available!');
}
```

### 3.1. Concepts

This section describes internal data-structures created when
[`registerLayout(name, layoutCtor)`](#dom-layoutworkletglobalscope-registerlayout) is called.

A [layout definition] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) about the author defined layout (which can be
referenced by the
[layout()](#valdef-display-layout) function). It consists of:

- [class constructor]
 which is the class
 [constructor](https://tc39.github.io/ecma262/#sec-constructor).

- [layout function] which is the
 layout
 [function](https://tc39.github.io/ecma262/#sec-terms-and-definitions-function) callback.

- [intrinsic sizes function] which is the intrinsic sizes
 [function](https://tc39.github.io/ecma262/#sec-terms-and-definitions-function) callback.

- [constructor valid flag].

- [input properties]
 which is a [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`.

- [child input properties] which is a
 [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`.

- [layout options] a
 [`LayoutOptions`](#dictdef-layoutoptions).

A [document layout definition] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the
[document](https://dom.spec.whatwg.org/#concept-document) about the author defined layout (which can be
referenced by the
[layout()](#valdef-display-layout) function). It consists of:

- [input properties] which is a
 [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`

- [child input
 properties] which is a
 [list](https://infra.spec.whatwg.org/#list) of `DOMStrings`.

- [layout options] a
 [`LayoutOptions`](#dictdef-layoutoptions).

### 3.2. Registering A Layout

The section describes how a web developer uses
[`registerLayout(name, layoutCtor)`](#dom-layoutworkletglobalscope-registerlayout) to register a layout.

```
dictionary LayoutOptions {
 ChildDisplayType childDisplay = "block";
 LayoutSizingMode sizing = "block-like";
};

enum ChildDisplayType {
 "block", // default - "blockifies" the child boxes.
 "normal",
};

enum LayoutSizingMode {
 "block-like", // default - Sizing behaves like block containers.
 "manual", // Sizing is specified by the web developer.
};
```

The
[document](https://dom.spec.whatwg.org/#concept-document) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [document layout
definitions]. Initially this map is empty; it is
populated when
[`registerLayout(name, layoutCtor)`](#dom-layoutworkletglobalscope-registerlayout) is called.

The
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [layout definitions]. Initially this map is empty;
it is populated when
[`registerLayout(name, layoutCtor)`](#dom-layoutworkletglobalscope-registerlayout) is called.

Each [box](https://drafts.csswg.org/css-display-3/#box) representing a [layout API
container](#layout-api-container) has a
[map](https://infra.spec.whatwg.org/#ordered-map) of [layout class instances]. Initially this map is empty; it is populated when the user
agent calls either [determine the intrinsic
sizes](#determine-the-intrinsic-sizes) or [generate a
fragment](#generate-a-fragment) for a
[box](https://drafts.csswg.org/css-display-3/#box).

Each [box](https://drafts.csswg.org/css-display-3/#box) representing a [layout API
container](#layout-api-container) has a [styleMap] internal slot. This is a
[`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) which contains the properties listed in
`inputProperties`.

The user agent *clear* the [styleMap](#stylemap) internal slot for a
[box](https://drafts.csswg.org/css-display-3/#box) when:

- The [computed
 values](https://drafts.csswg.org/css-cascade-5/#computed-value) of [input
 properties](#document-layout-definition-input-properties) for the
 [box](https://drafts.csswg.org/css-display-3/#box) changes.

- When the
 [box](https://drafts.csswg.org/css-display-3/#box) is removed from the [box
 tree](https://drafts.csswg.org/css-display-4/#box-tree).

- Every 1000 layout passes.

 The above rule exists to ensure that web developers
 do not rely on being able to store non-regeneratable state on the
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) object. The 1000 limit was picked as a high upper
 bound, this limit may improve (downwards) over time.

Note: The shape of the class should be:

```
registerLayout('example', class {
 static inputProperties = ['--foo'];
 static childInputProperties = ['--bar'];
 static layoutOptions = {
 childDisplay: 'normal',
 sizing: 'block-like'
 };

 async intrinsicSizes(children, edges, styleMap) {
 // Intrinsic sizes code goes here.
 }

 async layout(children, edges, constraints, styleMap, breakToken) {
 // Layout code goes here.
 }
});
```

The algorithm below is run when the
[`registerLayout(name, layoutCtor)`](#dom-layoutworkletglobalscope-registerlayout) is called. It notifies the user agent layout engine
about the new user defined layout.

When the
[`registerLayout(``name``, ``layoutCtor``)`] method is called, the user agent *must* run
the following steps:

1. If the `name` is an empty string,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps.

2. Let `layoutDefinitionMap` be
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope)'s [layout
 definitions](#layout-definitions) map.

3. If `layoutDefinitionMap`\[`name`\]
 [exists](https://infra.spec.whatwg.org/#map-exists)
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 \"[`InvalidModificationError`](https://webidl.spec.whatwg.org/#invalidmodificationerror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException) and abort all these steps.

4. Let `inputProperties` be an empty `sequence<DOMString>`.

5. Let `inputPropertiesIterable` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`layoutCtor`, \"inputProperties\").

6. If `inputPropertiesIterable` is not undefined, then set
 `inputProperties` to the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `inputPropertiesIterable` to a
 `sequence<DOMString>`. If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), rethrow the exception and abort all these steps.

7. Filter `inputProperties` so that it only contains
 [supported CSS
 properties](https://drafts.csswg.org/cssom-1/#supported-css-property) and [custom
 properties](https://drafts.csswg.org/css-variables-2/#custom-property).

 The list of CSS properties provided by the input
 properties getter can either be custom or native CSS properties.

 The list of CSS properties may contain shorthands.

 In order for a layout class to be forwards
 compatible, the list of CSS properties can also contains currently
 invalid properties for the user agent. For example
 `margin-bikeshed-property`.

8. Let `childInputProperties` be an empty
 `sequence<DOMString>`.

9. Let `childInputPropertiesIterable` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`layoutCtor`, \"childInputProperties\").

10. If `childInputPropertiesIterable` is not undefined, then
 set `childInputProperties` to the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `childInputPropertiesIterable` to a
 `sequence<DOMString>`. If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), rethrow the exception and abort all these steps.

11. Filter `childInputProperties` so that it only contains
 [supported CSS
 properties](https://drafts.csswg.org/cssom-1/#supported-css-property) and [custom
 properties](https://drafts.csswg.org/css-variables-2/#custom-property).

12. Let `layoutOptionsValue` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`layoutCtor`, \"layoutOptions\").

13. Let `layoutOptions` be the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `layoutOptionsValue` to a
 [`LayoutOptions`](#dictdef-layoutoptions). If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), rethrow the exception and abort all these steps.

14. Let `prototype` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`layoutCtor`, \"prototype\").

15. If the result of
 [Type](https://tc39.github.io/ecma262/#sec-ecmascript-data-types-and-values)(`prototype`) is not Object,
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror) and abort all these steps.

16. Let `intrinsicSizesValue` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`prototype`, \"intrinsicSizes\").

17. Let `intrinsicSizes` be the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `intrinsicSizesValue` to the
 [`Function`](https://webidl.spec.whatwg.org/#Function) [callback
 function](https://webidl.spec.whatwg.org/#dfn-callback-function) type. Rethrow any exceptions from the conversion.

18. Let `layoutValue` be the result of
 [Get](https://tc39.github.io/ecma262/#sec-get-o-p)(`prototype`, `"layout"`).

19. Let `layout` be the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `layoutValue` to the
 [`Function`](https://webidl.spec.whatwg.org/#Function) [callback
 function](https://webidl.spec.whatwg.org/#dfn-callback-function) type. Rethrow any exceptions from the conversion.

20. Let `definition` be a new [layout
 definition](#layout-definition) with:

 - [class
 constructor](#layout-definition-class-constructor) being `layoutCtor`.

 - [layout
 function](#layout-definition-layout-function) being `layout`.

 - [intrinsic sizes
 function](#layout-definition-intrinsic-sizes-function) being `intrinsicSizes`.

 - [constructor valid
 flag](#layout-definition-constructor-valid-flag) being **true**.

 - [child input
 properties](#layout-definition-child-input-properties) being `childInputProperties`.

 - [input
 properties](#layout-definition-input-properties) being `inputProperties`.

 - [layout
 options](#layout-definition-layout-options) being `layoutOptions`.

21. [Set](https://infra.spec.whatwg.org/#map-set)
 `layoutDefinitionMap`\[`name`\] to
 `definition`.

22. [Queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task) to run the following steps:

 1. Let `documentLayoutDefinitionMap` be the associated
 [document's](https://dom.spec.whatwg.org/#concept-document) [document layout
 definitions](#document-layout-definitions)
 [map](https://infra.spec.whatwg.org/#ordered-map).

 2. Let `documentDefinition` be a new [document layout
 definition](#document-layout-definition) with:

 - [child input
 properties](#document-layout-definition-child-input-properties) being `childInputProperties`.

 - [input
 properties](#document-layout-definition-input-properties) being `inputProperties`.

 - [layout
 options](#document-layout-definition-layout-options) being `layoutOptions`.

 3. If `documentLayoutDefinitionMap`\[`name`\]
 [exists](https://infra.spec.whatwg.org/#map-exists), run the following steps:

 1. Let `existingDocumentDefinition` be the result of
 [get](https://infra.spec.whatwg.org/#map-get)
 `documentLayoutDefinitionMap`\[`name`\].

 2. If `existingDocumentDefinition` is `"invalid"`,
 abort all these steps.

 3. If `existingDocumentDefinition` and
 `documentDefinition` are not equivalent, (that is
 [input
 properties](#document-layout-definition-input-properties), [child input
 properties](#document-layout-definition-child-input-properties), and [layout
 options](#document-layout-definition-layout-options) are different), then:

 [Set](https://infra.spec.whatwg.org/#map-set)
 `documentLayoutDefinitionMap`\[`name`\]
 to `"invalid"`.

 Log an error to the debugging console stating that the same
 class was registered with different `inputProperties`,
 `childInputProperties`, or `layoutOptions`.

 4. Otherwise,
 [set](https://infra.spec.whatwg.org/#map-set)
 `documentLayoutDefinitionMap`\[`name`\] to
 `documentDefinition`.

### 3.3. Terminology

We define the following terms to be clear about which layout algorithm
(formatting context) we are talking about.

The [current layout] is the layout algorithm for the
[box](https://drafts.csswg.org/css-display-3/#box) we are currently performing layout for.

The [parent layout] is the layout algorithm for the
[box's](https://drafts.csswg.org/css-display-3/#box) direct parent, (the layout algorithm which is
requesting the [current layout](#current-layout) to be performed).

A [child layout] is the layout algorithm for a
[`LayoutChild`](#layoutchild) of the [current
layout](#current-layout).

## 4. Layout API

This section describes the objects of the Layout API provided to web
developers.

### 4.1. Layout Children

A [`LayoutChild`](#layoutchild) represents a inflow CSS generated
[box](https://drafts.csswg.org/css-display-3/#box) before layout has occurred. (The box or boxes will all
have a computed value of
[display](https://drafts.csswg.org/css-display-4/#propdef-display) that is not
[none](https://drafts.csswg.org/css-display-3/#valdef-display-none)).

The [`LayoutChild`](#layoutchild) does not contain any layout information itself (like
inline or block size) but can be used to generate
[`LayoutFragment`](#layoutfragment)s which do contain layout information.

An author cannot construct a
[`LayoutChild`](#layoutchild) with this API, this happens at a separate stage of the
user agent rendering engine (post style resolution).

An array of [`LayoutChild`](#layoutchild)ren is passed into the layout/intrinsicSizes methods
which represents the children of the current box which is being laid
out.

```
[Exposed=LayoutWorklet]
interface LayoutChild {
 readonly attribute StylePropertyMapReadOnly styleMap;

 Promise<IntrinsicSizes> intrinsicSizes();
 Promise<LayoutFragment> layoutNextFragment(LayoutConstraintsOptions constraints, ChildBreakToken breakToken);
};
```

The [`LayoutChild`](#layoutchild) has internal slot(s):

- [`[[box]]`] a CSS
 [box](https://drafts.csswg.org/css-display-3/#box).

- [`[[styleMap]]`] a
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly), this is the computed style for the child, it is
 populated with only the properties listed in `childInputProperties`.

<!-- -->

- [`[[unique id]]`] the
 [unique
 id](#layout-api-context-unique-id) of the current [layout api
 context](#layout-api-context). This slot is used so that a
 [`LayoutChild`](#layoutchild) used outside the current layout pass is invalid.

The
[`[[styleMap]]`](#dom-layoutchild-stylemap-slot) may be pre-populated when the [computed
value](https://drafts.csswg.org/css-cascade-5/#computed-value) for properties listed in the in [child input
properties](#layout-definition-child-input-properties) for the
[`[[box]]`](#dom-layoutchild-box-slot).

The example below shows the basic
usage of a [`LayoutChild`](#layoutchild).

```
registerLayout('example-layout-child', class {
 static childInputProperties = ['--foo'];

 async layout(children, edges, constraints, styleMap) {

 // An array of LayoutChildren is passed into both the layout function,
 // and intrinsic sizes function below.
 const child = children[0];

 // You can query the any properties listed in "childInputProperties".
 const fooValue = child.styleMap.get('--foo');

 // And perform layout!
 const fragment = await child.layoutNextFragment();

 }

 async intrinsicSizes(children, edges, styleMap) {

 // Or request the intrinsic size!
 const childIntrinsicSize = await children[0].intrinsicSizes();

 }
});
```

A [`LayoutChild`](#layoutchild) could be generated by:

- An
 [element](https://dom.spec.whatwg.org/#concept-element).

- A [root inline
 box](https://drafts.csswg.org/css-inline-3/#root-inline-box).

- A
 [::before](https://drafts.csswg.org/css-pseudo-4/#selectordef-before) or
 [::after](https://drafts.csswg.org/css-pseudo-4/#selectordef-after) pseudo-element.

 Other pseudo-elements such as
 [::first-letter](https://drafts.csswg.org/css-pseudo-4/#selectordef-first-letter) or
 [::first-line](https://drafts.csswg.org/css-pseudo-4/#selectordef-first-line) do not generate a
 [`LayoutChild`](#layoutchild) for layout purposes. They are additional styling
 information for a text node.

- An [anonymous
 box](https://drafts.csswg.org/css-display-4/#anonymous). For example an anonymous box may be inserted as a
 result of:

 - A text node which has undergone
 [blockification](https://drafts.csswg.org/css-display-4/#blockify). (Or more generally a [root inline
 box](https://drafts.csswg.org/css-inline-3/#root-inline-box) which has undergone
 [blockification](https://drafts.csswg.org/css-display-4/#blockify)).

 - An element with [display:
 table-cell](https://drafts.csswg.org/css-display-4/#propdef-display) which doesn't have a parent with
 [display:
 table](https://drafts.csswg.org/css-display-4/#propdef-display).

Note: As an example the following would be placed into three
[`LayoutChild`](#layoutchild)ren:

```
<style>
 #box::before { content: 'hello!'; }
</style>

<div id="box">A block level box with text.</div>
<img src="..." />
```

Note: As an example the following would be placed into a single
[`LayoutChild`](#layoutchild) as they share a [root inline
box](https://drafts.csswg.org/css-inline-3/#root-inline-box):

```
This is a next node, <span>with some additional styling,
that may</span> break over<br>multiple lines.
```

Multiple non-[atomic
inlines](https://drafts.csswg.org/css-display-4/#atomic-inline) are placed within the same
[`LayoutChild`](#layoutchild) to allow rendering engines to perform text shaping
across element boundaries.

Note: As an example the following should produce one
[`LayoutFragment`](#layoutfragment) but is from three non-[atomic
inlines](https://drafts.csswg.org/css-display-4/#atomic-inline):

```
ع<span style="color: blue">ع</span>ع
```

 When accessing the
[`styleMap`](#dom-layoutchild-stylemap) the user agent can create a new
[`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) if none exists yet.

The [`styleMap`], on getting from a
[`LayoutChild`](#layoutchild) `this`, the user agent must perform the
following steps:

1. If `this`'
 [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) is null, then:

 1. Let `box` be `this`'
 [`[[box]]`](#dom-layoutchild-box-slot).

 2. Let `definition` be the result of [get a layout
 definition](#get-a-layout-definition).

 3. Let `childInputProperties` be
 `definition`'s [child input
 properties](#layout-definition-child-input-properties).

 4. Let `styleMap` be a new
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) populated with *only* the [computed
 values](https://drafts.csswg.org/css-cascade-5/#computed-value) for properties listed in
 `childInputProperties` for `box`.

 5. Set `this`'
 [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) internal slot to `styleMap`.

 If the user agent always pre-populates
 [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) then this branch of the algorithm won't be reached.

2. Return `this`'
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) contained in the
 [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) internal slot.

[`intrinsicSizes()`](#dom-layoutchild-intrinsicsizes) method allows the web developer to query the intrinsic
sizes of the [`LayoutChild`](#layoutchild).

When the [`intrinsicSizes()`] method is called on a
[`LayoutChild`](#layoutchild) `this`, the user agent must perform the
following steps:

1. Let `p` be a new promise.

2. Let `context` be the [current
 layout's](#current-layout)
 [layout API
 context](#layout-api-context).

3. If `this`'
 [`[[unique id]]`](#dom-layoutchild-unique-id-slot) is not equal to `context`'s [unique
 id](#layout-api-context-unique-id), reject `p` with a
 \"[`InvalidStateError`](https://webidl.spec.whatwg.org/#invalidstateerror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException), and abort all these steps.

 This is to ensure that only
 [`LayoutChild`](#layoutchild)ren passed in as arguments to either the layout or
 intrinsicSizes method are used.

4. Let `task` be a new [layout API work
 task](#layout-api-work-task) with:

 - [layout
 child](#layout-api-work-task-layout-child) being `this`.

 - [task
 type](#layout-api-work-task-task-type) being `"intrinsic-sizes"`.

 - [promise](#layout-api-work-task-promise) being `p`.

5. [Append](https://infra.spec.whatwg.org/#list-append) `task` to `context`'s [work
 queue](#layout-api-context-work-queue).

6. Return `p`.

[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) method allows the web developer to produce a
[`LayoutFragment`](#layoutfragment) for a given
[`LayoutChild`](#layoutchild) (the result of performing layout).

When the
[`layoutNextFragment(``constraints``, ``breakToken``)`] method is called on a
[`LayoutChild`](#layoutchild) `this`, the user agent must perform the
following steps:

1. Let `p` be a new promise.

2. Let `context` be the [current
 layout's](#current-layout)
 [layout API
 context](#layout-api-context).

3. If `this`'
 [`[[unique id]]`](#dom-layoutchild-unique-id-slot) is not equal to `context`'s [unique
 id](#layout-api-context-unique-id), reject `p` with a
 \"[`InvalidStateError`](https://webidl.spec.whatwg.org/#invalidstateerror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException), and abort all these steps.

 This is to ensure that only
 [`LayoutChild`](#layoutchild)ren passed in as arguments to either the layout or
 intrinsicSizes method are used.

4. If `breakToken`'s
 [`[[unique id]]`](#dom-childbreaktoken-unique-id-slot) is not equal to `context`'s [unique
 id](#layout-api-context-unique-id), reject `p` with a
 \"[`InvalidStateError`](https://webidl.spec.whatwg.org/#invalidstateerror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException), and abort all these steps.

5. If `context`'s
 [mode](#layout-api-context-mode) is `"intrinsic-sizes"`, reject `p` with
 a
 \"[`NotSupportedError`](https://webidl.spec.whatwg.org/#notsupportederror)\"
 [`DOMException`](https://webidl.spec.whatwg.org/#idl-DOMException).

 This is to ensure that inside a `intrinsicSizes`
 callback,
 [`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) cannot be called.

6. Let `task` be a new [layout API work
 task](#layout-api-work-task) with:

 - [layout
 constraints](#layout-api-work-task-layout-constraints) being `constraints`.

 - [layout
 child](#layout-api-work-task-layout-child) being `this`.

 - [child break

 - [task
 type](#layout-api-work-task-task-type) being `"layout"`.

 - [promise](#layout-api-work-task-promise) being `p`.

7. [Append](https://infra.spec.whatwg.org/#list-append) `task` to `context`'s [work

8. Return `p`.

#### 4.1.1. LayoutChildren and the Box Tree

Each [box](https://drafts.csswg.org/css-display-3/#box) has a
[`[[layoutChildMap]]`] internal slot,
which is a
[map](https://infra.spec.whatwg.org/#ordered-map) of
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope)s to
[`LayoutChild`](#layoutchild)ren.

 [Get a layout
child](#get-a-layout-child)
returns a [`LayoutChild`](#layoutchild) object for the correct
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) and creates one if it doesn't exist yet.

When the user agent wants to [get a layout child] given
`workletGlobalScope`, `name`, `box`,
and `uniqueId`, it *must* run the following steps:

1. Assert that:

 - `box` is currently attached to the [box
 tree](https://drafts.csswg.org/css-display-4/#box-tree).

 - `box`'s [containing
 block](https://drafts.csswg.org/css-display-4/#containing-block) is a [layout API
 container](#layout-api-container).

 - The [containing
 block's](https://drafts.csswg.org/css-display-4/#containing-block)
 [layout()](#valdef-display-layout) function's first argument is
 `name`.

2. Let `layoutChildMap` be `box`'s
 [`[[layoutChildMap]]`](#dom-box-layoutchildmap-slot).

3. If `layoutChildMap`\[`workletGlobalScope`\]
 does not
 [exist](https://infra.spec.whatwg.org/#map-exists), run the following steps:

 1. Let `definition` be the result of [get a layout
 definition](#get-a-layout-definition) given `name`, and
 `workletGlobalScope`.

 Assert that [get a layout
 definition](#get-a-layout-definition) succeeded, and `definition` is not
 `"invalid"`.

 2. Let `childInputProperties` be
 `definition`'s [child input
 properties](#layout-definition-child-input-properties).

 3. Let `layoutChild` be a new
 [`LayoutChild`](#layoutchild) with internal slot(s):

 - [`[[box]]`](#dom-layoutchild-box-slot) set to `box`.

 - [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) set to a new
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) populated with *only* the [computed
 values](https://drafts.csswg.org/css-cascade-5/#computed-value) for properties listed in
 `childInputProperties`.

 4. [Set](https://infra.spec.whatwg.org/#map-set)
 `layoutChildMap`\[`workletGlobalScope`\]
 to `layoutChild`.

4. Let `layoutChild` be the result of
 [get](https://infra.spec.whatwg.org/#map-get)
 `layoutChildMap`\[`workletGlobalScope`\].

5. Set `layoutChild`'s
 [`[[unique id]]`](#dom-layoutchild-unique-id-slot) internal slot to `uniqueId`.

6. Return `layoutChild`.

When a [box](https://drafts.csswg.org/css-display-3/#box) is inserted into the [box
tree](https://drafts.csswg.org/css-display-4/#box-tree) the user agent *may* pre-populate the
[`[[layoutChildMap]]`](#dom-box-layoutchildmap-slot) for all
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope)s.

When a [box](https://drafts.csswg.org/css-display-3/#box) is removed from the [box
tree](https://drafts.csswg.org/css-display-4/#box-tree) the user agent *must* clear the
[`[[layoutChildMap]]`](#dom-box-layoutchildmap-slot).

The user agent *must* clear the
[`[[layoutChildMap]]`](#dom-box-layoutchildmap-slot) internal slot every 1000 layout passes.

 The above rule exists to ensure that web developers do
not rely on being able to store non-regeneratable state on the
[`LayoutChild`](#layoutchild) object. The 1000 limit was picked as a high upper
bound, this limit may improve (downwards) over time.

When the user agent wants to [update a layout child
style] given `box`, it *must* run the following steps:

1. Assert that:

 - `box` is currently attached to the [box
 tree](https://drafts.csswg.org/css-display-4/#box-tree).

2. If `box`'s [containing
 block](https://drafts.csswg.org/css-display-4/#containing-block) is not a [layout API
 container](#layout-api-container), abort all these steps.

3. Let `layoutChildMap` be `box`'s
 [`[[layoutChildMap]]`](#dom-box-layoutchildmap-slot).

4. [For
 each](https://infra.spec.whatwg.org/#map-iterate) `layoutChild` in
 `layoutChildMap`:

 1. `layoutChild`'s
 [`[[styleMap]]`](#dom-layoutchild-stylemap-slot) to null.

When the [computed
values](https://drafts.csswg.org/css-cascade-5/#computed-value) of [child input
properties](#document-layout-definition-child-input-properties) for a
[box](https://drafts.csswg.org/css-display-3/#box) changes the user agent must run the [update a layout
child
style](#update-a-layout-child-style) algorithm.

### 4.2. Layout Fragments

A [`LayoutFragment`](#layoutfragment) represents a CSS
[fragment](https://drafts.csswg.org/css-break-3/#fragment) of a
[`LayoutChild`](#layoutchild) after layout has occurred on that child. This is
produced by the
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) method.

```
[Exposed=LayoutWorklet]
interface LayoutFragment {
 readonly attribute double inlineSize;
 readonly attribute double blockSize;

 attribute double inlineOffset;
 attribute double blockOffset;

 readonly attribute any data;

 readonly attribute ChildBreakToken? breakToken;
};
```

The [`LayoutFragment`](#layoutfragment) has internal slot(s):

- [`[[unique id]]`] the
 [unique
 id](#layout-api-context-unique-id) of the [layout api
 context](#layout-api-context) which produced this child fragment. This slot is used
 so that a
 [`LayoutFragment`](#layoutfragment) from a previous layout pass is invalid.

------------------------------------------------------------------------

The [`LayoutFragment`](#layoutfragment) has
[`inlineSize`](#dom-layoutfragment-inlinesize) and
[`blockSize`](#dom-layoutfragment-blocksize) attributes, which are set by the respective child's
layout algorithm. They represent the **border box** size of the CSS
[fragment](https://drafts.csswg.org/css-break-3/#fragment), and are relative to the [current
layout's](#current-layout)
writing mode.

The
[`inlineSize`](#dom-layoutfragment-inlinesize) and
[`blockSize`](#dom-layoutfragment-blocksize) attributes cannot be changed. If the [current
layout](#current-layout)
requires a different
[`inlineSize`](#dom-layoutfragment-inlinesize) or
[`blockSize`](#dom-layoutfragment-blocksize) the author must perform
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) again with different arguments in order to get
different results.

The author inside the current layout can position a resulting
[`LayoutFragment`](#layoutfragment) by setting its
[`inlineOffset`](#dom-layoutfragment-inlineoffset) and
[`blockOffset`](#dom-layoutfragment-blockoffset) attributes. If not set by the author they default to
zero. The
[`inlineOffset`](#dom-layoutfragment-inlineoffset) and
[`blockOffset`](#dom-layoutfragment-blockoffset) attributes represent the position of the
[`LayoutFragment`](#layoutfragment) relative to its parent's **border box**, before
transform or positioning (e.g. if a fragment is [relatively
positioned](https://drafts.csswg.org/css-position-3/#relative-position)) has been applied.

![A simple visualization showing positioning a
[`LayoutFragment`](#layoutfragment) using
[`inlineOffset`](#dom-layoutfragment-inlineoffset) and
[`blockOffset`](#dom-layoutfragment-blockoffset) in different writing
modes.](images/layout-fragment-offsets.png){a
width="800"}

The example below shows the basic
usage of a
[`LayoutFragment`](#layoutfragment).

```
registerLayout('example-layout-fragment', class {
 async layout(children, edges, constraints, styleMap) {

 // You must perform layout to generate a fragment.
 const fragment = await child.layoutNextFragment();

 // You can query the size of the fragment produced:
 console.log(fragment.inlineSize);
 console.log(fragment.blockSize);

 // You can set the position of the fragment, e.g. this will set it to the
 // top-left corner:
 fragment.inlineOffset = edges.inlineStart;
 fragment.blockOffset = edges.blockStart;

 // Data may be passed from the child layout:
 console.log(fragment.data);

 // If the child fragmented, you can use the breakToken to produce the next
 // fragment in the chain.
 const nextFragment = await child.layoutNextFragment(, fragment.breakToken);
 }
});
```

A [layout API
container](#layout-api-container) can communicate with other [layout API
containers](#layout-api-container) by using the
[`data`](#dom-layoutfragment-data) attribute. This is set by the
[`data`](#dom-fragmentresultoptions-data) member in the
[`FragmentResultOptions`](#dictdef-fragmentresultoptions) dictionary.

The [`LayoutFragment`](#layoutfragment)'s
[`breakToken`](#dom-layoutfragment-breaktoken) specifies where the
[`LayoutChild`](#layoutchild) last fragmented. If the
[`breakToken`](#dom-layoutfragment-breaktoken) is null the
[`LayoutChild`](#layoutchild) wont produce any more
[`LayoutFragment`](#layoutfragment)s for that token chain. The
[`breakToken`](#dom-layoutfragment-breaktoken) can be passed to the
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) function to produce the next
[`LayoutFragment`](#layoutfragment) for a particular child. The
[`breakToken`](#dom-layoutfragment-breaktoken) cannot be changed. If the [current
layout](#current-layout)
requires a different
[`breakToken`](#dom-layoutfragment-breaktoken) the author must perform
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) again with different arguments.

### 4.3. Intrinsic Sizes

```
[Exposed=LayoutWorklet]
interface IntrinsicSizes {
 readonly attribute double minContentSize;
 readonly attribute double maxContentSize;
};
```

A [`IntrinsicSizes`](#intrinsicsizes) object represents the [min-content
size](https://drafts.csswg.org/css-sizing-3/#min-content) and [max-content
size](https://drafts.csswg.org/css-sizing-3/#max-content) of a CSS
[box](https://drafts.csswg.org/css-display-3/#box). It has
[`minContentSize`](#dom-intrinsicsizes-mincontentsize) and
[`maxContentSize`](#dom-intrinsicsizes-maxcontentsize) attributes which represent the **border box**
min/max-content contribution of the
[`LayoutChild`](#layoutchild) for the [current
layout](#current-layout). The
attributes are relative to the inline direction of the [current
layout's](#current-layout)
writing mode.

The
[`minContentSize`](#dom-intrinsicsizes-mincontentsize) and
[`maxContentSize`](#dom-intrinsicsizes-maxcontentsize) cannot be changed. They must not change for a
[`LayoutChild`](#layoutchild) within the current layout pass.

The example below shows the border-box
intrinsic sizes of two children.

```
<style>
.child-0 {
 width: 380px;
 border: solid 10px;
}

.child-1 {
 border: solid 5px;
}

.box {
 display: layout(intrinsic-sizes-example);
 font: 25px/1 Ahem;
}
</style>

<div class="box">
 <div class="child-0"></div>
 <div class="child-1">XXX XXXX</div>
</div>
```

```
registerLayout('intrinsic-sizes-example', class {
 async intrinsicSizes(children, edges, styleMap) {
 const childrenSizes = await Promise.all(children.map((child) => {
 return child.intrinsicSizes();
 }));

 childrenSizes[0].minContentSize; // 400, (380+10+10) child has a fixed size.
 childrenSizes[0].maxContentSize; // 400, (380+10+10) child has a fixed size.

 childrenSizes[1].minContentSize; // 100, size of "XXXX".
 childrenSizes[1].maxContentSize; // 200, size of "XXX XXXX".
 }

 layout()
});
```

### 4.4. Layout Constraints

A
[`LayoutConstraints`](#layoutconstraints) object is passed into the layout method which
represents the all the constraints for the [current
layout](#current-layout) to
perform layout within.

```
[Exposed=LayoutWorklet]
interface LayoutConstraints {
 readonly attribute double availableInlineSize;
 readonly attribute double availableBlockSize;

 readonly attribute double? fixedInlineSize;
 readonly attribute double? fixedBlockSize;

 readonly attribute double percentageInlineSize;
 readonly attribute double percentageBlockSize;

 readonly attribute double? blockFragmentationOffset;
 readonly attribute BlockFragmentationType blockFragmentationType;

 readonly attribute any data;
};

enum BlockFragmentationType { "none", "page", "column", "region" };
```

The
[`LayoutConstraints`](#layoutconstraints) object has
[`availableInlineSize`](#dom-layoutconstraints-availableinlinesize) and
[`availableBlockSize`](#dom-layoutconstraints-availableblocksize) attributes. This represents the [available
space](https://drafts.csswg.org/css-sizing-3/#available) for the [current
layout](#current-layout) to
respect.

 Some layouts may need to produce a
[`LayoutFragment`](#layoutfragment) which exceed this size. For example a [replaced
element](https://drafts.csswg.org/css-display-4/#replaced-element). The [parent
layout](#parent-layout) should
expect this to occur and deal with it appropriately.

A [parent layout](#parent-layout) may require the [current
layout](#current-layout) to
be exactly a particular size. If the
[`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) or
[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) are specified the [current
layout](#current-layout)
should produce a
[`LayoutFragment`](#layoutfragment) with a the specified size in the appropriate direction.

The
[`LayoutConstraints`](#layoutconstraints) object has
[`percentageInlineSize`](#dom-layoutconstraints-percentageinlinesize) and
[`percentageBlockSize`](#dom-layoutconstraints-percentageblocksize) attributes. These represent the size that percentages
should be resolved against while performing layout.

The
[`LayoutConstraints`](#layoutconstraints) has a
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype) attribute. The [current
layout](#current-layout)
should produce a
[`LayoutFragment`](#layoutfragment) which fragments at the
[`blockFragmentationOffset`](#dom-layoutconstraints-blockfragmentationoffset) if possible.

The [current layout](#current-layout) can choose not to fragment a
[`LayoutChild`](#layoutchild) based on the
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype), for example if the child has a property like
[break-inside:
avoid-page;](https://drafts.csswg.org/css-break-3/#propdef-break-inside).

The example below shows the basic
usage of the
[`LayoutConstraints`](#layoutconstraints) object.

```
// The class below is registered with a "block-like" sizingMode, and can use the fixedInlineSize,
// fixedBlockSize attributes.
registerLayout('layout-constraints-example', class {
 async layout(children, edges, constraints, styleMap) {

 // Calculate the available size.
 const availableInlineSize = constraints.fixedInlineSize - edges.inline;
 const availableBlockSize = constraints.fixedBlockSize ?
 constraints.fixedBlockSize - edges.inline : null;

 // Web developers should resolve any percentages against the percentage sizes.
 const value = constraints.percentageInlineSize * 0.5;

 }
});
```

------------------------------------------------------------------------

The [create a layout constraints
object](#create-a-layout-constraints-object) algorithm is used to create the
[`LayoutConstraints`](#layoutconstraints) object. Depending on the
[`sizing`](#dom-layoutoptions-sizing) it will either pre-calculate the
[`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) and
[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) upfront.

When the user agent wants to [create a layout constraints
object] given `sizingMode`,
`box`, and `internalLayoutConstraints`, it *must*
run the following steps:

1. If `sizingMode` is `"block-like"` then:

 1. Let `fixedInlineSize` be the result of calculating
 `box`'s **border-box** [inline
 size](https://drafts.csswg.org/css-writing-modes-4/#inline-size) (relative to `box`'s writing mode)
 exactly like block containers do.

 2. Let `fixedBlockSize` be null if `box`'s
 [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) is unable to be calculated at this stage, (e.g.
 [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) is
 [auto](https://drafts.csswg.org/css-sizing-3/#valdef-width-auto)), otherwise the result of calculating
 `box`'s **border-box** [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) exactly like block containers do.

 3. Return a new
 [`LayoutConstraints`](#layoutconstraints) object with:

 - [`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize), and
 [`availableInlineSize`](#dom-layoutconstraints-availableinlinesize) set to `fixedInlineSize`.

 - [`percentageInlineSize`](#dom-layoutconstraints-percentageinlinesize) set to
 `internalLayoutConstraints`' percentage resolution
 size in the inline axis (relative to `box`'s
 writing mode).

 - [`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) set to `fixedBlockSize`.

 - [`availableBlockSize`](#dom-layoutconstraints-availableblocksize) set to `fixedBlockSize` if not
 null, otherwise `internalLayoutConstraints`'
 [available
 space](https://drafts.csswg.org/css-sizing-3/#available) in the block axis (relative to
 `box`'s writing mode).

 - [`percentageBlockSize`](#dom-layoutconstraints-percentageblocksize) set to
 `internalLayoutConstraints`' percentage resolution
 size in the block axis (relative to `box`'s writing
 mode).

2. If `sizingMode` is `"manual"` then:

 1. Return a new
 [`LayoutConstraints`](#layoutconstraints) object with:

 - [`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize)/[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) set to
 `internalLayoutConstraints`' fixed inline/block
 size (relative to `box`'s writing mode) imposed by
 the [parent layout](#parent-layout). Either may be null.

 See [§ 5.1 Sizing](#interaction-sizing) for
 different scenarios when this can occur.

 - [`availableInlineSize`](#dom-layoutconstraints-availableinlinesize)/[`availableBlockSize`](#dom-layoutconstraints-availableblocksize) set to
 `internalLayoutConstraints`' [available
 space](https://drafts.csswg.org/css-sizing-3/#available).

 - [`percentageInlineSize`](#dom-layoutconstraints-percentageinlinesize)/[`percentageBlockSize`](#dom-layoutconstraints-percentageblocksize) set to
 `internalLayoutConstraints`' percentage resolution
 size.

#### 4.4.1. Constraints for Layout Children

The
[`LayoutConstraintsOptions`](#dictdef-layoutconstraintsoptions) dictionary represents the set of constraints which can
be passed to a
[`LayoutChild`](#layoutchild) to produce a
[`LayoutFragment`](#layoutfragment).

```
dictionary LayoutConstraintsOptions {
 double availableInlineSize;
 double availableBlockSize;

 double fixedInlineSize;
 double fixedBlockSize;

 double percentageInlineSize;
 double percentageBlockSize;

 double blockFragmentationOffset;
 BlockFragmentationType blockFragmentationType = "none";

 any data;
};
```

 The [translate a LayoutConstraintsOptions to internal
constraints](#translate-a-layoutconstraintsoptions-to-internal-constraints) describes how to convert a
[`LayoutConstraintsOptions`](#dictdef-layoutconstraintsoptions) object into a user agents internal representation.

When the user agent wants to [translate a LayoutConstraintsOptions to
internal
constraints] given
`options`, it *must* run the following steps:

1. Let the [available
 space](https://drafts.csswg.org/css-sizing-3/#available) in the inline direction (with respect to the
 [current layout](#current-layout), be the result of:

 - If `options`'
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize) is not null, and
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize) is greater than zero, let the result be
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize).

 - Otherwhise, let the result be zero.

2. Let the [available
 space](https://drafts.csswg.org/css-sizing-3/#available) in the block direction (with respect to the
 [current layout](#current-layout)), be the result of:

 - If `options`'
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize) is not null, and
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize) is greater than zero, let the result be
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize).

 - Otherwhise, let the result be zero.

3. Let the override size in the inline direction (with respect to the
 [current layout](#current-layout), be the result of:

 - Let the result be `options`'
 [`fixedInlineSize`](#dom-layoutconstraintsoptions-fixedinlinesize).

 If the
 [`fixedInlineSize`](#dom-layoutconstraintsoptions-fixedinlinesize) is null, no override size is applied.

4. Let the override size in the block direction (with respect to the
 [current layout](#current-layout), be the result of:

 - Let the result be `options`'
 [`fixedBlockSize`](#dom-layoutconstraintsoptions-fixedblocksize).

 If the
 [`fixedBlockSize`](#dom-layoutconstraintsoptions-fixedblocksize) is null, no override size is applied.

5. Let the percentage resultion size in the inline direction (with
 respect to the [current
 layout](#current-layout),
 be the result of:

 - If `options`'
 [`percentageInlineSize`](#dom-layoutconstraintsoptions-percentageinlinesize) is not null, and
 [`percentageInlineSize`](#dom-layoutconstraintsoptions-percentageinlinesize) is greater than zero, let the result be
 [`percentageInlineSize`](#dom-layoutconstraintsoptions-percentageinlinesize).

 - If `options`'
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize) is not null, and
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize) is greater than zero, let the result be
 [`availableInlineSize`](#dom-layoutconstraintsoptions-availableinlinesize).

 - Otherwhise, let the result be zero.

6. Let the percentage resultion size in the block direction (with
 respect to the [current
 layout](#current-layout),
 be the result of:

 - If `options`'
 [`percentageBlockSize`](#dom-layoutconstraintsoptions-percentageblocksize) is not null, and
 [`percentageBlockSize`](#dom-layoutconstraintsoptions-percentageblocksize) is greater than zero, let the result be
 [`percentageBlockSize`](#dom-layoutconstraintsoptions-percentageblocksize).

 - If `options`'
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize) is not null, and
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize) is greater than zero, let the result be
 [`availableBlockSize`](#dom-layoutconstraintsoptions-availableblocksize).

 - Otherwhise, let the result be zero.

7. If the [child layout](#child-layout) is a [layout API
 container](#layout-api-container), then let the store the data (passed by
 [`data`](#dom-layoutconstraints-data)) be the result of:

 - Invoking
 [StructuredSerializeForStorage](https://html.spec.whatwg.org/#structuredserializeforstorage) on `options`'
 [`data`](#dom-layoutconstraintsoptions-data).

The example below shows the basic
usage of the
[`LayoutConstraintsOptions`](#dictdef-layoutconstraintsoptions) dictionary.

```
// The class below is registered with a "block-like" sizingMode, and can use the
// fixedInlineSize, fixedBlockSize attributes.
registerLayout('child-layout-constraints-example', class {
 async layout(children, edges, constraints, styleMap) {

 // The call below gives the child an "available" space. It will try and
 // fit within this.
 const fragment = children[0].layoutNextFragment({
 availableInlineSize: 100,
 availableBlockSize: 200,
 });

 // The call below gives the child a "fixed" size, it will be forced to
 // this size ignoring any style set.
 const fragment = children[0].layoutNextFragment({
 fixedInlineSize: 20,
 fixedBlockSize: 30,
 });

 }
});
```

### 4.5. Breaking and Fragmentation

A [`LayoutChild`](#layoutchild) can produce multiple
[`LayoutFragment`](#layoutfragment)s. A
[`LayoutChild`](#layoutchild) may fragment in the block direction if a
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype) is not none. Additionally
[`LayoutChild`](#layoutchild) which represents
[inline-level](https://drafts.csswg.org/css-display-4/#inline-level) content, may fragment line by line if the [layout
options\'](#document-layout-definition-layout-options)
[`childDisplay`](#dom-layoutoptions-childdisplay) (set by `layoutOptions`) is `"normal"`.

```
[Exposed=LayoutWorklet]
interface ChildBreakToken {
 readonly attribute BreakType breakType;
 readonly attribute LayoutChild child;
};

[Exposed=LayoutWorklet]
interface BreakToken {
 readonly attribute FrozenArray<ChildBreakToken> childBreakTokens;
 readonly attribute any data;
};

dictionary BreakTokenOptions {
 sequence<ChildBreakToken> childBreakTokens;
 any data = null;
};

enum BreakType { "none", "line", "column", "page", "region" };
```

The
[`ChildBreakToken`](#childbreaktoken) has internal slot(s):

- [`[[unique id]]`] the [unique
 id](#layout-api-context-unique-id) of the [layout api
 context](#layout-api-context) which produced this child break token. This slot is
 used so that a
 [`ChildBreakToken`](#childbreaktoken) from a previous layout pass is invalid.

------------------------------------------------------------------------

A subsequent
[`LayoutFragment`](#layoutfragment) is produced by using the previous
[`LayoutFragment`](#layoutfragment)'s
[`breakToken`](#dom-layoutfragment-breaktoken). This tells the [child
layout](#child-layout) to
produce a
[`LayoutFragment`](#layoutfragment) starting at the point encoded in the
[`ChildBreakToken`](#childbreaktoken).

### 4.6. Edges

A [`LayoutEdges`](#layoutedges) object is passed into the layout method. This
represents the sum of all the [box model
edges](https://www.w3.org/TR/CSS21/box.html#box-dimensions) (border, scrollbar, padding), for the current box which
is being laid out.

```
[Exposed=LayoutWorklet]
interface LayoutEdges {
 readonly attribute double inlineStart;
 readonly attribute double inlineEnd;

 readonly attribute double blockStart;
 readonly attribute double blockEnd;

 // Convenience attributes for the sum in one direction.
 readonly attribute double inline;
 readonly attribute double block;
};
```

Each of the accessors represents the width in CSS pixels of an edge in
each of the [abstract
dimensions](https://drafts.csswg.org/css-writing-modes-4/#abstract-dimensions)
([`inlineStart`](#dom-layoutedges-inlinestart),
[`inlineEnd`](#dom-layoutedges-inlineend),
[`blockStart`](#dom-layoutedges-blockstart),
[`blockEnd`](#dom-layoutedges-blockend)).

The
[`inline`](#dom-layoutedges-inline), and
[`block`](#dom-layoutedges-block) on the
[`LayoutEdges`](#layoutedges) object are convenience attributes which represent the
sum in that direction.

![A visualization showing the
[`LayoutEdges`](#layoutedges) object for a
[box](https://drafts.csswg.org/css-display-3/#box) with different sized scrollbar, border, and
padding.](images/edges.png){a
width="800"}

This example shows an node styled by
CSS, and what its respective
[`LayoutEdges`](#layoutedges) could contain.

```
<style>
.container {
 width: 50px;
 height: 50px;
}

.box {
 display: layout(box-edges);

 padding: 10%;
 border: solid 2px;
 overflow-y: scroll;
}
</style>

<div class="container">
 <div class="box"></div>
</div>
```

```
registerLayout('box-edges', class {
 async layout(children, edges, constraints, styleMap, breakToken) {
 edges.inlineStart; // 2 + 5 (as 10% * 50px = 5px).
 edges.blockEnd; // 7 (2 + 5)
 edges.inlineEnd; // UA-dependent, due to scrollbar.
 // Could be 2 + 5 + 0 or 2 + 5 + 16 for example.
 edges.block; // 14 (2 + 5 + 5 + 2).
 }
}
```

## 5. Interactions with other Modules

This section describes how other CSS modules interact with the CSS
Layout API.

### 5.1. Sizing

User agents must use the
[`LayoutConstraints`](#layoutconstraints) object to communicate to the [current
layout](#current-layout) the
size they would like the fragment to be.

If the user agent wishes to force a size on the box, it can use the
[`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) and
[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) attributes to do so.

The [layout API
container](#layout-api-container) can be passed size information in different ways
depending on the value of [layout
options\'](#document-layout-definition-layout-options)
[`sizing`](#dom-layoutoptions-sizing) (set by `layoutOptions` on the class).

If the value of [layout
options\'](#document-layout-definition-layout-options)
[`sizing`](#dom-layoutoptions-sizing) is `"block-like"`, then the
[`LayoutConstraints`](#layoutconstraints) passed to the [layout API
container](#layout-api-container):

- *Must* calculate and set
 [`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) based off the rules specified in
 [\[css-sizing-3\]](#biblio-css-sizing-3 "CSS Box Sizing Module Level 3")
 and the formatting context in which it participates, e.g.

 - As a
 [block-level](https://drafts.csswg.org/css-display-4/#block-level) box in a [block formatting
 context](https://drafts.csswg.org/css-display-4/#block-formatting-context), it is sized like a [block
 box](https://drafts.csswg.org/css-display-4/#block-box) that establishes a formatting context, with an
 [auto](https://drafts.csswg.org/css-sizing-3/#valdef-width-auto) [inline
 size](https://drafts.csswg.org/css-writing-modes-4/#inline-size) calculated as for non-replaced block boxes.

 - As an
 [inline-level](https://drafts.csswg.org/css-display-4/#inline-level) box in an [inline formatting
 context](https://drafts.csswg.org/css-display-4/#inline-formatting-context), it is sized as an atomic inline-level box (such as
 an inline-block).

- *Must* calculate and set
 [`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) based off the rules specified in
 [\[css-sizing-3\]](#biblio-css-sizing-3 "CSS Box Sizing Module Level 3"),
 and the formatting context in which it participates. If the [layout
 API container](#layout-api-container) has an
 [auto](https://drafts.csswg.org/css-sizing-3/#valdef-width-auto) [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size), and cannot be determined ahead of time,
 [`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) must be set to `null`.

If the value of [layout
options\'](#document-layout-definition-layout-options)
[`sizing`](#dom-layoutoptions-sizing) is `"manual"`, then the user-agent must not
pre-calculate
[`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) and/or
[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize) ahead of time, except when it is being forced to a
particular size by the formatting context in which it participates, for
example:

- If the [layout API
 container](#layout-api-container) is within a [block formatting
 context](https://drafts.csswg.org/css-display-4/#block-formatting-context), is inflow, and has an
 [auto](https://drafts.csswg.org/css-sizing-3/#valdef-width-auto) inline size, the user agent *must* set the
 [`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) to the [stretch-fit inline
 size](https://drafts.csswg.org/css-sizing-3/#stretch-fit-inline-size).

Note: In the example below the [layout API
container](#layout-api-container) has its inline size set to 50.

```
<style>
 #container {
 width: 100px;
 height: 100px;
 box-sizing: border-box;
 padding: 5px;
 }
 #layout-api {
 display: layout(foo);
 margin: 0 20px;
 }
</style>
<div id="container">
 <div id="layout-api"></div>
</div>
```

#### 5.1.1. Positioned layout sizing

If a [layout API
container](#layout-api-container) is out-of-flow positioned the user agent *must* solve
the positioned size equations ([CSS Positioned Layout 3 § 5.1 The Width
of Absolutely-Positioned, Non-Replaced
Elements](https://drafts.csswg.org/css-position-3/#abs-non-replaced-width),
[CSS Positioned Layout 3 § 5.3 The Height Of Absolutely Positioned,
Non-Replaced
Elements](https://drafts.csswg.org/css-position-3/#abs-non-replaced-height)),
and set the appropriate
[`fixedInlineSize`](#dom-layoutconstraints-fixedinlinesize) and
[`fixedBlockSize`](#dom-layoutconstraints-fixedblocksize).

Note: In the example below the [layout API
container](#layout-api-container) has its inline and block size fixed to

80.

```
<style>
 #container {
 position: relative;
 width: 100px;
 height: 100px;
 }
 #layout-api {
 display: layout(foo);
 top: 10px;
 bottom: 10px;
 left: 10px;
 right: 10px;
 position: absolute;
 }
</style>
<div id="container">
 <div id="layout-api"></div>
</div>
```

### 5.2. Positioning

All positioning in this level of the specification is handled by the
user agent.

As a result:

- Out-of-flow children do not appear as
 [`LayoutChild`](#layoutchild)ren.

- [Layout API
 containers](#layout-api-container) establish [containing
 blocks](https://drafts.csswg.org/css-display-4/#containing-block) [exactly like block containers
 do](https://www.w3.org/TR/CSS2/visudet.html#containing-block-details).
 [\[CSS21\]](#biblio-css21 "Cascading Style Sheets Level 2 Revision 1 (CSS 2.1) Specification")

- The
 [`inlineOffset`](#dom-layoutfragment-inlineoffset) and
 [`blockOffset`](#dom-layoutfragment-blockoffset) represent the position of the fragment before any
 positioning and transforms have occured.

- The [static
 position](https://www.w3.org/TR/CSS21/visudet.html#static-position) of an absolutely-positioned child of a [layout API
 container](#layout-api-container) is set to the
 [inline-start](https://drafts.csswg.org/css-writing-modes-4/#inline-start),
 [block-start](https://drafts.csswg.org/css-writing-modes-4/#block-start) padding edge of the [layout API
 container](#layout-api-container). Auto margins are treated as zero for the child.

Note: In the example below:

- \"child-relative\" would be the only child passed to the author's
 layout. If it was positioned at
 ([`inlineOffset`](#dom-layoutfragment-inlineoffset) `= 20`,
 [`blockOffset`](#dom-layoutfragment-blockoffset) ` = 30`), its final position would be (`25`, `40`) as
 the relative positioning was handled by the user agent.

- \"child-absolute\" would not appear as a
 [`LayoutChild`](#layoutchild), and instead would be laid out and positioned by the
 user agent.

- The examples above also apply in a similar way to sticky and fixed
 positioned children.

```
<style>
 #container {
 display: layout(foo);
 position: relative; /* container is a containing block */
 width: 100px;
 height: 100px;
 }
 #child-relative {
 position: relative;
 left: 5px;
 top: 10px;
 }
</style>
<div id="container">
 <div id="child-relative"></div>
 <div id="child-absolute"></div>
</div>
```

### 5.3. Overflow

The [scrollable
overflow](https://drafts.csswg.org/css-overflow-3/#scrollable-overflow) for a [layout API
container](#layout-api-container) is handled by the user agent in this level of the
specification.

A [layout API
container](#layout-api-container) should calculate its scrollable overflow exactly like
block containers do.

Even if the author's [layout API
container](#layout-api-container) positions a fragment into the [scrollable
overflow](https://drafts.csswg.org/css-overflow-3/#scrollable-overflow) region, relative positioning or transforms may cause
the fragment to shift such that its [scrollable
overflow](https://drafts.csswg.org/css-overflow-3/#scrollable-overflow) region, causing no overflow to occur.

### 5.4. Fragmentation

A [parent layout](#parent-layout) can ask the [current
layout](#current-layout) to
[fragment](https://drafts.csswg.org/css-break-3/#fragment) by setting the
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype) and
[`blockFragmentationOffset`](#dom-layoutconstraints-blockfragmentationoffset).

E.g.
[\[css-multicol-1\]](#biblio-css-multicol-1 "CSS Multi-column Layout Module Level 1")
layout would set a
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype) to `"column"` and set the
[`blockFragmentationOffset`](#dom-layoutconstraints-blockfragmentationoffset) to where it needs the child to fragment.

### 5.5. Alignment

The first/last baseline sets of a [layout API
container](#layout-api-container) is generated exactly like block containers do (see [CSS
Box Alignment 3 § 9.1 Determining the Baselines of a
Box](https://drafts.csswg.org/css-align-3/#baseline-export)). Except
that the order of the in-flow children should be determined by the in
which they are returned form the layout method (via
[`childFragments`](#dom-fragmentresultoptions-childfragments)) instead of the document order.

Note: In a future level of the specification there will be the ability
for the author to define the baselines themselves. This will be of the
form:

To *query* baseline information from a
[`LayoutChild`](#layoutchild).

```
const fragment = await child.layoutNextFragment({
 fixedInlineSize: availableInlineSize,
 baselineRequests: ['alphabetic', 'middle'],
});
fragment.baselines.get('alphabetic') === 25 /* or something */;
```

To *produce* baseline information for a [parent
layout](#parent-layout):

```
registerLayout('baseline-producing', class {
 async layout(children, edges, constraints, styleMap) {
 const result = {baselines: };

 for (let baselineRequest of constraints.baselineRequests) {
 // baselineRequest === 'alphabetic', or something else.
 result.baselines[baselineRequest] = 25;
 }

 return result;
 }
});
```

## 6. Layout

This section describes how the CSS Layout API interacts with the user
agent's layout engine.

### 6.1. Processing Model

A [layout API work task] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the user
agent layout engine to perform layout work. It consists of:

- [layout constraints] a
 [`LayoutConstraintsOptions`](#dictdef-layoutconstraintsoptions).

- [layout child] a
 [`LayoutChild`](#layoutchild).

- [child break token] a
 [`ChildBreakToken`](#childbreaktoken).

- [task type] which is
 either `"layout"`, or `"intrinsic-sizes"`

- [promise] a promise
 object.

A [layout API context] is a
[struct](https://infra.spec.whatwg.org/#struct) which describes the information needed by the [current
layout](#current-layout) to
produce either a fragment or determine the intrinsic-sizes for a
[box](https://drafts.csswg.org/css-display-3/#box). It consits of:

- [work queue] which is a
 [list](https://infra.spec.whatwg.org/#list) of [layout API work
 tasks](#layout-api-work-task). The user agent will alternate between processing
 these tasks, and running the microtask queue.

- [unique id] a internal
 unique identifier. This is used for determining that objects exposed
 to the web developer are only used within the correct layout pass.
 E.g.
 [`LayoutFragment`](#layoutfragment)s returned in the
 [`FragmentResultOptions`](#dictdef-fragmentresultoptions) dictionary belong to the current layout pass.

- [mode] which is
 either `"layout"`, or `"intrinsic-sizes"`. This is used for
 determining what the user agent layout engine is producing, and if a
 call to
 [`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment) is valid.

When the user agent wants to [create a layout API
context] given `mode`, it *must* run the following steps:

1. Return a new [layout API
 context](#layout-api-context) with:

 - [work
 queue](#layout-api-context-work-queue) being a new
 [empty](https://infra.spec.whatwg.org/#list-empty)
 [list](https://infra.spec.whatwg.org/#list).

 - [unique
 id](#layout-api-context-unique-id) being a unique id.

 - [mode](#layout-api-context-mode) being `mode`.

### 6.2. Performing Layout

The section describes how a user agent calls the web developer defined
layout to produces intrinsic sizes, and fragments.

```
// This is the final return value from the author defined layout() method.
dictionary FragmentResultOptions {
 double inlineSize = 0;
 double blockSize = 0;
 double autoBlockSize = 0;
 sequence<LayoutFragment> childFragments = ;
 any data = null;
 BreakTokenOptions breakToken = null;
};

[Exposed=LayoutWorklet]
interface FragmentResult {
 constructor(optional FragmentResultOptions options = );
 readonly attribute double inlineSize;
 readonly attribute double blockSize;
};

dictionary IntrinsicSizesResultOptions {
 double maxContentSize;
 double minContentSize;
};
```

The [`FragmentResult`](#fragmentresult) has internal slot(s):

- [`[[box]]`] a CSS
 [box](https://drafts.csswg.org/css-display-3/#box).

- [`[[inline size]]`] the inline size of the resulting fragment.

- [`[[block size]]`] the block size of the resulting fragment.

- [`[[child fragments]]`] the list of child fragments.

- [`[[data]]`] some optional
 serialized data.

- [`[[internal break token]]`] an internal representation of the
 break information for this fragment.

- [`[[unique id]]`] the
 [unique
 id](#layout-api-context-unique-id) of the current [layout api
 context](#layout-api-context). This slot is used so that a
 [`FragmentResult`](#fragmentresult) used outside the current layout pass is invalid.

------------------------------------------------------------------------

The web developer defined layout method can return either a
[`FragmentResultOptions`](#dictdef-fragmentresultoptions) or a
[`FragmentResult`](#fragmentresult). The
[`FragmentResult`](#fragmentresult) can be used for determining the final size of the
fragment or detecting if the provided
[`FragmentResultOptions`](#dictdef-fragmentresultoptions) would result in triggering a fallback to [flow
layout](https://drafts.csswg.org/css-display-4/#flow-layout).

This example show the web developer
using the
[`FragmentResult`](#fragmentresult) instead of just returning the
[`FragmentResultOptions`](#dictdef-fragmentresultoptions) object.

```
registerLayout('feature-detection', class {
 async layout(children, edges, constraints, styleMap, breakToken) {

 let result;
 try {
 result = new FragmentResult({
 childFragments: ,
 autoBlockSize: 100
 });
 } catch (e) {
 // The above call may throw, if the dictionary was just returned, it
 // would fallback to flow layout.
 }

 // The web developer can test what size the fragment will be.
 result.blockSize;

 // Instead of returning the dictionary, we can just return this object.
 return result;
 }
}
```

The [`inlineSize`], on
getting from a
[`FragmentResult`](#fragmentresult) `this`, the user agent must perform the
following steps:

1. Return `this`'
 [`[[inline size]]`](#dom-fragmentresult-inline-size-slot) internal slot.

The [`blockSize`], on
getting from a
[`FragmentResult`](#fragmentresult) `this`, the user agent must perform the
following steps:

1. Return `this`'
 [`[[block size]]`](#dom-fragmentresult-block-size-slot) internal slot.

When the
[`FragmentResult(``options``)`]
constructor is called, the user agent must perform the following steps:

1. Let `context` be the [current
 layout's](#current-layout) [layout API
 context](#layout-api-context).

2. Return the result of [construct a fragment
 result](#construct-a-fragment-result) given `context`, and
 `options`.

 The [construct a fragment
result](#construct-a-fragment-result) algorithm performs a series of validation checks (the
web developer isn't using an object from a previous invocation, and
determines the final size of the resulting fragment.

When the user agent wants to [construct a fragment
result] given `context`, and `options` the
user agent must perform the following steps:

1. Let `uniqueId` be `context`'s [unique
 id](#layout-api-context-unique-id).

2. Let `box` be the [current
 layout's](#current-layout)
 [box](https://drafts.csswg.org/css-display-3/#box).

3. Let `breakTokenOptions` be `options`'s
 [`breakToken`](#dom-fragmentresultoptions-breaktoken).

4. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `childFragment` in
 `options`'s
 [`childFragments`](#dom-fragmentresultoptions-childfragments), perform the following stubsteps:

 1. If `childFragment`'s
 [`[[unique id]]`](#dom-layoutfragment-unique-id-slot) internal slot is not equal to
 `uniqueId`, then
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror), and abort all these steps.

5. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `childBreakToken` in
 `breakTokenOptions`'s
 [`childBreakTokens`](#dom-breaktokenoptions-childbreaktokens), perform the following stubsteps:

 1. If `childBreakToken`'s
 [`[[unique id]]`](#dom-childbreaktoken-unique-id-slot) internal slot is not equal to
 `uniqueId`, then
 [throw](https://webidl.spec.whatwg.org/#dfn-throw) a
 [TypeError](https://tc39.github.io/ecma262/#sec-native-error-types-used-in-this-standard-typeerror), and abort all these steps.

6. If `sizingMode` is `"block-like"`:

 - Then:

 1. Let `inlineSize` be the result of calculating
 `box`'s **border-box** [inline
 size](https://drafts.csswg.org/css-writing-modes-4/#inline-size) (relative to `box`'s writing mode)
 exactly like block containers do.

 2. Let `blockSize` be the result of calculating
 `box`'s **border-box** [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) (relative to `box`'s writing mode)
 exactly like block containers do, given
 `fragment`'s
 [`autoBlockSize`](#dom-fragmentresultoptions-autoblocksize) as the \"intrinsic block size\".

 - Otherwise (`sizingMode` is `"manual"`):

 1. Let `inlineSize` be `fragment`'s
 [`inlineSize`](#dom-fragmentresultoptions-inlinesize).

 2. Let `blockSize` be `fragment`'s
 [`blockSize`](#dom-fragmentresultoptions-blocksize).

7. Let `clonedData` be the result of invoking
 [StructuredSerializeForStorage](https://html.spec.whatwg.org/#structuredserializeforstorage) on `options`'s
 [`data`](#dom-fragmentresultoptions-data).

8. Let `clonedBreakTokenData` be the result of invoking
 [StructuredSerializeForStorage](https://html.spec.whatwg.org/#structuredserializeforstorage) on `breakTokenOptions`'s
 [`data`](#dom-breaktokenoptions-data).

9. Let `internalBreakToken` be the internal representation
 of the [fragmentation
 break](https://drafts.csswg.org/css-break-4/#fragmentation-break) containing `clonedBreakTokenData`, and
 `breakTokenOptions`.

10. Return a new
 [`FragmentResult`](#fragmentresult) with:

 - [`[[box]]`](#dom-fragmentresult-box-slot) being `box`.

 - [`[[inline size]]`](#dom-fragmentresult-inline-size-slot) being `inlineSize`.

 - [`[[block size]]`](#dom-fragmentresult-block-size-slot) being `blockSize`.

 - [`[[child fragments]]`](#dom-fragmentresult-child-fragments-slot) being `options`'s
 [`childFragments`](#dom-fragmentresultoptions-childfragments).

 - [`[[data]]`](#dom-fragmentresult-data-slot) being `clonedData`.

 - [`[[internal break token]]`](#dom-fragmentresult-internal-break-token-slot) being `internalBreakToken`.

 - [`[[unique id]]`](#dom-fragmentresult-unique-id-slot) being `uniqueId`.

#### 6.2.1. Determining Intrinsic Sizes

The [determine the intrinsic
sizes](#determine-the-intrinsic-sizes) algorithm defines how a user agent is to query the
author defined layout for a
[box's](https://drafts.csswg.org/css-display-3/#box) [intrinsic
sizes](https://drafts.csswg.org/css-sizing-3/#intrinsic-size) information.

 The [determine the intrinsic
sizes](#determine-the-intrinsic-sizes) algorithm allows for user agents to cache an arbitrary
number of previous invocations to reuse.

When the user agent wants to [determine the intrinsic
sizes] of a [layout API formatting
context](#layout-api-formatting-context) for a given `box`, `childBoxes`
it *must* run the following steps:

1. Let `layoutFunction` be the
 [layout()](#valdef-display-layout) for the [computed
 value](https://drafts.csswg.org/css-cascade-5/#computed-value) of
 [\<display-inside\>](https://drafts.csswg.org/css-display-4/#typedef-display-inside) for `box`.

2. Let `name` be the first argument of the
 `layoutFunction`.

3. Let `documentDefinition` be the result of [get a document
 layout
 definition](#get-a-document-layout-definition) given `name`.

 If [get a document layout
 definition](#get-a-document-layout-definition) returned failure, or if
 `documentDefinition` is `"invalid"`, then let
 `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

4. Let `workletGlobalScope` be a
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) from the layout
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet)'s [global
 scopes](https://html.spec.whatwg.org/multipage/worklets.html#concept-worklet-global-scopes), following the rules defined in [§ 6.2.3 Global
 Scope Selection](#global-scope-selection).

 The user agent *may* also [create a worklet global
 scope](https://html.spec.whatwg.org/multipage/worklets.html#create-a-worklet-global-scope) at this time, given the layout
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet).

5. Run [invoke an intrinsic sizes
 callback](#invoke-an-intrinsic-sizes-callback) given `name`, `box`,
 `childBoxes`, and `workletGlobalScope`
 optionally [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel).

 If the user agent runs [invoke an intrinsic sizes
 callback](#invoke-an-intrinsic-sizes-callback) on a thread [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel), it should select a layout worklet global scope
 which can be used on that thread.

When the user agent wants to [invoke an intrinsic sizes
callback] given `name`, `box`,
`childBoxes`, and `workletGlobalScope`, it *must*
run the following steps:

1. Let `definition` be the result of [get a layout
 definition](#get-a-layout-definition) given `name`, and
 `workletGlobalScope`.

 If [get a layout
 definition](#get-a-layout-definition) returned failure, let the `box` fallback
 to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

2. Let `layoutInstance` be the result of [get a layout class
 instance](#get-a-layout-class-instance) given `box`, `definition`,
 `workletGlobalScope`.

 If [get a layout class
 instance](#get-a-layout-class-instance) returned failure, let the `box` fallback
 to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

3. Let `inputProperties` be `definition`'s [input
 properties](#layout-definition-input-properties).

4. Let `children` be a new
 [list](https://infra.spec.whatwg.org/#list).

5. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `childBox` in `childBoxes`
 perform the following substeps:

 1. Let `layoutChild` be the result of [get a layout
 child](#get-a-layout-child) given `workletGlobalScope`,
 `name`, `childBox`, and
 `context`'s [unique
 id](#layout-api-context-unique-id).

 2. [Append](https://infra.spec.whatwg.org/#list-append) `layoutChild` to
 `children`.

6. Let `edges` be a new
 [`LayoutEdges`](#layoutedges) populated with the [computed
 value](https://drafts.csswg.org/css-cascade-5/#computed-value) for all the [box model
 edges](https://www.w3.org/TR/CSS21/box.html#box-dimensions) for `box`.

7. Let `styleMap` be the result of [get a style
 map](#get-a-style-map)
 given `box`, and `inputProperties`.

8. At this stage the user agent may re-use the [intrinsic
 sizes](https://drafts.csswg.org/css-sizing-3/#intrinsic-size) from a previous invocation if
 `children`, `edges`, and `styleMap`
 are equivalent to that previous invocation. If so let the intrinsic
 sizes the cached intrinsic sizes and abort all these steps.

9. Let `context` be the result of [create a layout API
 context](#create-a-layout-api-context) given `"intrinsic-sizes"`.

10. Let `intrinsicSizesFunction` be `definition`'s
 [intrinsic sizes
 function](#layout-definition-intrinsic-sizes-function).

11. Let `value` be the result of
 [invoking](https://webidl.spec.whatwg.org/#invoke-a-callback-function) `intrinsicSizesFunction` with «
 `children`, `edges`, `styleMap` »
 and \"\`rethrow\`\", and with `layoutInstance` as the
 [callback this
 value](https://webidl.spec.whatwg.org/#dfn-callback-this-value).

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw) the let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

12. If `value` is a promise:

 - Then:

 1. Let `intrinsicSizesValue` be the result of [run a
 work queue](#run-a-work-queue) given `value`, and
 `context`'s [work
 queue](#layout-api-context-work-queue).

 If [run a work
 queue](#run-a-work-queue) returns failure, let the `box`
 fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

 - Otherwise:

 1. Let `intrinsicSizesValue` be `value`.

13. Let `intrinsicSizes` be the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `intrinsicSizesValue` to a
 [`IntrinsicSizesResultOptions`](#dictdef-intrinsicsizesresultoptions). If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

14. Set the [intrinsic
 sizes](https://drafts.csswg.org/css-sizing-3/#intrinsic-size) of `box`:

 - Let `intrinsicSizes`'s
 [`minContentSize`](#dom-intrinsicsizesresultoptions-mincontentsize) be the [min-content
 size](https://drafts.csswg.org/css-sizing-3/#min-content) of `box`.

 - Let `intrinsicSizes`'s
 [`maxContentSize`](#dom-intrinsicsizesresultoptions-maxcontentsize) be the [max-content
 size](https://drafts.csswg.org/css-sizing-3/#max-content) of `box`.

#### 6.2.2. Generating Fragments

The [generate a
fragment](#generate-a-fragment) algorithm defines how a user agent is to generate a
[box's](https://drafts.csswg.org/css-display-3/#box)
[fragment](https://drafts.csswg.org/css-break-3/#fragment) for an author defined layout.

 The [generate a
fragment](#generate-a-fragment) algorithm allows for user agents to cache an arbitrary
number of previous invocations to reuse.

When the user agent wants to [generate a fragment] of a [layout API
formatting
context](#layout-api-formatting-context) for a given `box`, `childBoxes`,
`internalLayoutConstraints`, and an optional
`internalBreakToken` it *must* run the following steps:

1. Let `layoutFunction` be the
 [layout()](#valdef-display-layout) for the [computed
 value](https://drafts.csswg.org/css-cascade-5/#computed-value) of
 [\<display-inside\>](https://drafts.csswg.org/css-display-4/#typedef-display-inside) for `box`.

2. Let `name` be the first argument of the
 `layoutFunction`.

3. Let `documentDefinition` be the result of [get a document
 layout
 definition](#get-a-document-layout-definition) given `name`.

 If [get a document layout
 definition](#get-a-document-layout-definition) returned failure, or if
 `documentDefinition` is `"invalid"`, then let
 `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

4. Let `workletGlobalScope` be a
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) from the layout
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet)'s [global
 scopes](https://html.spec.whatwg.org/multipage/worklets.html#concept-worklet-global-scopes), following the rules defined in [§ 6.2.3 Global
 Scope Selection](#global-scope-selection).

 The user agent *may* also [create a worklet global
 scope](https://html.spec.whatwg.org/multipage/worklets.html#create-a-worklet-global-scope) at this time, given the layout
 [`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet).

5. Run [invoke a layout
 callback](#invoke-a-layout-callback) given `name`, `box`,
 `childBoxes`, `internalLayoutConstraints`,
 `internalBreakToken`, and `workletGlobalScope`
 optionally [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel).

 If the user agent runs [invoke a layout
 callback](#invoke-a-layout-callback) on a thread [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel), it should select a layout worklet global scope
 which can be used on that thread.

When the user agent wants to [invoke a layout
callback] given `name`, `box`,
`childBoxes`, `internalLayoutConstraints`,
`internalBreakToken`, and `workletGlobalScope`, it
*must* run the following steps:

1. Let `definition` be the result of [get a layout
 definition](#get-a-layout-definition) given `name`, and
 `workletGlobalScope`.

 If [get a layout
 definition](#get-a-layout-definition) returned failure, let the `box` fallback
 to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

2. Let `layoutInstance` be the result of [get a layout class
 instance](#get-a-layout-class-instance) given `box`, `definition`,
 `workletGlobalScope`.

 If [get a layout class
 instance](#get-a-layout-class-instance) returned failure, let the `box` fallback
 to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

3. Let `context` be the result of [create a layout API
 context](#create-a-layout-api-context) given `"layout"`.

4. Let `sizingMode` be `definition`'s [layout
 options](#layout-definition-layout-options)\'
 [`sizing`](#dom-layoutoptions-sizing) property.

5. Let `inputProperties` be `definition`'s [input
 properties](#layout-definition-input-properties).

6. Let `children` be a new
 [list](https://infra.spec.whatwg.org/#list).

7. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `childBox` in `childBoxes`
 perform the following substeps:

 1. Let `layoutChild` be the result of [get a layout
 child](#get-a-layout-child) given `workletGlobalScope`,
 `name`, `childBox`, and
 `context`'s [unique
 id](#layout-api-context-unique-id).

 2. [Append](https://infra.spec.whatwg.org/#list-append) `layoutChild` to
 `children`.

8. Let `edges` be a new
 [`LayoutEdges`](#layoutedges) populated with the [computed
 value](https://drafts.csswg.org/css-cascade-5/#computed-value) for all the [box model
 edges](https://www.w3.org/TR/CSS21/box.html#box-dimensions) for `box`.

9. Let `layoutConstraints` be the result of [create a layout
 constraints
 object](#create-a-layout-constraints-object) given `internalLayoutConstraints`,
 `box`, and `sizingMode`.

10. Let `styleMap` be the result of [get a style
 map](#get-a-style-map)
 given `box`, and `inputProperties`.

11. Let `breakToken` be a new
 [`BreakToken`](#breaktoken) populated with the appropriate information from
 `internalBreakToken`.

 If `internalBreakToken` is null, let
 `breakToken` be null.

12. At this stage the user agent may re-use a
 [fragment](https://drafts.csswg.org/css-break-3/#fragment) from a previous invocation if
 `children`, `styleMap`,
 `layoutConstraints`, `breakToken` are
 equivalent to that previous invocation. If so let the fragment
 output be that cached fragment and abort all these steps.

13. Let `layoutFunction` be `definition`'s [layout
 function](#layout-definition-layout-function).

14. Let `value` be the result of
 [invoking](https://webidl.spec.whatwg.org/#invoke-a-callback-function) `layoutFunction` with «
 `children`, `edges`,
 `layoutConstraints`, `styleMap`,
 `breakToken` », and with `layoutInstance` as
 the [callback this
 value](https://webidl.spec.whatwg.org/#dfn-callback-this-value).

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw) the let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

15. If `value` is a promise:

 - Then:

 1. Let `fragmentResultValue` be the result of [run a
 work queue](#run-a-work-queue) given `value`.

 If [run a work
 queue](#run-a-work-queue) returns failure, let the `box`
 fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

 - Otherwise:

 1. Let `fragmentResultValue` be `value`.

16. If `fragmentResultValue` [is a platform
 object](https://webidl.spec.whatwg.org/#is-a-platform-object):

 - Then:

 1. Let `fragmentResult` be the result
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `fragmentResultValue` to a
 [`FragmentResult`](#fragmentresult).

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

 - Otherwise:

 1. Let `fragmentResultOptions` be the result of
 [converting](https://webidl.spec.whatwg.org/#dfn-convert-ecmascript-to-idl-value) `fragmentResultValue` to a
 [`FragmentResultOptions`](#dictdef-fragmentresultoptions).

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

 2. Let `fragmentResult` be the result of [construct a
 fragment
 result](#construct-a-fragment-result) given `fragmentResultOptions`.

 If an exception is
 [thrown](https://webidl.spec.whatwg.org/#dfn-throw), let `box` fallback to the [flow
 layout](https://drafts.csswg.org/css-display-4/#flow-layout) and abort all these steps.

17. Return an internal representation of a
 [fragment](https://drafts.csswg.org/css-break-3/#fragment) with:

 - The [inline
 size](https://drafts.csswg.org/css-writing-modes-4/#inline-size) set to `fragmentResult`'s
 [`[[inline size]]`](#dom-fragmentresult-inline-size-slot).

 - The [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) set to `fragmentResult`'s
 [`[[inline size]]`](#dom-fragmentresult-inline-size-slot).

 - The child fragments set to `fragmentResult`'s
 [`[[child fragments]]`](#dom-fragmentresult-child-fragments-slot).

 The ordering *is* important as this dictates their paint order
 (described in [§ 2 Layout API
 Containers](#layout-api-containers)). Their position relative to
 the **border box** of the fragment should be based off the author
 specified
 [`inlineOffset`](#dom-layoutfragment-inlineoffset) and
 [`blockOffset`](#dom-layoutfragment-blockoffset).

 - The [fragmentation
 break](https://drafts.csswg.org/css-break-4/#fragmentation-break) information set to `fragmentResult`'s
 [`[[internal break token]]`](#dom-fragmentresult-internal-break-token-slot).

 - Store `fragmentResult`'s
 [`[[data]]`](#dom-fragmentresult-data-slot) with the
 [fragment](https://drafts.csswg.org/css-break-3/#fragment).

#### 6.2.3. Global Scope Selection

When the user agent needs to select a
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) from the layout
[`Worklet`](https://html.spec.whatwg.org/multipage/worklets.html#worklet)'s [global
scopes](https://html.spec.whatwg.org/multipage/worklets.html#concept-worklet-global-scopes)
[list](https://infra.spec.whatwg.org/#list) it *must*:

- Select from at *least* two
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope)s, unless the user agent is under memory constraints.

- *Not* re-use the same
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope) more than 1000 times in a row.

 The 1000 limit was picked as a high upper bound, this
 limit may improve (downwards) over time.

 These rules exist to ensure that authors do not rely on
being able to store state on the global object or non-regeneratable
state on the class. See [the discussion in the worklets specification
about code
idempotence](https://html.spec.whatwg.org/multipage/worklets.html#worklets-idempotent).

#### 6.2.4. Utility Algorithms

The section specifies algorithms common to the [determine the intrinsic
sizes](#determine-the-intrinsic-sizes) and [generate a
fragment](#generate-a-fragment) algorithms.

 [Get a document layout
definition](#get-a-document-layout-definition) returns a [document layout
definition](#document-layout-definition) from the owning
[document](https://dom.spec.whatwg.org/#concept-document).

When the user agent wants to [get a document layout
definition] given `name`, it *must* run the
following steps:

1. Let `documentLayoutDefinitionMap` be the associated
 [document's](https://dom.spec.whatwg.org/#concept-document) [document layout
 definitions](#document-layout-definitions) map.

2. If `documentLayoutDefinitionMap`\[`name`\]
 does not
 [exist](https://infra.spec.whatwg.org/#map-exists), return failure and abort all these steps.

3. Return the result of
 [get](https://infra.spec.whatwg.org/#map-get)
 `documentLayoutDefinitionMap`\[`name`\].

 [Get a layout
definition](#get-a-layout-definition) returns a [layout
definition](#layout-definition) for a given
[`LayoutWorkletGlobalScope`](#layoutworkletglobalscope), it the desired definition doesn't exist it will
\"invalidate\" the [document layout
definition](#document-layout-definition), (so that the layout can't be used again), and return
failure.

When the user agent wants to [get a layout
definition] given `name`, and
`workletGlobalScope`, it *must* run the following steps:

1. Let `layoutDefinitionMap` be
 `workletGlobalScope`'s [layout
 definitions](#layout-definitions) map.

2. If `layoutDefinitionMap`\[`name`\] does not
 [exist](https://infra.spec.whatwg.org/#map-exists), run the following steps:

 1. [Queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task) to run the following steps:

 1. Let `documentLayoutDefinitionMap` be the
 associated
 [document's](https://dom.spec.whatwg.org/#concept-document) [document layout
 definition](#document-layout-definition) map.

 2. [Set](https://infra.spec.whatwg.org/#map-set)
 `documentLayoutDefinitionMap`\[`name`\]
 to `"invalid"`.

 3. The user agent *should* log an error to the debugging
 console stating that a class wasn't registered in all
 [`LayoutWorkletGlobalScope`](#layoutworkletglobalscope)s.

 2. Return failure, and abort all these steps.

3. Return the result of
 [get](https://tc39.github.io/ecma262/#sec-get-o-p)
 `layoutDefinitionMap`\[`name`\].

 [Get a layout class
instance](#get-a-layout-class-instance) returns an instance of the web developer provided
class. (Registered in
[`registerLayout()`](#dom-layoutworkletglobalscope-registerlayout)). If one isn't present yet, it will create a new one.
This algorithm may fail, as the constructor may throw an exception.

When the user agent wants to [get a layout class
instance] given `box`, `definition`, and
`workletGlobalScope`, it *must* run the following steps:

1. Let `layoutClassInstanceMap` be `box`'s
 [layout class
 instances](#layout-class-instances) map.

2. Let `layoutInstance` be the result of
 [get](https://tc39.github.io/ecma262/#sec-get-o-p)
 `layoutClassInstanceMap`\[`workletGlobalScope`\].
 If `layoutInstance` is null, run the following steps:

 1. If the [constructor valid
 flag](#layout-definition-constructor-valid-flag) on `definition` is false, then
 return failure and abort all these steps.

 2. Let `layoutCtor` be the [class
 constructor](#layout-definition-class-constructor) on `definition`.

 3. Let `layoutInstance` be the result of
 [Construct](https://tc39.github.io/ecma262/#sec-construct)(`layoutCtor`).

 If
 [construct](https://tc39.github.io/ecma262/#sec-construct) throws an exception, set the
 `definition`'s [constructor valid
 flag](#layout-definition-constructor-valid-flag) to false, then return failure and abort all
 these steps.

 4. [Set](https://infra.spec.whatwg.org/#map-set)
 `layoutClassInstanceMap`\[`workletGlobalScope`\]
 to `layoutInstance`.

3. Return `layoutInstance`.

When the user agent wants to [get a style map] given `box`, and
`inputProperties`, it *must* run the following steps:

1. If `box`'s [styleMap](#stylemap) is null, then:

 1. Let `styleMap` be a new
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) populated with *only* the [computed
 values](https://drafts.csswg.org/css-cascade-5/#computed-value) for properties listed in
 `inputProperties` for `box`.

 2. Set `box`'s [styleMap](#stylemap) internal slot to `styleMap`.

2. Return `box`'s
 [`StylePropertyMapReadOnly`](https://drafts.css-houdini.org/css-typed-om-1/#stylepropertymapreadonly) contained in the
 [styleMap](#stylemap) internal
 slot.

[Run a work queue](#run-a-work-queue) is designed to allow user agents to work in both a
single threaded, and multi-threaded environment.

 [Run a work
queue](#run-a-work-queue)
processes [layout api work
task](#layout-api-work-task)s enqueued with
[`intrinsicSizes()`](#dom-layoutchild-intrinsicsizes) and
[`layoutNextFragment()`](#dom-layoutchild-layoutnextfragment). It will continue processing tasks until the promise
from the web developers layout or intrinsicSizes method is resolved, or
the queue is empty after running the microtask queue.

The result of running the queue will either be the result of the layout
or intrinsicSizes method, or failure.

When the user agent wants to [run a work queue] given `promise`, and
`workQueue`, it *must* run the following steps:

1. If `promise` is not a promise, return failure.

2. [While](https://infra.spec.whatwg.org/#iteration-while) `workQueue` is not
 [empty](https://infra.spec.whatwg.org/#list-empty), and `promise` is pending:

 1. [For
 each](https://infra.spec.whatwg.org/#list-iterate) `task` in `workQueue`:

 1. Let `layoutChild` be `task`'s [layout
 child](#layout-api-work-task-layout-child).

 2. Let `box` be `layoutChild`'s
 [box](https://drafts.csswg.org/css-display-3/#box) in the
 [`[[box]]`](#dom-layoutchild-box-slot) internal slot.

 3. Let `childPromise` be `task`'s
 [promise](#layout-api-work-task-promise).

 4. If `task`'s [task
 type](#layout-api-work-task-task-type) is `"layout"`,

 - Then [queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task), or run synchronously, the following
 substeps:

 1. Let `childConstraints` be
 `task`'s [layout
 constraints](#layout-api-work-task-layout-constraints).

 2. Let `childBreakToken` be
 `task`'s [child break
 token](#layout-api-work-task-child-break-token).

 3. Let `targetRealm` be
 `layoutChild`'s
 [Realm](https://html.spec.whatwg.org/multipage/webappapis.html#concept-global-object-realm).

 4. Let `internalFragment` be the result of the
 user agent producing a
 [fragment](https://drafts.csswg.org/css-break-3/#fragment) based on `box`,
 `childConstraints`, and
 `childBreakToken`.

 Invoking [translate a LayoutConstraintsOptions to
 internal
 constraints](#translate-a-layoutconstraintsoptions-to-internal-constraints) given `childConstraints`,
 must be run to translate the given
 [`LayoutConstraintsOptions`](#dictdef-layoutconstraintsoptions) into the internal constraints for the
 user agent's layout engine.

 5. Let `fragment` be a new
 [`LayoutFragment`](#layoutfragment) with:

 - [`inlineSize`](#dom-layoutfragment-inlinesize) being
 `internalFragment`'s [inline
 size](https://drafts.csswg.org/css-writing-modes-4/#inline-size) relative to the [current
 layout's](#current-layout) writing mode.

 - [`blockSize`](#dom-layoutfragment-blocksize) being
 `internalFragment`'s [block
 size](https://drafts.csswg.org/css-writing-modes-4/#block-size) relative to the [current
 layout's](#current-layout) writing mode.

 - [`inlineOffset`](#dom-layoutfragment-inlineoffset) initially set to 0.

 - [`blockOffset`](#dom-layoutfragment-blockoffset) initially set to 0.

 - [`breakToken`](#dom-layoutfragment-breaktoken) being a new
 [`ChildBreakToken`](#childbreaktoken) representing
 `internalFragment`'s internal break
 token, if any.

 - If `internalFragment` has a
 `clonedData` object stored with it, let
 [`data`](#dom-layoutfragment-data) being the result of
 [StructuredDeserialize](https://html.spec.whatwg.org/#structureddeserialize)(`clonedData`,
 `targetRealm`), otherwise null.

 6. Resolve `childPromise` with
 `fragment`.

 - Otherwise [queue a
 task](https://html.spec.whatwg.org/multipage/webappapis.html#queue-a-task), or run synchronously, the following
 substeps:

 1. Let `internalIntrinsicSizes` be the result
 of the user agent calculating the **border box**
 min/max content contribution of `box`.

 2. Let `intrinsicSizes` be a new
 [`IntrinsicSizes`](#intrinsicsizes) with:

 - [`minContentSize`](#dom-intrinsicsizes-mincontentsize) being
 `internalIntrinsicSizes`' **border box**
 min-content contribution, relative to the [current
 layout's](#current-layout) writing mode.

 - [`maxContentSize`](#dom-intrinsicsizes-maxcontentsize) being
 `internalIntrinsicSizes`'s **border box**
 max-content contribution, relative to the [current
 layout's](#current-layout) writing mode.

 3. Resolve `childPromise` with
 `intrinsicSizes`.

 2. Wait (optionally [in
 parallel](https://html.spec.whatwg.org/multipage/infrastructure.html#in-parallel)) for all of the above tasks to complete.

 If the tasks were perform synchronously, then
 this step is a no-op.

 3. [Empty](https://infra.spec.whatwg.org/#list-empty) `workQueue`.

 4. [Perform a microtask
 checkpoint](https://html.spec.whatwg.org/multipage/webappapis.html#perform-a-microtask-checkpoint).

3. If `promise` isn't fulfilled (it is pending, or got
 rejected), return failure.

4. Return the fulfilled value of `promise`.

## 7. Examples

The layout algorithm below performs a
block-like layout (positioning fragments sequentially in the block
direction), while centering its children in the inline direction.

```
registerLayout('block-like', class {
 async intrinsicSizes(children, edges, styleMap) {
 const childrenSizes = await Promise.all(children.map((child) => {
 return child.intrinsicSizes();
 }));

 const maxContentSize = childrenSizes.reduce((max, childSizes) => {
 return Math.max(max, childSizes.maxContentSize);
 }, 0) + edges.inline;

 const minContentSize = childrenSizes.reduce((max, childSizes) => {
 return Math.max(max, childSizes.minContentSize);
 }, 0) + edges.inline;

 return {maxContentSize, minContentSize};
 }

 async layout(children, edges, constraints, styleMap) {
 // Determine our (inner) available size.
 const availableInlineSize = constraints.fixedInlineSize - edges.inline;
 const availableBlockSize = constraints.fixedBlockSize ?
 constraints.fixedBlockSize - edges.block : null;

 const childFragments = ;
 const childConstraints = { availableInlineSize, availableBlockSize };

 const childFragments = await Promise.all(children.map((child) => {
 return child.layoutNextFragment(childConstraints);
 }));

 let blockOffset = edges.blockStart;
 for (let fragment of childFragments) {
 // Position the fragment in a block like manner, centering it in the
 // inline direction.
 fragment.blockOffset = blockOffset;
 fragment.inlineOffset = Math.max(
 edges.inlineStart,
 (availableInlineSize - fragment.inlineSize) / 2);

 blockOffset += fragment.blockSize;
 }

 const autoBlockSize = blockOffset + edges.blockEnd;

 return {
 autoBlockSize,
 childFragments,
 };
 }
});
```

The layout algorithm performs a
flexbox-like distribution of spare space in the inline direction. It
creates child layout constraints which specify that a child should be a
fixed inline size.

```
registerLayout('flex-distribution-like', class {
 async intrinsicSizes(children, edges, styleMap) {
 const childrenSizes = await Promise.all(children.map((child) => {
 return child.intrinsicSizes();
 }));

 const maxContentSize = childrenSizes.reduce((sum, childSizes) => {
 return sum + childSizes.maxContentSize;
 }, 0) + edges.inline;

 const minContentSize = childrenSizes.reduce((max, childSizes) => {
 return sum + childSizes.minContentSize;
 }, 0) + edges.inline;

 return {maxContentSize, minContentSize};
 }

 async layout(children, edges, constraints, styleMap) {
 // Determine our (inner) available size.
 const availableInlineSize =
 constraints.fixedInlineSize - edges.inline;
 const availableBlockSize = constraints.fixedBlockSize ?
 constraints.fixedBlockSize - edges.block : null;

 const childConstraints = { availableInlineSize, availableBlockSize };

 const unconstrainedChildFragments = await Promise.all(children.map((child) => {
 return child.layoutNextFragment(childConstraints);
 }));

 const unconstrainedSizes = ;
 const totalSize = unconstrainedChildFragments.reduce((sum, fragment, i) => {
 unconstrainedSizes[i] = fragment.inlineSize;
 return sum + fragment.inlineSize;
 }, 0);

 // Distribute spare space between children.
 const remainingSpace = Math.max(0, inlineSize - totalSize);
 const extraSpace = remainingSpace / children.length;

 const childFragments = await Promise.all(children.map((child, i) => {
 return child.layoutNextFragment({
 fixedInlineSize: unconstrainedSizes[i] + extraSpace,
 availableBlockSize
 });
 }));

 // Position the fragments.
 let inlineOffset = 0;
 let maxChildBlockSize = 0;
 for (let fragment of childFragments) {
 fragment.inlineOffset = inlineOffset;
 fragment.blockOffset = edges.blockStart;

 inlineOffset += fragment.inlineSize;
 maxChildBlockSize = Math.max(maxChildBlockSize, fragment.blockSize);
 }

 return {
 autoBlockSize: maxChildBlockSize + edges.block,
 childFragments,
 };
 }
});
```

This example shows a simple layout
which indents child fragments for a certain number of lines.

This example also demonstrates using the previous
[`breakToken`](#dom-layoutfragment-breaktoken) of a
[`LayoutFragment`](#layoutfragment) to produce the next fragment for the
[`LayoutChild`](#layoutchild).

It also demonstrates using the
[`BreakToken`](#breaktoken)
to respect the
[`LayoutConstraints`](#layoutconstraints)\'
[`blockFragmentationType`](#dom-layoutconstraints-blockfragmentationtype), it resumes it layout from the previous
[`BreakToken`](#breaktoken).
It returns a
[`FragmentResultOptions`](#dictdef-fragmentresultoptions) with a
[`breakToken`](#dom-fragmentresultoptions-breaktoken) which is used to resume the layout.

```
registerLayout('indent-lines', class {
 static layoutOptions = {childDisplay: 'normal'};
 static inputProperties = ['--indent', '--indent-lines'];

 async layout(children, edges, constraints, styleMap, breakToken) {
 // Determine our (inner) available size.
 const availableInlineSize =
 constraints.fixedInlineSize - edges.inline;
 const availableBlockSize = constraints.fixedBlockSize ?
 constraints.fixedBlockSize - edges.block : null;

 // Detrermine the number of lines to indent, and the indent amount.
 const indent = resolveLength(constraints, styleMap.get('--indent'));
 let lines = styleMap.get('--indent-lines').value;

 const childFragments = ;

 let childBreakToken = null;
 if (breakToken) {
 childBreakToken = breakToken.childBreakTokens[0];

 // Remove all the children we have already produced fragments for.
 children.splice(0, children.indexOf(childBreakToken.child));
 }

 let blockOffset = edges.blockStart;
 let child = children.shift();
 while (child) {
 const shouldIndent = lines-- > 0;

 // Adjust the inline size for the indent.
 const childAvailableInlineSize = shouldIndent ?
 availableInlineSize - indent : availableInlineSize;

 const childConstraints = {
 availableInlineSize: childAvailableInlineSize,
 availableBlockSize,
 percentageInlineSize: availableInlineSize,
 blockFragmentationType: constraints.blockFragmentationType,
 };

 const fragment = await child.layoutNextFragment(childConstraints,
 childBreakToken);
 childFragments.push(fragment);

 // Position the fragment.
 fragment.inlineOffset = shouldIndent ?
 edges.inlineStart + indent : edges.inlineStart;
 fragment.blockOffset = blockOffset;
 blockOffset += fragment.blockSize;

 // Check if we have gone over the block fragmentation limit.
 if (constraints.blockFragmentationType != 'none' &&
 blockOffset > constraints.blockSize) {
 break;
 }

 if (fragment.breakToken) {
 childBreakToken = fragment.breakToken;
 } else {
 // If a fragment doesn't have a break token, we move onto the
 // next child.
 child = children.shift();
 childBreakToken = null;
 }
 }

 const autoBlockSize = blockOffset + edges.blockEnd;

 // Return our fragment.
 const result = {
 autoBlockSize,
 childFragments: childFragments,
 }

 if (childBreakToken) {
 result.breakToken = {
 childBreakTokens: [childBreakToken],
 };
 }

 return result;
 }
});
```
