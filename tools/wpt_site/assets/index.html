Status of this document

Crane is a web platform engine written in Zig: the browser, minus the pixels. This is its record of its own results on the web-platform-tests (WPT), measured by its own runner and regenerated with every run. Scope: the … testharness files of the 0.1 worklist, in … suites. Reftests and tests that need rendering or layout (html/rendering/, canvas, scrolling, focus traversal) are out of scope by design, and every total describes this scope and nothing wider.

No headline percentage. This is not a browser comparison, and a single rate would mostly measure encoding/, which holds … of all reported subtests (…) in … files. A file blocks the 0.1 gate when it times out, errors, crashes or finishes with no subtest passing (TIMEOUT, ERROR, CRASH, NONE-PASSED): … block today. Subtest detail comes from the runner’s result streams: ….

How to read a section

Revision history

One generation is recorded each time the progress report is regenerated and at least one file changes standing. The chart shows every generation’s files by standing, oldest at the left.

Two changes of rule sit inside this history

Early generations were reconstructed afterwards from the journals that survived, so they show less coverage than was measured at the time. From generation 82 the gate counts NONE-PASSED files as blocking; before it they sat among the files with some subtests failing, which is why blocking rises there. In this history, as in the progress report it comes from, a file that reports no subtests counts as passing every subtest.

Subtest totals are not charted: the way subtests were counted changed twice in this period, so a line would show changes of method, not of Crane.
