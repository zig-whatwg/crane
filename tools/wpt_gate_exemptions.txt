# The 0.1 gate's exemptions: worklist files omitted from the blocking count
# (AGENTS.md "The 0.1 gate", in full in .claude/rules/wpt-workflow.md). Two kinds:
#
#   intentional  ALL THREE of Chrome, Firefox and Safari intentionally deviate
#                from the spec the file tests (the user, 2026-10-17; golden rule
#                2's "all three intentionally declined" case).
#   test-bug     the file fails IDENTICALLY in Chrome, Firefox and Safari
#                because of a bug in the test, filed upstream with
#                web-platform-tests (the user, 2026-11-08). It is exempt only
#                until that bug is resolved: when the issue closes, the entry is
#                removed and the file revisited. Filing the issue still needs the
#                user's OK.
#
# Read by tools/wpt_progress.py (the progress page) and tools/wpt_site/
# (the public results site). A listed file that would block is counted in its
# kind's own group - "exempt (all three browsers intentionally deviate)" or
# "exempt until an upstream test bug is fixed" - never as blocking; a listed file
# that does not block keeps its own standing. Both tools stop with an error on an
# invalid entry - never a silent exemption.
#
# NOT exempt: a file every browser merely fails, a file only some browsers
# decline, a file the browsers fail because they lag a newer spec, a file where
# the spec text is old and simply never implemented (golden rule 2's "no newer
# spec" case: Crane follows the browsers there, and the file blocks), a file the
# browsers fail DIFFERENTLY (one fails at an earlier step, or one passes), and a
# test bug whose upstream issue is already resolved.
#
# Format: one entry per worklist path, a [path] line followed by key = value
# lines. Blank lines and lines starting with # are ignored. Every key of the
# entry's kind is required, exactly once; no other key may appear.
#
# An intentional entry (its `kind` line is optional: an entry without one is
# intentional, as every entry was before the second kind):
#
#   [content-security-policy/example/file.html]
#   kind            = intentional
#   why             = one line: what the browsers do instead of the spec, and why it is intentional
#   spec            = https://... the spec text (and the change) the browsers decline
#   chrome.result   = wpt.fyi run <run id>: <passes>/<total>
#   chrome.intent   = https://... standards position, WontFix bug or implementer objection
#   firefox.result  = wpt.fyi run <run id>: <passes>/<total>
#   firefox.intent  = https://...
#   safari.result   = wpt.fyi run <run id>: <passes>/<total>
#   safari.intent   = https://...
#
# A test-bug entry:
#
#   [html/example/file.https.html]
#   kind            = test-bug
#   why             = one line: what is wrong with the test, and how every browser fails because of it
#   upstream        = https://github.com/web-platform-tests/wpt/issues/<n> (or /pull/<n>)
#   chrome.result   = wpt.fyi run <run id>: <passes>/<total>
#   firefox.result  = wpt.fyi run <run id>: <passes>/<total>
#   safari.result   = wpt.fyi run <run id>: <passes>/<total>
#   revisit         = when <the upstream URL above> is resolved
#
# Rules the tools check: the path is in tests/wpt_0_1_worklist.txt and is
# listed once; kind is intentional or test-bug; spec and every *.intent value is
# an http(s) URL; every *.result value names a wpt.fyi run ("wpt.fyi run <id>:
# <passes>/<total>", a note may follow); upstream is a web-platform-tests issue
# or pull request URL; revisit reads "when <upstream> is resolved" with the
# entry's own upstream URL; a test-bug entry's three results have the same
# <passes>/<total>; no key of the other kind, and no unknown key, appears.
# The tools cannot see whether an upstream issue is still open: check it before
# adding an entry, and whenever the entry is reviewed.
#
