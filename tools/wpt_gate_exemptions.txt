# The 0.1 gate's exemptions: worklist files omitted from the blocking count
# (AGENTS.md "The 0.1 gate", in full in .claude/rules/wpt-workflow.md). Five kinds:
#
#   intentional  ALL THREE of Chrome, Firefox and Safari intentionally deviate
#                from the spec the file tests (the user, 2026-10-17; golden rule
#                2's "all three intentionally declined" case).
#   test-bug     the file fails IDENTICALLY in Chrome, Firefox and Safari
#                because of a bug in the test, filed upstream with
#                web-platform-tests (the user, 2026-11-08). It is exempt only
#                until that bug is resolved: when the issue closes, the entry is
#                removed and the file revisited. Filing the issue still needs the
#                user's OK.
#   needs-renderer  the file fails ONLY because no renderer answers geometry -
#                a layout box's size or position, which Crane, drawing nothing,
#                answers with CSSOM View's no-box values (the user, 2026-11-09,
#                choice (b)). It still runs and shows on the site, but does not
#                block 0.1 until a renderer exists; then the entry is removed
#                and the file revisited. Every failure of the file must be one a
#                renderer would answer: a file that also fails for any other
#                reason is not this kind.
#   needs-decoder  like needs-renderer: the file fails ONLY because the
#                platform WPT runs on has no decoder for its media - a wait on
#                canplay, stalled or playing never settles, or a typed <source>
#                is skipped because canPlayType answers "" (the user, 2026-11-18
#                2:53 PM ET; Crane decodes no media itself, the platform
#                supplies decoders, and the default platform decodes WAV only).
#                It still runs and shows, but does not block 0.1 until a
#                video-capable platform runs WPT; then the entry is removed and
#                the file revisited. A file that also fails for any other reason
#                is not this kind.
#   follows-majority  the file blocks, but Crane's result is the one golden
#                rule 2 says is correct, so no change in Crane can clear it (the
#                user, 2026-11-18 2:36 PM ET, "Add the exemption kind"): Crane's
#                result equals, subtest by subtest, that of at least two of
#                Chrome, Firefox and Safari - the browser majority where the
#                spec and the browsers disagree with no newer spec involved - or
#                of the browsers a recorded ruling follows (a user ruling, or the
#                golden-rule-2 case that decides it: a newer spec one browser
#                ships, a mechanism-by-mechanism majority). The entry comes off
#                when the browsers change: re-check it against each new aligned
#                wpt.fyi run, and whenever Crane's own result moves.
#
# Read by tools/wpt_progress.py (the progress page) and tools/wpt_site/
# (the public results site). A listed file that would block is counted in its
# kind's own group - "exempt (all three browsers intentionally deviate)",
# "exempt until an upstream test bug is fixed", "exempt until a renderer
# answers geometry", "exempt until a decoder plays its media" or "exempt:
# Crane follows the browser majority" - never as blocking; a listed file that
# does not block keeps its own standing. Both tools stop with an error on an
# invalid entry - never a silent exemption. The progress page shows a
# follows-majority file's current passes/total beside the browsers' and asks for
# a review when it no longer equals the matched browsers'.
#
# NOT exempt: a file every browser merely fails, a file only some browsers
# decline, a file the browsers fail because they lag a newer spec (Crane
# implements the newer spec: golden rule 2), a test bug the browsers fail
# DIFFERENTLY (one fails at an earlier step, or one passes), a test bug whose
# upstream issue is already resolved, and a follows-majority candidate whose
# result equals only one browser's with no ruling deciding it, or where Crane
# fails at a different step than the browsers it would cite, or fails a subtest
# the majority passes. (Since 2026-11-18 a file where the spec text is old and
# simply never implemented - golden rule 2's "no newer spec" case, Crane doing
# what the browsers do - IS exempt, as follows-majority, when Crane's result
# equals the majority's.)
#
# Format: one entry per worklist path, a [path] line followed by key = value
# lines. Blank lines and lines starting with # are ignored. Every key of the
# entry's kind is required (but a follows-majority entry's ruling), exactly once;
# no other key may appear.
#
# An intentional entry (its `kind` line is optional: an entry without one is
# intentional, as every entry was before the second kind):
#
#   [content-security-policy/example/file.html]
#   kind            = intentional
#   why             = one line: what the browsers do instead of the spec, and why it is intentional
#   spec            = https://... the spec text (and the change) the browsers decline
#   chrome.result   = wpt.fyi run <run id>: <passes>/<total>
#   chrome.intent   = https://... standards position, WontFix bug or implementer objection
#   firefox.result  = wpt.fyi run <run id>: <passes>/<total>
#   firefox.intent  = https://...
#   safari.result   = wpt.fyi run <run id>: <passes>/<total>
#   safari.intent   = https://...
#
# A test-bug entry:
#
#   [html/example/file.https.html]
#   kind            = test-bug
#   why             = one line: what is wrong with the test, and how every browser fails because of it
#   upstream        = https://github.com/web-platform-tests/wpt/issues/<n> (or /pull/<n>)
#   chrome.result   = wpt.fyi run <run id>: <passes>/<total>
#   firefox.result  = wpt.fyi run <run id>: <passes>/<total>
#   safari.result   = wpt.fyi run <run id>: <passes>/<total>
#   revisit         = when <the upstream URL above> is resolved
#
# A needs-renderer entry (the user, 2026-11-09):
#
#   [html/example/file.html]
#   kind            = needs-renderer
#   why             = one line: why the failing assertion needs a layout box - what reads geometry,
#                     and what Crane's no-box answer makes it do
#   assertion       = the failing assertion as the run reports it, e.g.
#                     promise_test: Unhandled rejection with value: object "IndexSizeError: IndexSizeError"
#
# A needs-decoder entry (the user, 2026-11-18):
#
#   [html/example/file.html]
#   kind            = needs-decoder
#   why             = one line: why the test needs a decoder - the wait that never settles, or the
#                     <source> skipped because canPlayType answers ""
#   media           = the media file(s) the test needs and their type, e.g. /media/movie_5.webm (video/webm)
#   assertion       = the failing wait or assertion as the run reports it, e.g. TIMEOUT: ... - Test timed out
#
# A follows-majority entry (the user, 2026-11-18):
#
#   [html/example/file.html]
#   kind            = follows-majority
#   why             = one line: what Crane does, which browsers do the same, and what the others do
#   chrome.result   = wpt.fyi run <run id>: <passes>/<total>
#   firefox.result  = wpt.fyi run <run id>: <passes>/<total>
#   safari.result   = wpt.fyi run <run id>: <passes>/<total>
#   matches         = chrome, safari  (the browsers whose result Crane's equals, subtest by subtest -
#                     the same status and the same failing assertion in each subtest)
#   ruling          = OPTIONAL: the user's ruling (with its date) or the golden-rule-2 case that decides
#                     the entry; required when matches names only one browser
#   revisit         = when <what ends the exemption>, e.g. when Chrome, Firefox or Safari changes its result
#
#   The results are the aligned stable runs at Crane's own WPT revision (tests/wpt's
#   .crane-upstream-revision), so the browsers ran the file Crane runs.
#
# (Each value is one line; the examples above wrap only here.)
#
# Rules the tools check: the path is in tests/wpt_0_1_worklist.txt and is
# listed once; kind is intentional, test-bug, needs-renderer, follows-majority
# or needs-decoder; spec and every *.intent value is an http(s) URL; every
# *.result value names a wpt.fyi run ("wpt.fyi run <id>: <passes>/<total>", a
# note may follow); upstream is a web-platform-tests issue or pull request URL;
# a test-bug entry's revisit reads "when <upstream> is resolved" with the
# entry's own upstream URL, and its three results have the same
# <passes>/<total>; a follows-majority entry's matches names chrome, firefox or
# safari, comma-separated, each once, at least two of them unless the entry has a
# ruling, the browsers it names have the same <passes>/<total>, and its revisit
# starts "when "; no key of another kind, and no unknown key, appears.
# The tools cannot see whether an upstream issue is still open: check it before
# adding an entry, and whenever the entry is reviewed.
#
