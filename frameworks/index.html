3What is not run, and why

rendering 102 tests · skipped by the projects 52 tests · skipped by TodoMVC's spec 45 tests
  • Rendering. Crane draws nothing, so tests whose result depends on layout geometry or pixels are not run. Computed style, events, timers and animations do run. Not run for this reason: 102 tests (Angular 13, htmx 13, jQuery 76), each listed with its reason in the project's exclusion list (tools/fw_matrix/excluded/).
  • Browser-automation protocols. React, Svelte and Vue run their browser tests only through Playwright or Puppeteer, which drive the browser over the Chrome DevTools Protocol (CDP) or WebDriver BiDi. Crane does not speak either yet, so these suites wait until after Crane 0.1; Crane does not run them through a harness of its own instead. React 19.3.1, Playwright end-to-end tests (react-devtools-inline, fixtures/flight, the compiler playground) (19 tests): Waits for Chrome DevTools Protocol support in Crane, after 0.1. Playwright drives Chromium through that protocol; its other browsers are patched Firefox and WebKit builds with protocols of their own. React's other tests run under Jest with jsdom, not in a browser. Vue 3.5.45, e2e tests (36 tests): Waits for WebDriver BiDi or Chrome DevTools Protocol support in Crane, after 0.1: Puppeteer drives a browser through one of the two. Puppeteer also clicks at a point computed from the element's layout box, which needs a renderer. Vue 3.5.45, e2e-browser tests (Transition, TransitionGroup) (84 tests): Waits for Chrome DevTools Protocol support in Crane, after 0.1. The tests run inside the page, but the project's provider, Playwright, opens Chromium through that protocol, and some tests call it directly (Vitest's cdp()). Svelte 5.57.3, runtime-browser and custom-elements samples (39 and 36): Waits for Chrome DevTools Protocol support in Crane, after 0.1. The project's harness launches Chromium through Playwright directly, and Playwright drives it through that protocol; Svelte offers no other driver for these tests. Its other tests run under jsdom, not in a browser.
  • Node. Node runs only the projects' own build steps, test servers and test runners, never inside Crane. jQuery's pages are served by its own test server (jquery-test-runner) with its own dependencies; Angular's are built by its own Bazel and served by its own web-test-runner, one target per page. htmx's test page and the TodoMVC apps are static files, served as they are.
  • Left out by the projects, and the rest. The projects skip 52 tests (Angular 48, htmx 4) themselves. 9 test files run only through the project's Node test runner, not in a browser page (htmx 9). TodoMVC's app spec skips 45 tests for the apps it names (its localStorage test for apps that keep nothing there, and each app's known issues). Angular's web test targets of the documentation site and Angular DevTools (18 and 50 targets): They test two applications kept in the repository (adev/, the angular.dev site, and devtools/, the browser extension), not the framework; the framework's own 44 targets under packages/ run above.

4How this was measured
  • Each page is opened in Crane's console as a user opens it, and read from the test framework's own report; Chrome's numbers come from the same pages, or from the project's own runner where the project runs its tests that way. Pass rate is the tests that passed of the tests run: tests not run (below) are in neither number.
  • Angular 22.2.6: https://github.com/angular/angular at v22.2.6 (dda2d41d9483), Jasmine, web-test-runner manual mode. Crane: run fw1-b5-angular-3, Crane fb2911d722a (console sha256 e0dad3700d23da59…); served by the project's own test server, web-test-runner manual mode (the target's own _debug), run by the project's own Bazel 8.8.2 (its MODULE.bazel.lock sha256 5b7676ba4c7ee9b8…), one target per page. Chrome: Chrome for Testing headless shell 159.0.8154.2, pinned by sha256 1bf5977949625d9e…; the project's own runner on 2026-11-14: bazel test <target>_chromium: web-test-runner through Puppeteer in the headless shell rules_browsers pins, the 44 targets; read from its log tmp/fw-results/lanes/chrome/fw1-b5-chrome-ng/bazel-test.log; run fw1-b5-chrome-ng. web-test-runner's page takes no filter, so every test runs; the tests that need layout and fail are classified as rendering after the run (excluded/angular-22.2.6.txt). Two zone.js targets (browser_test, browser_green_test: 1,074 specs in Chrome) do not run in Crane: Crane has no Notification API, so the project skips its Notification tests, which leaves an empty describe() that Jasmine refuses before any test runs.

Chrome: Chrome for Testing 157.0.8103.78, pinned by sha256 0dc5fa1ed2364c0e…; the project's own runner on 2026-11-14: htmx's own web-test-runner 1.0.0 with @web/test-runner-playwright 1.0.0 and Playwright 1.58.2 from its package-lock (npm run test:chrome: test/web-test-runner.config.mjs, all 88 test files), Playwright's Chromium set to Chrome for Testing 157.0.8103.78; read from its log tmp/fw-results/lanes/chrome/fw1-b9-htmx-chrome/wtr.log; run fw1-b9-htmx-chrome.

  • TodoMVC: the apps todomvc.com lists, each the unmodified build committed in tastejs/todomvc at ff43b02e59df, examples/<app>/ pinned by its sha256 and checked at every fetch. Crane runs TodoMVC's app spec (cypress/e2e/spec.cy.js, 29 tests) through Crane's port of it: the same tests, steps and checks in the app's own page, driving the unmodified app through DOM events as Cypress drives it, with Cypress's configuration read from the project's cypress.config.js (includeShadowDom: queries reach into shadow roots as Cypress's do). What the port cannot do in Crane is layout: an element counts as visible by its computed style (no box, visibility, opacity) and not by its size, clipping or transforms, and an action neither scrolls the element into view nor checks that something covers it. Cypress's hooks that run before an app's own scripts have no in-page equivalent: an app counts as started when its page has loaded and its heading is visible, and the spec's spy on localStorage.setItem is installed then. Chrome's TodoMVC numbers are the same port run in Chrome for Testing: the same tests through the same harness as Crane's, so the two columns differ only by the browser. 5 apps are given to both as the folder of the build todomvc.com links (backbone/dist, emberjs/todomvc/dist, javascript-es5/dist, jquery/dist, web-components/dist), the path form of the spec's framework value: its default folders for those names are unbuilt sources. Their name-keyed settings in the spec (known issues, localStorage checks) then do not apply, in Cypress as in the port. Crane: run fw1-b8-todomvc-2, Crane 6495ddc8d50. Chrome: Chrome for Testing 157.0.8103.78, run fw1-b8-chrome-2. The port was checked test by test against TodoMVC's own Cypress suite in Chrome (run fw1-b8-cypress-2, 2026-11-14): the two agree on 1,162 of 1,202 tests. Cypress did not run 31 of the others, in 6 apps, because a hook had failed earlier in their suite and Mocha skips the rest of it, and 1 more is such a hook's own failure; the port ran them and they passed. AngularDart 5, CanJS 1, CanJS + RequireJS 1 and Polymer 1 fail in the port and pass in Cypress: the port's harness and Cypress's differ there in timing or focus. That run: TodoMVC's own Cypress 15.14.2 suite (cypress.config.js and cypress/e2e/spec.cy.js at ff43b02e59df, unmodified; binary zip sha256 fb68a62b5b47...), one app per run as tests/cya.js runs them.
