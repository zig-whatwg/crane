# Architecture: An API callback's current context is the callee's realm, and a Global of it pins that realm

**Date**: 2026-09-30
**Lesson**: Inside a V8 API callback, `v8_Isolate_GetCurrentContext` is the realm the called function was made in. A Global of it that is never released keeps that realm - every object in it - alive for the life of the isolate, so a page that calls a frame's methods keeps the frame alive after the frame is gone.

**Why**: The adapter wraps every `Local` V8 lends it in a heap-allocated `Global` the caller owns ([Local vs Global at the FFI seam](architecture-local-vs-global-at-the-ffi-seam.md)). A forgotten `Global<Context>` is not a small leak: a native context holds the realm's global object, its intrinsics and every interface object - about 1.3 MB with Crane's 1,263 interfaces - and a `Global<Object>` of anything made in the realm pins it the same way.

**What Happened**: html5lib_write.html and html5lib_write_single.html ended every sweep with SIGTRAP: V8's "Ineffective mark-compacts near heap limit", 1,120 MB live after a full collection, raised by the runner's LowMemoryNotification between pages. Alone they passed - at 1.17 GB and 898 native contexts, just under the limit; any prefix tipped them over. `CRANE_HEAP_GC=1` (a full GC before the reading) showed the contexts were live, and a heap snapshot (`CRANE_HEAP_SNAPSHOT=<path>`) showed each held directly from `(Global handles)`. Two-variant probes (9 contexts if the previous page is freed, 18 if not) bisected it: `for (const c of frameDoc.childNodes)`, `childNodes.forEach` and `childNodes[Symbol.iterator]().next()` retained; indexed access, sibling walks, `document.open/write/close`, onload and fetch did not. The iterable callbacks took the current context and never disposed it; their per-interface iterator-prototype "cache" compared the address of that fresh Global, so it never hit, and each call built a new prototype and dropped the old Global over it. Cross-realm iteration was also wrong: a frame's URLSearchParams iterated from its parent counted 3 entries of 18.

**Fix**: every iterable callback releases what it takes (the context by `defer`, and every key, value, iterator and result handle once `Set`/`SetReturnValue` has copied it); the iterator prototype is `GetFunction(context).prototype` of an isolate-scoped FunctionTemplate kept in the isolate's template storage - V8 caches a template's instantiation per native context, so it is one object per interface per realm (WebIDL 3.7.10) and dies with the realm. Red, tests/v8/page_realm_operations_test.zig: 16 rounds of cross-realm iteration left 2,592 global handles and both realms alive; after, none and none.

**Takeaway**: **A Global of the current context taken in an API callback is a Global of the callee's realm. Release it, or every realm whose functions you ever called stays alive - and when V8 dies of OOM between pages, count the live native contexts after a forced GC before suspecting the page.**
