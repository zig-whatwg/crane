# Architecture: State keyed by an instance's address outlives a teardown that misses it - and the next instance there inherits it

**Date**: 2026-10-05
**Lesson**: Per-type state kept in a map keyed by the instance's address dies only if that type's own deinit runs. A teardown that runs a base class's deinit instead leaves the entry behind, and when the slab reissues the address the next instance either overwrites it - what it owned leaks - or, where the map fills lazily, reads it as its own.

**Why**: `Node.deinitNodeByType` tore every element it did not name down with `Element.deinit`, so HTMLElement's state (the inline style `style` writes) and the element type's own (an input's dirty value, a textarea's raw value, an img's request state) stayed in their `InstanceRegistry`s and StateMaps, all keyed by `@intFromPtr(instance)`. The node's wrapper's finalizer then released the slot (the teardown had completed, as far as Node knew), and the slab reissued it. A registry's `createIn` `put` the new instance's state over the stale one; a StateMap's lazy `getOrPut` found the stale one and used it.

**What Happened**: `dom/ranges/Range-surroundContents.html` leaked 3 blocks in some processes and 0 in others (6 under leak traces: `setInlineStyleProperty`'s name and value and the map's growth). A scratch runner that logged every registry put on an existing key, and every element the tree walk tore down as an Element, named it in one run: two HTMLElement states with one inline property each, overwritten at addresses the walk had torn down as HTMLDivElement - the `testDiv` that `Range-test-iframe.html` styles `display: none`, in the html subtree `restoreIframe` removes. The leak needed a collection to free the slot and a new HTML element to take it, which is why it moved with the process. A Crane test that drops styled subtrees and collects them (`crane/lk3-styled-subtree-collected.html`) leaked 13,243 blocks on main, and one of its cases failed: a new textarea's `value` read `"text 0 234"`, a dead textarea's raw value.

**Fix**: the tree walk dispatches an element through `instance.vtable.deinit` - the same function the collector's finalizer runs for a collected root - with a check that the chain reached `Node.deinit` (a deinit that does not chain is completed as an Element, so its subtree still goes); the teardown is recorded in `instance_lifecycle` before anything of the element runs. And the next birth at an address checks it: a registration that finds an entry frees it and logs an error, and the lazily filled maps drop any entry at a new instance's address in its init. One trap on the way: the registries are the process's, but the arena their blocks live in is re-made per Browser (`runtime.initializeRuntime`), so an entry left by an earlier Browser points into freed memory - the check must not free THAT one. Each entry records the runtime it was made in (`runtime_epoch`); an earlier runtime's is forgotten, never read.

**Measured** (FULL sweep vs main-9ef434a820's): `leaked:` 83 -> 41 (execution-timing/087, joint-session-history iframe-state, iso-2022-jp, link-load shards gone), blocking and passing flat, CRASH 0; gc_bench on a styled-subtree body: 89.9 -> 58.2 MB general allocator over 10,000 cycles.

**Takeaway**: **A side table keyed by an address needs both exits: the owner's own deinit on every teardown path, and a check at the address's next birth - an entry found there belongs to a dead instance, never to the new one.**
