# Testing: A runner must not decide what a page includes before its parse ends

**Date**: 2026-11-07
**Lesson**: The WPT runner installed its own harness whenever its completion hook was missing when the page load returned. The load returns while the parser is still blocked on a script, and that script can come before the page's own testharness.js include, so the page then got two harnesses. In a file that ends at the harness timeout, the runner's empty copy reported first, and the file reported no subtest at all.

**Why**: `Context.LoadWait` is a settle point in the style of CDP Page.navigate: the navigation has committed and the parser has run as far as it can. "As far as it can" includes a parser waiting on a parsing-blocking script, and its callers rely on that (nd_new_document_per_load_test loads a page blocked by a stylesheet nobody answers). The runner read that return as "the parse has reached its includes". A script fetched before the include, such as `/common/get-host-info.sub.js`, was still pending at that moment. So the runner ran testharness.js (harness A, no subtests, its 10 s timer armed), and the page's own include then made harness B with the subtests. Both hooks write the same `window.__wpt_results`. A's timer was armed first, so at the harness timeout A completed with an empty test list.

**What Happened**: html/cross-origin-embedder-policy/reporting-to-frame-owner and reporting-to-worker-owner end at the harness timeout by design (worker-owner.js posts a report whose body is a platform object, so a DataCloneError leaves one subtest waiting). Since lane loadpath1 moved the harness to the page's include, they reported nothing in 6-9 of 10 fresh-process runs, on base and tip alike. The giveaway was in the journal: TIMEOUT with 0 subtests and NO message, a duration of 10,007 ms (the harness's own timer, not the runner's ceiling plus its grace), and the same heap and realm count as a run that reported. It was the only such record among 13,169 files. Sweeps hid it most of the time: a warm runner usually had the script before the load wait looked.

**Fix**: In runHTMLTest, decide the late install only once the parse has ended. The runner spins the event loop with `Browser.spinEventLoopUntil` until HTML "the end" step 1 has moved the document out of readiness "loading", within the run's ceiling, and installs nothing for a parse that never ends. The goal reads readiness natively, because a spin's goal runs no script. The settle point itself is unchanged, since its other callers rely on it. Upstream wptrunner has no late install at all (wpt lint requires the include). Crane's runner keeps one only for pages that never reach its hook from an include. Red test: crane/coi2-harness-after-pending-script.html, in which the server holds a parsing-blocking script before the include.

**Takeaway**: **"The load returned" is not "the parse is done". Before a host decides what a page did or did not include, wait for the document to leave readiness "loading". And when a file reports no subtest at all, compare its record's duration and message with a reporting run's: a harness timer that fired on time with nothing to report means a second harness.**
