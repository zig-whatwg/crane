# Architecture: Count which fields objects set before choosing their rare data

**Date**: 2026-11-08
**Lesson**: A field's name and its feature do not say how often it is set. Before moving fields to a block made on first use, count, over a broad sample of real pages, how many objects set each one, and move only what few set.

**Why**: Rare data saves its fields' bytes on every object that never makes it, and costs an allocation, a pointer and an indirection on every object that does. A field that looks feature-specific can be written by a step every object passes through: then the "rare" block is made for a large share of objects, and the change costs more than it saves.

**What Happened**: Lane perf2 batch 7 moved Document's cold state to a DocumentRareData. The candidate list by reading the code included the back/forward cache's record (blocking details, suspension time, suspended timer handles) and the about base URL - both looked like features few pages use. A temporary instrumented Debug runner (a counter per field group, read at each Document's teardown; tmp/plans/perf2-evidence/batch7/count-instrumentation.patch, never committed) ran in-process over a 1-in-16 sample of the 0.1 worklist: 823 files, 15,601 Documents. The import map, the pragma language, the target element and the fullscreen, pointer lock and picture-in-picture elements were set on none; the prefetch hints on 1, the frozen base URL on 13, the pointer states on 15, the template contents owner on 548 (3.5%). But "unload a document" records the suspension time and timer handles on EVERY unloaded document - 27% of them - and every iframe's initial about:blank gets an about base URL - 16%. Those stayed in the state. Two fields were set on none because nothing could set them (the string pool's only writer had no caller, the CSP self-origin's setter had no caller): they were removed, not moved.

**Fix**: For any rare-data split: write the counters as a patch kept out of the tree; build one Debug runner with it; run a worklist sample in-process (`crane-measure.sh run`, no `--parallel`, so one process prints the cumulative counts); record the table as evidence; move what few objects set; name each moved field's measured rate in the commit. Count "ever set" for fields that are cleared again (the pointer states), not only their value at teardown.

**Takeaway**: **Measure each field's set rate on real pages before choosing rare data: a field set by a step every object passes through (unload, an iframe's initial document) is not rare, whatever feature it belongs to.**
