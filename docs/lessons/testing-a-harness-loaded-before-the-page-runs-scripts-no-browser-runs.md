# Testing: A harness loaded before the page runs scripts no browser runs

**Date**: 2026-11-02
**Lesson**: Crane's WPT runner ran testharness.js in the realm before the page was parsed, and answered the page's own `<script src=/resources/testharness.js>` with an empty script. That is a runner deviation. Every script before the include then ran with a harness no browser has, so its results can never match a browser's.

**Why**: Upstream wptrunner preloads nothing. The page's own includes load the harness, and wptrunner serves its own testharnessreport.js at `/resources/testharnessreport.js`, where it calls `setup(props)` and `add_completion_callback` (tools/wptrunner/wptrunner/environment.py `get_routes`, wptrunner/testharnessreport.js). So in a browser, harness API used before the include throws a ReferenceError. The harness also reads `<meta name=timeout>` from the document when it runs; preloaded, it saw no document at all.

**What Happened**: content-security-policy/generic/generic-0_8_1.sub.html was a "race flake": 0 of 2 subtests passed in 75 of 149 records, 1 of 2 in the rest. Its first inline script calls `async_test()` before the include. Every browser throws there and reports one subtest, "Wildcard host matching works.", PASS (wpt.fyi 2026-11-02). In Crane, the preloaded harness let the script go on to append a cross-host script. That fetch started before the page's `<meta http-equiv=Content-Security-Policy>`, so nothing blocked it (a correct result: the request's policy container is cloned at fetch start). The script then raced the parser's `wildcardHostTestFailure.js`. The brief took it for a race between CSP delivery and the fetch. The engine was right, and the race was one that no browser could reach. The tell was in the counts: Crane reported 2 subtests where wpt.fyi lists 1.

**Fix**: The runner loads the harness at the page's include. Its script loader answers `/resources/testharness.js` with the cached harness, and `/resources/testharnessreport.js` with the runner's own report: output off, the runner's explicit timeout for a long file, and the completion callback. A page whose source never names testharness.js still gets the harness before the page. A page that reached no report include gets the hooks after it is parsed. The decision is test_harness.zig `harnessLoadFor`. Crane tests: crane/c6-harness-before-include.html (red on the old runner), c6-harness-long-timeout.html, c6-harness-page-setup.html and c6-harness-no-include.html.

**Takeaway**: **Before chasing an engine race, compare the subtest list with wpt.fyi's. A runner that reports subtests no browser reports is running the page differently from a browser, and its results can never match.**
