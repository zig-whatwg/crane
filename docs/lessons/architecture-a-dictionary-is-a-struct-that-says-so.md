# Architecture: A dictionary is a struct that says so, never "any struct"

**Date**: 2026-11-23
**Lesson**: The binding's dictionary rules must test a POSITIVE marker codegen emits (`pub const webidl_dictionary = true`), never "a struct without Meta": every new handle-holding struct otherwise passes for a dictionary, and its argument's handle is released under the impl.

**Why**: The V8 binding decides who frees an argument's Global with allowlist predicates (`argHandleIsCopied`, `memberHandleIsSafe`, `typeRetainsContext`, `needsArgCleanup`, `freeConvertedArg`). Each has a structural rule for dictionaries: a struct is copied when every field's handle is safe, because a dictionary reads each member through a Get of its own. A JSValue field counts as safe there - a member's JSValue aliases only its own Get handle. A struct whose single JSValue field IS the argument's Global passes that rule.

**What Happened**: Lane bind1 replaced the callback carrier - a fake function pointer holding the binding's Global in its bits - with `runtime.BorrowedCallbackFunction { function: JSValue }` and `runtime.BorrowedCallbackInterface { object: JSValue }`. The function-pointer shape had been unknown to the struct rules (a pointer, so "not copied": keep the handle). The new types are structs, and `argHandleIsCopied` would have walked them as dictionaries, found one safe JSValue field and answered "copied" - so `convertArgReleasingWith` would dispose the argument's Global right after conversion, and the impl's `keep()` (a v8_Global_TakeOver of that Global) would read a freed box. Every addEventListener, MutationObserver constructor and event handler setter would have been a use-after-free. Read while generalizing the predicates, before the first build. A second rule of the same shape was missed and caught by the full gate: the union conversion picks its dictionary arm as "a struct without `Meta`", and TimerHandler's `function` arm became one - `setTimeout({ toString() { ... } })` went to the callback arm and threw a TypeError instead of running the string (tests/v8/flk4_union_tostring_handle_test, 2 FAIL); `isDictionaryValue` had the same test.

**Fix**: First the two rules were taught to skip the callback types (86085bc56) - which fixed the case, not the class (the integrator, 2026-11-23). Then detection went positive: codegen writes `pub const webidl_dictionary = true` into every generated dictionary and `pub const webidl_record_entry = true` into every record entry; `interface.isDictionaryType` / `isRecordEntryType` read them, and every rule - argHandleIsCopied, typeRetainsContext, needsArgCleanup, freeConvertedArg, getDefaultArgValue, the union's dictionary and record arms, isDictionaryValue, the from/to-V8 struct paths (a compile error for an unmarked struct), the variadic-parameter test - uses them. The compile error then named a bug the shape test had hidden: every record<K, V> dictionary member (AudioWorkletNodeOptions.parameterData and ten more) and record argument (MLGraphBuilder.build's MLNamedOperands) was converted as a sequence of {key, value} dictionaries - a plain object was a TypeError - and a record argument was taken as a variadic one. Records now convert by WebIDL 3.2.23. Test structs that stand for a dictionary or a record entry declare the marker; `retention_predicate_test` pins that a plain struct holding a JSValue is no dictionary.

**Takeaway**: **Never classify a value by its Zig shape: a gate that says "dictionary" (or "record", or "variadic") tests a marker the generator emits, and an unmarked type is a compile error - a struct of one JSValue looks exactly like a safe dictionary.**
