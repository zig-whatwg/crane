# Architecture: A realm a navigation replaced is kept by whoever was meant to end it - hand it to the collector, and hang its edges on its OWN global

**Date**: 2026-10-02
**Lesson**: Every realm an iframe's navigations replaced stayed alive until the iframe went - 200 navigations kept 200 native contexts and 235 MB, and a test that renavigates in a loop ran V8 out of memory - because the integration kept each one in `retired_realms` to end it "with the integration". Handing it to the engine as a detached realm (no root into it; it ends when the collector takes it or with its page) made the probe flat, but only after two more holds were found by measurement.

**Why**: HTML unloads and destroys the old document; its Window lives as long as script reaches anything of the realm, and no longer. A Zig list that "ends it later" is a root by another name. Detaching it (protocol_realms `detach`, realms2's removed-frame path) is the right model, with two traps that removed frames never hit:
- A replaced realm's `context->Global()` is the global PROXY the new realm took over: V8 reuses it (`Context::New` with the old proxy after `DetachGlobal`), so `ctx->Global()->GetPrototype()` is the NEW realm's global object. The detach's "retain on the global" (wrappers the cache held strongly, tagged callbacks) hung the old realm's objects on the new realm. The retainer must be the old hidden global, kept since the handover (`retired_global`) - `v8_Object_RetainInPrivateArray(holder, ...)`, not a context-based lookup.
- A heap snapshot of the one realm still kept (the first, which had also hosted the initial about:blank document) showed exactly four strong handles into it, all Promise objects: a navigation API method tracker's committed and finished capabilities. HTML leaves a cross-document navigation's tracker ongoing on the document it left; Crane's capabilities were Globals.

**What Happened**: crane/td-frame-navigation-churn.html (200 navigations of one iframe to about:blank) read 200 native contexts / 231,906 KB on main. After the detach at replace: 3 / 7,373 KB; compile-event-handler-settings-objects.html went from a 1.37 GB OOM CRASH to a 13 MB TIMEOUT. crane/r3-navigated-frame-realm-collected.html still kept the realm of the first navigation; the retainer walk (BFS from "(Global handles)", skipping weak edges, realm of each root object from its prototype's constructor's context) named the four Promise handles. Promise capabilities are now tagged with their realm at creation (`v8_Global_TagRealm`, as callbacks are) so a detached realm keeps them by an edge from its global object; settling one whose realm was collected is a no-op.

**Fix**: `replaceRealm` -> `IFrameIntegration.releaseCurrentRealm` + `engine.destroyWindowRealm(old, .global_detached)`, which detaches a frame realm whose WindowProxy went on; the wrapper cache's detach and `v8_Object_WeakenTaggedHandles` take the realm's hidden global as the holder; `createPromise` tags both capability handles and releases them through `v8_Global_Dispose` (which untags).

**Takeaway**: **"Ended later by its owner" is a root until the owner goes - give a lifetime that depends on reachability to the collector, and when you hang edges on a global, make sure it is the realm's own global object and not the proxy a navigation handed on.**
