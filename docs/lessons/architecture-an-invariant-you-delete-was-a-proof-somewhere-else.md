# Architecture: An invariant you delete was a proof somewhere else - find every "X, so Y" that cited it

**Date**: 2026-11-09
**Lesson**: When a change deletes an invariant (here: "a wrapped node's ancestors are wrapped"), every piece of code that used it as a proof of something else ("an unwrapped root means no node of its tree is reachable") silently becomes wrong. Find those places by the invariant's own wording and by the tests that pinned it, and give each its own check - at the caller that drew the conclusion, never in a hook other callers share.

**Why**: The wrapper redesign's node tracing wrapped every unwrapped ancestor of a node it wrapped, so its JS edges reached the root (the "upward closure"). Three frees leaned on that without saying so in their code: runtime.orphan_roots freed a removed root no wrapper reached at its realm's end; the HTML parser's adapter freed an orphan it made when the orphan's root had no wrapper; a template freed its contents when the contents' root had none. Each asked one node - the root - and concluded something about the whole tree. P7 deleted the closure (a query must wrap only its results), so a script can hold a node read out of a tree whose root it never touched: HTML "in body" removes the body for a `<frameset>` after a script in it ran `getElementById`.

**What Happened**: Lane wr1 batch 7 found the three by grepping for the closure's wording ("upward-closed", "a wrap reaches up to the root", "wraps every ancestor") and wrote a red Crane test per case (tests/wpt/crane/wr7-*). The first fix put the guard in the shared destroy hook (Node's destroyUninsertedHook: "free only a subtree with no wrapped node"). That hook also serves `destroyRoot` - an owner tearing down a window's document under live wrappers by design - and `zig build test` failed 106 tests, most with "9 node(s) alive at the agent's end" (the window's document kept). Moved to the two callers that drew the conclusion (the parser's orphan loop, the template's contents), the suite went to the expected handful; a narrowing to "the tree holds nothing" (subtree_holds) instead of "no node of it is wrapped" then exposed holder holds the realm-end orphan drain had been masking (editing tests: lone elements still counted at the agent's end), so the check became the exact question the closure used to answer: is any node of this tree wrapped (dom.wrapper_tracing.holdsWrapper, a pruned walk - a wrapped node is held).

**Fix**:
1. Before deleting an invariant, grep for its wording and for the tests that pin it (here: tests that asserted `hasWrapper(root)` after wrapping a leaf). Each hit is either a test that changes with the invariant or a proof that needs a replacement.
2. Replace each proof with the question it was standing in for, asked directly (does any node of this subtree have a wrapper?), not with a broader one (does anything hold it?) that changes behaviour the deletion did not touch.
3. Put the replacement at the caller that drew the conclusion. A hook shared by several callers carries only what is true for all of them.

**Takeaway**: **Deleting an invariant deletes the proofs that cited it. Grep for its words, re-ask each proof's real question at its own caller, and ask exactly that question - no broader.**

**Status (2026-11-13, lane wr1 batch 11)**: a fourth proof that leaned on the upward closure, missed by the grep because it never used the closure's words: refcount step 7a's net (node_wrappers.zig `endedRealmNet`, `runNetRoot`, `endRealm`) read "no wrapper reaches this tree" from the ROOT's own empty slot.
