# Debugging: An event made by `init` has no type and reaches no listener

**Date**: 2026-10-02
**Lesson**: Build an event the engine fires with `interfaces.Event.call_constructor` (or the event type's own constructor), never with the generated `init` followed by `call_initEvent`: that event is typeless, and nothing says so.

**Why**: The generated `interfaces.Event.init` reaches `EventImpl.init`, which makes a bare Instance - "state will be done in call_constructor". The internal state (initialized flag, the type string dispatch matches listeners on) is made only by the constructor. `call_initEvent` starts with `getInternal(instance) orelse return`, so on a bare instance it returns success having done nothing, and the dispatch that follows matches no listener. Every step reports success; the only symptom is a test waiting for an event until the harness times out.

**What Happened**: No `<img>` ever fired `load` or `error` - from `img.src = url`, from `setAttribute`, from the parser - on main and on the secfeatures branch after its M-img commit (f71b9142f) put "update the image data" in the img element's attribute change steps. Both image paths, HTMLImageElement's `fireEventOnElement` and a legacy copy in Element.zig (`triggerImageSrcChange` + `fireImageEvent`, a synchronous, policy-blind `globalFetch` of the raw src on every set), built their event with `Event.init` + `call_initEvent`. The M-img commit's Crane test stayed red (TIMEOUT) and the 18 mixed-content/gen img-tag and picture-tag files with it. A probe with listeners on `new Image()`, an appended img and a detached one, IDL setter and setAttribute, got "nothing" in every case within 3 s - which ruled out the attribute change steps, URL resolution and document membership at once and left the event itself.

**Fix**: `Event.call_constructor(instance.ctx, type, EventInit{ bubbles = false, cancelable = false })`, then `EventTarget.dispatchTrusted`, then `releaseIfUnwrapped(generation)` - the `fireLoadEventOnIframe` pattern (a listener can keep the event, so never `defer deinit`; the old code freed it only on error and leaked it on success). Element.zig's duplicate path was deleted. A grep for the pattern (`interfaces.<X>Event.init(` or an aliased `Event.init(allocator, ctx)` followed by `call_initEvent`) found no other site: `BeforeUnloadEvent`'s impl `init` makes its base state itself (`initEventBase`), and WebSocket and XHR call `initEvent` on constructed events.

**Takeaway**: **When an event "never fires", first check that the event has a type: `initEvent` on an event without internal state is a silent no-op.** A probe that varies everything except the event, and gets nothing everywhere, points at the event.
