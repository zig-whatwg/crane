# Workflow: A pass lost to a binding fix can be a false pass - read wpt.fyi before calling it a regression

**Date**: 2026-10-12
**Lesson**: When a merge makes WPT files stop passing, read the three browsers' messages for those files on wpt.fyi and look for sibling files that gained the same count. Do both before treating the loss as a regression and opening a lane to fix it.

**Why**: Many WPT files detect a behaviour through a probe built from another API: a storage item, a posted message, a timer. While the probe is broken, a file can pass for the wrong reason. A file that expects the probe to report "nothing happened" passes because the probe never reports anything. When a later change fixes the probe, the file starts failing. The new failure is correct, but a sweep shows it as a regression on a commit that has nothing to do with the feature the file tests.

**What Happened**: Generation 130 (main c2c4b851ff) made websockets/unload-a-document/002.html and 004.html block: 3 passed in generation 129 and 0 passed now. The brief for lane wsunload named lane oac (agent-cluster keys on navigation) as the prime suspect and said that all three browsers pass both files. Neither was true:
- **The probe.** The 001-004 files decide whether a document was discarded on navigation. The document writes `sessionStorage[uuid] = 'true'` through Storage's named setter, navigates away, and calls `history.back()`. If the document that comes back finds the key, it is a new document, so the old one was discarded. Crane keeps no document in session history (it has no back/forward cache), so the document is always discarded. Before lane specops (1f9e9ce980, special operations bound from `Meta.special_operations`), Storage had no named setter in the binding. The write made an expando on that Window's Storage wrapper, and the returning document never saw it. 002 and 004 expect the document to be kept, and they passed: 004 looped through about 60 navigations until the opener's 4 s timer called `t.done()` (121 native contexts, 148 MB). 001 and 003 expect the document to be discarded, and they failed.
- **The ledger.** In the sweep journals from d48c884729 to c2c4b851ff, websockets/ held at 1,850 passing subtests. 001 went from (0 passed, 3 failed) to (2, 1) and 003 from (0, 1) to (1, 0), exactly what 002 (2, 1 -> 0, 3) and 004 (1, 0 -> 0, 1) lost. Two files stopped blocking and two started, so the blocking count did not change. The same commit took webstorage/ from 115 to 1,279 passing subtests.
- **The browsers.** The aligned stable runs of 2026-10-06 (Chrome 154 run 6218298311311360, Firefox 157 run 4877098740350976, Safari 27 run 5164107446878208) show Chrome and Firefox failing every 002 variant, and all three failing 004. Each failure carries Crane's new message, "assert_unreached: document was discarded". Safari passes 002 only, from its page cache.
- **The bisect.** Debug runners built at aa2d7708dc (just before the specops merge) and b62e025bd0 (the specops merge) confirmed it: 3 of 4 passed before the merge and 0 of 4 after. The merge that the brief suspected, lane oac, played no part.

**Fix**: No code change. Crane test crane/wsu-session-storage-named-across-navigation.html pins the probe's mechanism: a named-property write in one document is an item that the navigable's next document reads. It fails on the frozen d48c884729 runner and passes from b62e025bd0 on. Making 002 and 004 pass needs a back/forward cache, a design decision; Safari passes 002 and no browser passes 004.

**Takeaway**: **Before opening a lane for a "regression", read the browsers' failure messages for the file on wpt.fyi (`https://storage.googleapis.com/wptd/<sha>/<run>/<test path>` serves them per test), and diff the whole directory's journal numbers, not only the file's. A loss balanced by a sibling's gain, with the browsers failing the same way, is a false pass removed. Record it as such.** See also [A WebAssembly.Module is bound to its agent cluster](spec-compliance-a-wasm-module-is-bound-to-its-agent-cluster-not-its-origin.md): a probe made real breaks every suite that uses it.
