# Architecture: A sweep that destroys its entries must take each out of its map first

**Date**: 2026-10-22
**Lesson**: A realm's wrapper cache tore its entries down in a walk over its own map and destroyed each CacheEntry it handled, but left the destroyed entry in the map; a teardown the walk ran made a new platform object, the slab gave it a handled entry's address, and the cache answered "wrapped" for it from the destroyed entry, so nothing ever freed it.

**Why**: The walk runs types' own teardown steps (`gc.onObjectFreed`), and those reach back into the cache: a response body freed there ends its fetch's body, and Resource Timing's "mark resource timing" makes a PerformanceResourceTiming, asks the engine to keep it (traceChild) and frees it only if it is not wrapped (`releaseIfUnwrapped` -> `engine.hasWrapper` -> `cache.get`). The slab hands out the last freed Instance handle first, so the new object had the address of an object the walk had just freed - whose CacheEntry the map still held, freed. A map that holds what was already destroyed answers for whatever is put at that address next.

**What Happened**: Every full sweep of main printed intermittent groups of 5 or 6 `leaked:` blocks at runner exit, empty traces in ReleaseSafe, gone under `CRANE_LEAK_TRACES=1` in some lists, and every Codex row had to pair its leak counts against main's. Lane exitleak1 reproduced it with `fetch/api/basic/stream-response.any.js` alone (main [0,0,6] ReleaseSafe, [0,6,5,0,0,6] Debug), named the six blocks with a traced Debug run (createEntry's name, two InternalStates and three ResourceTiming clones), and then logged every PerformanceResourceTiming made and freed with its realm, a frame-pointer trace and whether it was wrapped. The leaked ones were made in worker and service worker realms, after their cache's teardown had started, reported wrapped, and `WrapperCache.set` never ran - so the suspected path (a wrapper put into the map being iterated) was not it. Worker realms only, because their teardown runs with the context entered; a Window realm's Window is freed before its cache and its timeline is gone.

**Fix**: `WrapperCache.deinit` takes each entry out of the map (`removeByPtr`, through the entry iterator, which re-reads the map's size) before tearing it down, so the map only ever holds entries still to come; `set` refuses while the cache is torn down; `relevantWrapper` refuses for a realm whose cache is torn down, before the wrap path logs. The object a teardown makes is then unwrapped, and its maker frees it. Red tests: tests/v8/exitleak1_teardown_wrap_test.zig (a TextEncoder whose vtable copy makes and wraps an object in its teardown, in a Window and a worker realm: 1 fail and 2 SIGSEGV on main).

**Takeaway**: **A walk that runs other code while it destroys entries must remove each entry from its container before destroying it - a destroyed entry left in a map will answer the next lookup at its key, and an address is a key the allocator reuses at once.**
