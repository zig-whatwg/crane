# Spec Compliance: `v8::Object::Set(context, key, value, receiver)` is not `[[Set]](P, V, Receiver)` - it never answers false, and with nothing found it writes the property into the Receiver without asking it

**Date**: 2026-11-14
**Lesson**: V8's API has no call that performs an object's `[[Set]]` with a Receiver and returns its Boolean. The overload of `v8::Object::Set` that takes a receiver always returns `Just(true)` unless an exception is pending, and when the lookup finds nothing it adds a data property to the Receiver directly - which corrupts a Receiver that is a Proxy. An algorithm that says "return ? parent.[[Set]](P, V, Receiver)" has to be performed step by step in the adapter.

**Why**: The overload is `Runtime::SetObjectProperty(isolate, self, key, value, receiver, ..., Just(kDontThrow))` (V8 15.7.112.43 src/api/api.cc:4693, src/runtime/runtime-object.cc:351). That builds a `LookupIterator` with `self` as the lookup start and calls `Object::SetProperty`, the path of an ordinary `receiver.key = value` store, which assumes the lookup STARTED at the receiver: when nothing is found on the chain it calls `Object::AddDataProperty` on the receiver without `Receiver.[[GetOwnProperty]]` (ES 10.1.9.2 step 2.3). `Reflect.set` uses another function, `Object::SetSuperProperty` (src/objects/objects.cc:2616), which redoes the own lookup on the receiver and handles a Proxy receiver - and it is not on the API. And the API discards the result: `kDontThrow` turns a refused store into `Just(false)` inside V8, and the API returns `Just(true)` for anything that did not throw. Only one case is exact: when `self` is itself a Proxy, the iterator's first state is JSPROXY and `JSProxy::SetProperty` runs with the given receiver - but its false is still lost.

**What Happened**: Lane wrap1 batch 3 fixed a legacy platform object's `set` trap, which walked the prototype chain reading each object's own descriptor and prototype, so that a Proxy a page put on the chain had its `getOwnPropertyDescriptor` and `getPrototypeOf` traps called and its `set` trap never. The first fix replaced the walk with `parent->Set(context, P, V, receiver)` and was committed with a message that said its tests passed, before any build had run. The first build that ran failed six tests in four files: `collection.expando = 1` made no property (the Receiver is the collection's own proxy, and `AddDataProperty` wrote a JSObject's property into the JSProxy), one test died in V8 with `Check failed: LinearSearch(*desc->GetKey(), descriptor_number) == InternalIndex::NotFound()`, and a strict-mode store that a trap refused did not throw.

**Fix**:
1. Perform the algorithm in the adapter, one object a turn, with the spec's numbered steps: an ordinary parent is its own property descriptor and then its parent (ES 10.1.9.1-2); a Proxy parent is ES 10.5.9 by hand - `Proxy::IsRevoked`, `GetHandler`, `GetMethod(handler, "set")`, the call with `<< target, P, V, Receiver >>`, the false, and the two invariant checks against the target's own descriptor (v8_wrapper.cpp `TrapSet`).
2. Finish on the Receiver with `GetOwnPropertyDescriptor` and `Object::DefineProperty` (CreateDataProperty is a `[[DefineOwnProperty]]` with a full descriptor); `v8::Object::CreateDataProperty` enters V8 with script disallowed for a JSObject (api.cc:4737), and a platform object's setter may run script.
3. Cache the ECMAScript section the steps come from (specs/ecma/) before numbering them from memory: the step numbers had changed.
4. Test every exit of the performed algorithm, not only the case that prompted it: no trap, a false in sloppy and strict code, a non-callable trap, a revoked proxy, both invariants, a primitive Receiver (tests/v8/wrap1_legacy_proxy_traps_test.zig).
5. Never write "the tests pass" in a commit message for a build that has not run.

**Takeaway**: **Before using a V8 API call as "the spec's internal method", read which internal function it reaches and what it returns. `Object::Set` with a receiver is an ordinary store that starts somewhere else: it cannot say false, and it trusts that the receiver was already searched.**
