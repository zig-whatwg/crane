# Architecture: Under kAuto, every do_callback=true API at call depth 0 is a microtask checkpoint

**Date**: 2026-10-09
**Lesson**: V8's kAuto policy performs a microtask checkpoint whenever an API scope entered with do_callback=true (ENTER_V8) returns to call depth 0, not only at the end of Script::Run. So native code with no script on the stack ran every queued microtask from inside whatever it was doing. The trigger could be an Object::Set on a handler, a HasPrivate, a DefineProperty with a descriptor, a promise resolve, or a SetIntegrityLevel.

**Why**: V8 13.1 api.cc enters most API calls through one of three macros. ENTER_V8 creates a `CallDepthScope<true>`, whose destructor calls `FireCallCompletedCallback` (api-inl.h). At call depth 0, `FireCallCompletedCallbackInternal` (isolate.cc) runs `PerformCheckpoint` under kAuto. PREPARE_FOR_EXECUTION and ENTER_V8_NO_SCRIPT use `CallDepthScope<false>`, which fires nothing. Which macro an API uses is not in the header and does not follow from its name. Object::Get is PREPARE (false). Object::Set, Has, HasOwnProperty (and so HasPrivate) and DefineProperty(PropertyDescriptor) are ENTER_V8. CreateDataProperty and DefineOwnProperty are ENTER_V8_NO_SCRIPT on a JSObject but ENTER_V8 on a proxy. HTML performs a checkpoint only in "clean up after running script" (a callback's included) and at the event loop's own points.

**What Happened**: edges caught a MutationObserver callback running once per record in the middle of a parse. The stack went through v8_CreateLegacyPlatformObjectProxy's `handler->Set` for the trap functions. The audit that followed registered an `AddCallCompletedCallback` in an instrumented runner and ran it over 1,255 worklist files. It recorded each distinct native stack once per process, as raw addresses symbolized offline with `atos`. A first version that called `backtrace_symbols` on every event made each realm creation take about 30 s, because realm creation fires about 8,000 times. The audit found the proxy plus about 20 other sites, among them realm creation (isMaterializedInterfaceObject's HasPrivate, registerPropertiesAsOwnOnObject's DefineProperty, the namespaces' Set and PreventExtensions), tracing (tracedValue, wrapper_cache edges on node removal), engine.setProperty (event handler content attributes), promise resolve and reject from tasks, Freeze on frozen arrays, structured serialization, module linking, the dynamic-import continuation, and the iterator protocol of WebIDL conversions.

**Fix**:
1. Where an API with do_callback=false does the job, use it. The proxy handler's traps are now `CreateDataProperty` (ENTER_V8_NO_SCRIPT on a JSObject, 13.1 api.cc:4526), which also stops an Object.prototype setter from seeing them.
2. Elsewhere, put the step under `NativeStepScope` (v8_wrapper.cpp), which is `Isolate::SuppressMicrotaskExecutionScope` (13.1 api.cc:10100-10113). It raises the call depth for its lifetime and fires nothing when it ends. It must live on the C++ stack.
3. Never put it on a callback invocation. kAuto's checkpoint after `Function::Call` from native code is "clean up after running a callback".
4. Make sure every event loop checkpoints after every task. A promise a native task resolves now relies on that checkpoint. Timers were the gap: `NativeTimerManager.pollEach` takes the loop's checkpoint as `AfterEach`.

**Takeaway**: **Under kAuto, a native step is a microtask checkpoint unless it proves otherwise. Read the API's ENTER_V8 macro in api.cc for the version you link, and measure the call-completed callback rather than guessing which calls fire.**
