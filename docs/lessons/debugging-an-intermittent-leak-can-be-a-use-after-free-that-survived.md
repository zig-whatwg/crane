# Debugging: An intermittent leak can be a use-after-free that survived

**Date**: 2026-11-15
**Lesson**: Twelve allocations leaked at a WPT runner child's exit and a segmentation fault in the same file were one bug: code that ran in a realm the collector had taken. When the freed memory it read still looked intact, the run "only" leaked.

**Why**: A leak report names what was never freed, not what the leaking code read on its way. Code that makes an object in a place where nothing can free it is usually running where it should not run at all, and what it reads there may already be gone. The leak is the mild outcome of the same road; the crash is the other one, rarer and easier to lose.

**What Happened**: html/browsers/browsing-the-web/navigating-across-documents/replace-before-load/location-setter-user-click.html clicks a button in a frame, and each click navigates that frame. The WPT runner's pointer (html.user_input.Pointer) kept the old button weakly, as an address and a slab generation. Nothing of script reached the old document, so the collector took its realm - and queued the realm's end as a task. Until that task ran, the old tree was still allocated, the weak reference still answered, and the next pointer move fired pointerout / pointerleave / mouseout / mouseleave at the old button. Each event's timestamp step read the old Window's Performance object, which the collector had already freed with its wrapper. 39 of 96 bug-finding runner processes leaked the events (nothing frees an object of a realm with no engine); 3 of 96 crashed in that read. The first hunt counted the leaks and kept only the last five lines of the two processes that ended with status 134, so the crash was seen and lost; the hunt's script kept only logs with a "leaked" line.

**Fix**: (1) Keep the whole log of every process that ends with a non-zero status, whatever the hunt is for. (2) Read the leak's allocation stack (CRANE_LEAK_TRACES=1) for what the code READ, not only for what it allocated, and ask whether that code should have run at all. (3) Make the state deterministic in a unit test: the frame navigates, script keeps nothing, a collection is requested (engine.requestGarbageCollection), the loop is NOT turned, then the embedder acts (tests/html/tl1_pointer_after_realm_collected_test.zig crashes with the runner's stack on main's code). (4) Fix the road - a pointer is over nothing of a document that is not fully active - and then the state itself, in which a Window names objects the collector has freed (docs/lessons/architecture-a-collected-realm-has-not-ended.md).

**Takeaway**: **An intermittent leak and an intermittent crash in the same file are one bug until proven otherwise. A hunt keeps every abnormal log, and a leak's stack is read for what the code touched as well as for what it kept.**
