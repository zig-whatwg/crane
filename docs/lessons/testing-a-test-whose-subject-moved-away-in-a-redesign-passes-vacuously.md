# Testing: A test whose subject moved out from under it in a redesign keeps passing vacuously

**Date**: 2026-11-22
**Lesson**: When a test drives a scenario in order to reach a subject (a table, a queue, a path), assert that it reached that subject before you assert anything about it. A redesign that sends the scenario's objects elsewhere leaves the test green, and from then on it tests nothing.

**Why**: tests/v8/wrapper_cache_tombstones_test.zig's "a page that makes and drops wrapped elements leaves its realm's end cheap misses for every node it queued" was written for a time when every element's wrapper had a WrapperCache record. A collection that found the wrapper dead took the record out of the cache's hash map and left a tombstone. The test made 24 rounds of 2,048 dropped elements, then asserted that the table still had a tenth of its slots free and a bounded miss probe. Then the wrapper redesign moved a node's wrapper into the node's own slot ("A node wrapper never enters the WrapperCache", node_wrappers.zig). From that point the scenario never touched the table. Its assertions held on a table of capacity 8 with 1 live entry and 0 tombstones (lane mem1's measurement on main's src, 2026-11-22). The test kept passing for months.

**What Happened**: Lane mem1's byte bound made the test's one shape precondition fail: `queue.pendingNodes() >= rounds * 1024`, because the queue now frees past max(2 MB, live) at depth zero. The integrator's grant required the rewrite to "stress the table at the scale it was written for". To find out what that scale was, both trees were measured with the table's slot counts printed. The table was empty in both, so the stress had already gone before the change that exposed it.

**Fix**: Put the subject back in the scenario and assert that it is reached. Each round now also makes and drops 2,048 `new TextEncoder()`. A non-node record is the cache's, and its collection removes the entry (unlinkCollected). Before the existing bounds, the test now asserts a churn floor: after the last round, at least half a round of tombstones are standing. Those removals come after the last insert, and the guard rehashes only before an insert. Red: the old scenario (elements only) under the new assertions fails the churn floor. The probe bounds then check a loaded table.

**The same hole elsewhere** (lane mem1's audit, 2026-11-22: 37 files that reach the wrapper cache):
- tests/html/parser_wrapper_count_test.zig (C1 navigation, C1 document.write, C3 frame) and the wrapper halves of five tests in tests/html/nodeholds_cost_test.zig assert "no wrapper per node" by reading the `wrapper_cache_entries` diagnostic counter. Nodes are counted as `node_wrappers` now, so those assertions cannot fail even if every node were wrapped.
- tests/v8/constructed_wrapper_test.zig's "WrapperCache.set refuses to replace a live wrapper" uses a Text node. It now tests node_wrappers.adopt, and the cache's own AlreadyWrapped refusal for non-nodes is left with no test.
- tests/v8/tsanfix1_entry_read_after_free_test.zig names a sweep that nodes no longer take, so only its non-node objects exercise the bug it was written for.
- Several test headers still describe nodes going through the cache.
The integrator gave these to lane mem1 as one test-hygiene unit, where each new assertion must fail on a deliberately broken variant.

**Takeaway**: **Pair every "the bound holds" assertion with a "the scenario reached the bound's subject" assertion: tombstones > 0, the queue non-empty, the slow path taken at least once. Without it, a redesign that moves the subject makes the test vacuous, and nothing says so.** When a test's precondition starts failing after an unrelated change, measure what the test's subject looks like on the old tree too, before you loosen or rewrite anything.
