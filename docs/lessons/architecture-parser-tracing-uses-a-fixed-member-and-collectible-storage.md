# Architecture: Parser tracing uses a fixed member and collectible storage

**Date**: 2026-10-08
**Lesson**: Variable parser references belong in a collectible container under one fixed Document member, with temporary roots for active native calls.

**Why**: V8's `Private::ForApi` interns names in an isolate-wide registry whose symbols never collect. Its [linked-header contract](../../jsengines/v8/include/v8-object.h) explicitly limits this API to statically fixed properties. Deleting a property releases its value, but does not release its registry key. An address-derived key for every TreeNode therefore retains metadata after EOF; allocator address reuse can hide it in a tiny repeated-page measurement.

**What Happened**: The persistent parser introduced `document-parser:{TreeNode-address}` for each mapped DOM wrapper. The old-source full sweep recorded large encoding files with substantially higher heap and wall time, and Fetch GC changed from twelve passes to six passes plus a timeout. A controlled three-file forced-GC comparison then found 1,582,530 address-derived key strings occupying 82,291,560 bytes at the integrated tip, versus none on the baseline; total snapshot node self size rose from 8,314,800 to 149,477,060 bytes. Fetch GC passed all twelve subtests in both serial controls, but its heap rose from 7,739 to 145,593 KiB and wall time from 622 to 12,237 ms. These establish retained key metadata and a same-list heap/timing regression; they do not by themselves establish the full-sweep timeout's cause. Neither a clean Zig allocator nor flat Global-handle counts measures this JavaScript-heap registry.

**Fix**: Keep a fresh hidden Array in the fixed `document-parser:nodes` Document slot. Append wrappers with dense numeric `defineOwnProperty` calls, so numeric prototype setters cannot run. Numeric properties and the backing store collect with the Array. A suspended parser holds no independent Owned value; its Document wrapper owns the graph. Active calls fallibly root both the Document and Array before callbacks. Nested calls share those roots. The final call moves the roots to local ownership, releases the native parser while they still protect adapter cleanup, and then releases them without touching the freed parser.

Ordinary detach clears its member only while its own publication flag, Document epoch, and slab generation match. The Document clears `active_parser` before detach, so association-pointer equality alone is the wrong guard. A reentrant replacement installs a fresh bag; the old call's temporary root protects its nodes, and old cleanup cannot erase the new member. Collector destruction drops native associations and publication flags without manipulating engine edges. An Owned wrapper cannot protect a native Instance against forced realm teardown; saved context and generation checks still apply.

The protection scope includes completion callbacks after `pump()` returns, restoration after `processInserted()`, and abort's interactive readiness callback before the open-element stack is popped. Bag publication is verified by reading back the exact Array before releasing its construction hold: `traceValue` itself returns no error. A node receives a temporary wrapper root before property-definition allocations. If definition fails, revoke only that node's mapping, retain the adapter's unwrapped-orphan cleanup ownership, record the error, and discard input before another callback can follow an unrooted pointer. Keep the tree callbacks installed for existing owners and cleanup.

The design follows [Blink HTMLTreeBuilder::Trace and Detach](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/parser/html_tree_builder.cc), which traces member containers and preserves in-flight construction state, and [WebKit HTMLDocumentParser::insert, append, and resumeParsingAfterScriptExecution](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/parser/HTMLDocumentParser.cpp), which protect the parser across calls that can detach it. Crane's existing wrapper-tree graph likewise uses fixed member names with collectible child storage. These are lifetime designs; their tracing and refcount implementations cannot be copied across engines.

Focused allocator-backed tests cover detached-node survival and eventual collection, an unreachable suspended Document cycle, replacement during completion and abort readiness, numeric prototype setters, realm teardown, native EOF/cancellation, constructor allocation failure, and cancellation of a terminally failed parser while an active caller retains it. A cleanup guard may acquire roots while leaving the parse failure intact; cancellation discards parser-owned blocker and deferred preparations before detaching, without resuming failed input. Engine bag publication and property-definition allocation failures have been reviewed statically; the constructor allocator test and explicit native failure-state control do not inject failures into V8. The corrected same-list forced-GC comparison has zero dynamic parser key strings, one fixed 48-byte member key, and 8,314,668 bytes of snapshot node self size (baseline 8,314,800). Fetch GC returns to 7,739 KiB and 634 ms with all twelve passes, versus baseline 7,739 KiB and 622 ms. All 31,711 subtests in the control pass on every side. Three priority timer runs have zero ownership violations and zero fatal or leak markers. This resolves the measured metadata retention; the full sweep must still verify the timeout in its original process context.

**Takeaway**: **Use fixed traced member names for variable graphs, and protect active calls until native cleanup finishes; deleting dynamic private properties cannot reclaim V8's key registry.**
