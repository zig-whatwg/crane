# Architecture: An agent's thread keeps its engine current for the agent's life - never its first page

**Date**: 2026-11-22
**Lesson**: The engine's isolate must be entered on the agent's thread from `createAgent` until `destroyAgent`, not as a side effect of one realm being entered for its life: once that realm (the host's first page) went, every operation that asked for the current isolate failed or crashed.

**Why**: The V8 adapter asks `v8_Isolate_GetCurrent()` in about fifty places (JsScope.initFromV8Context, the context manager, the wrapper cache, page_realm.installWindowOperations, ...) and opens a HandleScope on it. Nothing entered the isolate but the Browser's first page, whose realm is entered for its life (WindowRealmOptions.entered_for_life). Host-opened tabs (lane cdph) are entered only per call, so that tabs can end in any order - which left no isolate current between calls once the first page closed. A renderer's main thread keeps its isolate entered for the thread's life, and each worker thread its own; that invariant is the agent's, not a page's.

**What Happened**: The CDP test pass (lane tpg) found three symptoms with one cause: cdph_host_realm_entry_test (host tabs with no page entered for life) and cdph_host_tabs_test "the first page closes like any tab" crashed with SIGSEGV at 0x228 in HandleScope::Initialize while a tab's realm ended (protocol_realms.endRealm -> context_manager.keyOf); and a host tab's NAVIGATION after the first page closed failed with ContextCreationFailed (Context.replaceRealm -> installWindowOperations -> JsScope.initFromV8Context: no isolate -> OperationFailed). Puppeteer and Playwright close the initial page routinely. A first fix entered the isolate in endRealm and detach only; the navigation showed it was one patch of fifty.

**Fix**: `createAgent` enters the isolate when no other is current on the thread (the agent is that thread's: `AgentRecord.entered_for_life`), and `destroyAgent` exits it after `endAgent`, last - panicking if another isolate entered later is still current (agents of one thread end in reverse order). Realms' own enter/exit pairs nest inside, unchanged. A realm's end still enters its own context when no context is entered (Blink's DisposeContext runs under a ScriptState::Scope). docs/engine-protocol.md states the rule: an agent's operations run on its own thread with its engine current for the agent's life; another engine's adapter meets it its own way.

**Takeaway**: **An invariant every engine call relies on (an isolate is current) belongs to the owner whose life matches it - the agent and its thread - never to an object that happens to live as long most of the time (the first page): when that object can go first, the invariant goes with it, in fifty places at once.**
