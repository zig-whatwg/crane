# Workflow: Measure a test runner's CDP traffic through its own launch route

**Date**: 2026-11-21
**Lesson**: To learn which Chrome DevTools Protocol commands a framework suite's runner needs, run the suite unmodified against Chrome for Testing with the runner's own protocol log on - Playwright through `SELENIUM_REMOTE_URL` (chromedriver as the endpoint) with `DEBUG=pw:protocol`, Puppeteer through `PUPPETEER_EXECUTABLE_PATH` with `NODE_DEBUG='puppeteer:protocol*'` - and read the command set from the log, not from the runner's source alone.

**Why**: A runner's Chromium code names every command it could send (playwright-core 1.64.1: 114 commands, puppeteer-core 25.11.0: 149), most behind features a suite never uses (video, tracing, PDF, extensions). Which are required, which are tolerated failing (`_sendMayFail`, `.catch`) and which Chrome behaviours the runner leans on (frame id = page target id, loaderId = the navigation's requestId, when `Page.navigate` answers, `tab` targets for Puppeteer) only show in a real run. And the route matters: Playwright's `SELENIUM_REMOTE_URL` connects over CDP to an existing browser, which sends a different start-up sequence than its default pipe launch, and it is the route a non-Chrome engine can serve without editing the project's config.

**What Happened**: Lane cdp1 (CDP part 1 design) ran htmx 4.0.1 (web-test-runner + Playwright 1.58.2), Svelte 5.57.3 runtime-browser (Vitest + Playwright 1.62.1), Vue 3.5.45 e2e (Vitest + Puppeteer 25.11.0) and e2e-browser (Vitest browser mode + Playwright 1.64.1) against Chrome for Testing 157 on chat2 in about 20 minutes, every suite with its own config. The logs gave 72 commands and 46 events, found Puppeteer's `tab` targets, Vitest's second session on a page (`cdp()` = `Target.attachToBrowserTarget` + `attachToTarget`), the 1,229 `DOM.describeNode`/`resolveNode` round trips that move handles between worlds, and that Playwright runs `setContent` in its utility world - none of it visible as "required" in the sources. Three traps on the way: Playwright's log lines end in ` +0ms` and carry ANSI codes when stderr looks like a terminal (parse with `json.JSONDecoder().raw_decode`); Puppeteer 25 logs through Node's `util.debuglog` (`NODE_DEBUG`), not the `debug` package (`DEBUG`); @playwright/test 1.51.1 hung without output loading an ES module config under Node 24 (a CommonJS config ran).

**Fix**: In a scratch directory on a pool host: pin Node, Chrome for Testing and its chromedriver; start chromedriver on a free port; set `SELENIUM_REMOTE_URL=http://127.0.0.1:<port>` and `SELENIUM_REMOTE_CAPABILITIES` (`goog:chromeOptions` with the Chrome binary and `--headless`); run each suite's own test command with the protocol log on; count commands, events and error responses per run (tmp/plans/cdp1-evidence/analyze.py, sequence.py).

**Takeaway**: **A protocol surface is measured from the clients' real traffic over the route the engine will serve, with the projects unmodified - a runner's source lists what it could send, its log shows what it needs.**
