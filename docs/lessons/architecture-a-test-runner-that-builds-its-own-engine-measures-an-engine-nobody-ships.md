# Architecture: A test runner that builds its own engine measures an engine nobody ships

**Date**: 2026-11-09
**Lesson**: Crane's WPT runner published and timed a hybrid nobody runs - a ReleaseSafe root over Debug Crane modules, a leak-detecting DebugAllocator with poison-on-free, the testing platform's compiled-in decoders and clipboard, a script loader no browser has - so its scores and its timings described that hybrid, not Crane.

**Why**: Each piece was added for a good reason (leak detection for the sweeps, decoders so image tests could run, a loader to hand the page the harness), and each made the runner one step further from the console, Crane's own browser. Nothing compared the two configurations, so the drift was invisible until a timing went wrong. Browsers keep the two apart: wpt.fyi scores their SHIPPING builds; their own CI runs the same tests on debug and sanitizer builds that never feed a score, with per-build expectations (Firefox metadata's `if debug:`, Chromium's `[ Debug ]`).

**What Happened**: Lane wr1 b6 found a page 2.25x slower under the runner than it should be: the DebugAllocator never reuses a freed slot and unmaps an empty bucket, so a per-call allocation alone in its size class paid mmap + faults + munmap - a cost the console, on libc malloc, never pays. Lane wptcfg's audit then found every other difference (testing vs console platform graph, Debug modules, the harness script loader, a runner-supplied media backend, log_performance), and the production adapters turned out to lack image decoding and a clipboard that every browser ships - a gap the testing platform had hidden from every WPT run.

**Fix**: Two builds of one tree (tests/wpt_runner/build_mode.zig `RunnerBuild`): `wpt_runner` IS the release console's configuration - its modes, its allocator, the very graph it links, pinned by tests so they cannot drift - and alone feeds generations, A/B counts and timings; `wpt_runner_bug_finding` adds detection only, on the same platform graph, and any result that differs between the two is a bug listed in tools/wpt_build_differences.txt (which only goes down). WPT's own needs go in the browsers' way: the runner's testharnessreport.js through a `wpt serve` alias, as wptrunner serves its own. Capabilities the production platform lacked were added to the production platform, never to the runner.

**Takeaway**: **Score and time only the build you ship, built from the same graph; put detection in a second build of the same product, and treat every result that differs between the two as a bug - a capability only the test build has is a gap in the product.**
