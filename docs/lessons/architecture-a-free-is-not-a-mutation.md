# Architecture: A free is not a mutation - a version script can observe must not move with the collector

**Date**: 2026-10-15
**Lesson**: The document's DOM tree version moved on every node free (`refcount.nodeFreed`), so a garbage collection of any unrelated detached tree invalidated every XPath iterator over the document, and `iterateNext()` threw InvalidStateError depending on when the collector ran.

**Why**: The version had two jobs. Live collection caches used it as "nothing I remember can have changed", and the bump on free let `Link.getUnchanged` skip the cleanup check on cached entries. XPathResult used it as DOM Level 3 XPath's "the document has been mutated since this result was returned", which is script-observable. Blink (`ContainerNode::ChildrenChanged`, `Element::AttributeChangedWithInvalidations`, `CharacterData::SetDataAndUpdate`) and WebKit (`ContainerNode::childrenChanged`, `Element::notifyAttributeChanged`, `CharacterData::notifyParentAfterChange`) move their version on mutations only, and both move it on every character data change too. Crane's version did not move on character data changes.

**What Happened**: `crane/xp2-result-gc.html` result type 5 failed now and then: `TestUtils.gc()` between `evaluate` and `iterateNext` freed the previous subtest's dropped tree, and its free moved the version. The cache's need was met another way. A node a cache remembers is in the root's subtree. The collection being read keeps its root, so the root's tree is not garbage. A node leaves a tree that is not garbage only by removal, which moves the version first. A document's teardown takes its counts first (Document's `deinitOwn` runs before Node's `deinit`), so its version reads null from then on. The cleanup bit now lives in the slab stamp beside the generation, so `Link.get` costs one word read and `getUnchanged` had nothing left to save.

A second non-mutation moved it too: `nodeDocumentChanged` bumped the new document at a node's FIRST node document, so `document.createElement()` between `evaluate()` and `iterateNext()` invalidated the iterator. It surfaced when the first draft of the tests built its garbage after the evaluation. The draft failed at the fixed tip for that reason. Building a tree is a real mutation, and browsers count it as well (Blink's ChildrenChanged runs for any container). Making a node is not a mutation.

**Fix**: `nodeFreed` no longer moves the version, and neither does a node's first node document (adoption still moves both documents). "Replace data" moves it (`refcount.characterDataChanged`), whether or not the node has a parent, as both engines do. Cached entries and the cursor are read through `Link.get`. Tests: `tests/dom/refcount_tree_version_test.zig` (a free does not move the version; a character data change does), `tests/dom/xpath_api_test.zig` (an iterator survives an unrelated free and is invalidated by a data change), `tests/html/tree_version_collection_test.zig` (both under a real collector, and live collections still read only live nodes across collections).

**Takeaway**: **A counter that script can observe through an API counts only what the spec calls a mutation: not a free, not a creation. Never let the collector move it. If a cache needs to hear about frees, prove from ownership that nothing it remembers can be freed, and check each entry cheaply. Do not borrow the observable counter for that.**
