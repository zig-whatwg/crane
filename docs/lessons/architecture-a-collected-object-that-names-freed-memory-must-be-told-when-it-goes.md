# Architecture: A collected-heap object that names manually freed memory must be told when that memory goes - a conservative scan keeps objects nothing references

**Date**: 2026-11-15
**Status** (2026-11-16, lane wrap2): the lesson stands; its mechanism changed. The first pass of a weak-handle record's Global now gets the wrapper's anchor as its parameter and severs it in every collection (v8_wrapper.cpp `platformAnchorFirstPass`), so the record's "anchor traced" bit and `GCPauses::cpp_weak_processed` are gone. The test this lesson names covers three cases now (a traced record; a weak handle found dead by a full collection; one found dead by a young collection and traced afterwards with its record freed). Why the anchor can be read there: [V8 runs first-pass weak callbacks before the C++ heap's sweep](architecture-v8-runs-first-pass-weak-callbacks-before-the-cpp-heaps-sweep-a-weak-globals-parameter-can-be-the-dead-wrappers-anchor.md).
**Lesson**: "The anchor dies with its wrapper" is not a lifetime rule on a heap that scans the stack conservatively. An object on the C++ heap that holds a raw pointer to memory the host frees by hand (a cache record, a slot) must lose that pointer in the same collection that makes the memory freeable, on every path, or its next Trace reads freed memory.

**Why**: V8's unified heap marks C++-heap objects from the native stack conservatively whenever a collection runs under script (V8 15.7.112.43 `src/heap/cppgc-internal/marker.cc` IteratePointersUntilMarker, `visitor.cc` ConservativeTracingVisitor): a stale word that holds an object's address keeps the object and runs its Trace. Reachability then follows only what Trace traces. Where the object's Trace keeps its partner alive (Blink's ScriptWrappable tracing `wrapper_`; Crane's anchor tracing a record's TracedReference) the pair lives or dies together and nothing is stale. Where it does not - the partner is held by a weak `v8::Global`, which nothing traces - the partner can die while the object lives, and whatever the partner's death frees is still named by the object.

**What Happened**: Lane wrap1 batch 3 moved a non-node wrapper's cache entry into a 32-byte record that the wrapper's C++-heap anchor names. Two kinds of record exist: traced (the anchor's Trace keeps the wrapper) and weak-handle (an Event, a proxy, a wrapper the binding changed: held by a weak Global so that young collections take it). For a weak-handle record's wrapper that died in a full collection, the code said "the anchor died with its wrapper and the sweep takes it: it is not touched". With a stale stack word the anchor survived; the record's finalizer freed the record at the agent's safe point; and the anchor's Trace in the next collection read `record->bits` (and, for a holder, an instance and a generation) from it. While the cache's pool kept every chunk until the realm ended this read pool memory; the same batch's change that gives an empty chunk back to the allocator (c7b00a6704e) turned it into a read and a one-bit write of freed memory. No gate saw it: the tests' collections run with the stack scan off, and a sweep would need the stale word to survive two collections. It was found by asking, for the pool change, "who can still hold a pointer to a record when its chunk is freed?" and listing every holder by kind and by collection.

**Fix**:
1. For every raw pointer from a collected-heap object to host memory, write the table: each way the host memory is freed (young collection, full collection, explicit removal, the owner's end) against "what clears the pointer". An empty cell is a bug. "The object is dead by then" fills a cell only if the object's own Trace keeps what its death is tied to.
2. Close the empty cell in the collection itself. Here: the anchor's Trace marks the record (it runs only if the anchor is kept); the caches' weak processing, in the same atomic pause, keeps that as the record's `anchor_traced` bit; the weak Global's first pass, which runs after the pause, severs an anchor that was traced (`dropDeadWrapperAnchor`). An anchor that was not traced is dead and must not be touched - it may be swept already.
3. Test it with the real mechanism, not a stand-in: keep the object's address in a local of the test's frame and collect with the stack scanned (`v8_test_Isolate_CollectScanningStack`), then read what the object names through a weak look (`v8_test_PlatformAnchorWatch_*`). A strong root would also keep the object but is wrong for the paths that free it explicitly.
4. When a change makes memory go back to the allocator sooner (a pool that gives chunks back, an entry freed earlier), re-run step 1 for that memory before the gates: the change is safe only if every holder was already told.

**Takeaway**: **On a conservatively scanned heap, an object can outlive everything that points at it. Give every raw pointer it holds an owner that clears it when the target is freed, and prove it with a test that keeps the object by a stack word.**
