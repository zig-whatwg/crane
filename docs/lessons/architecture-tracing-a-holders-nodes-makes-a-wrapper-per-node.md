# Architecture: Tracing a holder's nodes makes a wrapper for every node it holds

**Date**: 2026-10-09
**Lesson**: Keeping a static NodeList's or a MutationRecord's nodes alive by traced edges (engine.traceChild / traceValue) wraps every node at the moment the holder is filled - and, by the wrappers' upward closure, its ancestors - which is the cost Blink's `Member<Node>` does not have. On the hot holders that is several times the operation itself.

**Why**: Crane's only native-to-collector bridge is a wrapper: an edge goes from the owner's wrapper to the child's, so traceChild makes the child's wrapper if script has not seen it, and createSequenceOfPlatformObjects wraps each value. A node in a tree that gets a wrapper also draws tree edges (a private parent ref, an entry in its parent's children Set) and wraps its unwrapped ancestors. Blink traces a native Member and makes wrappers only on access; WebKit holds a Ref. querySelectorAll results and parse-time mutation records are mostly nodes no script has touched.

**What Happened**: Lane edges fixed the PR-N1 holders that kept bare node pointers. A record traced its target, siblings and lists, and a static list traced one Array of its nodes' wrappers. Correct - the use-after-free reds (crane/ed-mutation-record-nodes-gc.html, ed-static-nodelist-gc.html) went green and dropped holders released their nodes. But in 7 paired rounds against base: `querySelectorAll('*').length` over 10,000 parsed elements went 131.5 -> 1,114.7 ms (8.7x); iterating every node 3,158 -> 3,577 ms (1.15x - base pays ~31 us/node to wrap on access anyway); ps-parser-page under a subtree MutationObserver 1,148 -> 2,904 ms (2.55x). The integrator's bars were 1.5x and 1.03x, so neither holder was committed (patch: tmp/plans/edges-held/). The same run showed the parse delivering the observer callback once per record on tip (none before the last script on base): native engine calls made while no script runs are not free of microtask checkpoints either.

**Fix**: Not this. For a holder of many nodes, hold them natively and make the tree teardown honour the hold: a node is safe while its tree's root is the Document or a rooted wrapper, so only a removal that detaches a held subtree needs a wrapper - pholds' "rescue" (tmp/plans/parser-holds-design.md), generalized. Traced edges stay right for holders of one or two nodes on cold paths (StaticRange's containers, an SVG script task's element).

**Takeaway**: **Before choosing traced edges for a holder, count the wrappers its hottest fill path makes: an edge per held node is a wrapper per held node, so a holder of many nodes needs a native hold the teardown respects, not a trace.**
