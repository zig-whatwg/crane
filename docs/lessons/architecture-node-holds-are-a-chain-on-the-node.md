# Architecture: Holds on nodes are a chain on the node - a removal asks exactly the holders that hold something in it

**Date**: 2026-10-09
**Lesson**: A holder of many nodes (a static NodeList, a MutationRecord) holds them natively with a record linked into each node's own chain of holds (`NodeBase.holds`, src/dom/node_holds.zig), and rescues - roots from its own wrapper - only the root of a tree holding one of its nodes that is not a document with a window. The chain head is both the per-node mark (a removal that touches nothing held pays one field test per node it already visits) and the answer to "who holds this", which a bit cannot give.

**Why**: Blink keeps a StaticNodeList's and a MutationRecord's nodes with traced `Member<Node>`s and wraps nothing until script asks. Crane's only native-to-collector bridge is a wrapper, and tracing each node from the holder wrapped every node at fill time (lane edges: 8.7x on querySelectorAll('*').length, 2.55x on an observed parse). pholds showed the alternative for the parser - hold natively, rescue the root of a tree that leaves the document - but asked each parser on every removal whether the removed root contains a node it holds: O(holders x held nodes), fine for a few parsers, quadratic for thousands of uncollected querySelectorAll lists or queued records (`qSA('.x').forEach(e => e.remove())`).

**What Happened**: Lane nodeholds generalized pholds. A `Hold` (node, generation, NodeBase, holder, prev, next) is embedded in its holder and linked into the node's chain in O(1). The one removing-steps callback tests `node.holds` for every node a removal visits (remove step 11 for the root, step 14 for each shadow-including descendant); when set, every holder in the chain rescues the removal root (deduplicated, amortized pruning of rescues a holder's nodes have left). At hold time a node whose root is not a kept document (a detached tree, a script-made document, a shadow tree whose host left, template contents) is rescued at once. An unwrapped holder (a record still queued) gets traceChild's documented deferral: the edge waits strongly in the wrapper cache until the holder is wrapped, and its teardown lets it go. A record holds all its nodes itself and makes its NodeLists on first read, so a queued record makes no list and wraps nothing; the parser, whose stack changes on every push and pop, stays a "scanning" holder asked on the removal root only. Results: ed-mutation-record-nodes-gc 1/6 -> 6/6, ed-static-nodelist-gc 1/4 -> 4/4; an observed parse 0.71x of base (the two carrier NodeLists per mutation are gone); querySelectorAll('*') walked over NodeBase links to stay under its bar.

**Fix**: For a new holder of nodes: embed a `node_holds.Holder` (owner = the instance whose wrapper the rescues hang on), `hold` its nodes (pass the tree nodes or a root hint when you have them, to spare the lookups), read through `Holder.get`, and `release` in its teardown. Never keep a bare node pointer in a script-reachable object.

**Takeaway**: **Mark a held node with the head of its holders' chain, not a bit: a removal of nothing held stays a field test, and a removal of something held asks exactly its holders - pay one wrapper for the detached root, never one per node.**
