# Workflow: Zig 0.17's self-hosted Debug backend is not reproducible - prove a Debug artifact by its gates

**Date**: 2026-11-16
**Lesson**: On x86-64 Linux two builds of one tree, each from a fresh cache, give Debug executables (crane) and Debug objects (libwhatwg_full.a's Zig object) that differ in their code - .text, symbol addresses - so no byte or section comparison can prove such an artifact unchanged; its compile commands and its gates do.

**Why**: The build migration's proof standard (tmp/plans/build-protocol-design.md 5.1a) recorded an open item from batch 0: "crane and libwhatwg_full.a differ between two cold Linux builds" - unattributed, so both were held "by their gates". Crane's Debug x86-64 artifacts are compiled by Zig's self-hosted backend and linked by its own ELF linker (-fno-lld); the release runners go through LLVM and LLD. A difference in a Debug artifact therefore says nothing about a commit unless the same tree, built twice, is identical - and it is not.

**What Happened**: Lane build5 (batch E5) compared, with tools/section_diff.zig, two builds of crane at its tip, each `zig build crane` in a fresh `--cache-dir` on server1 (30 s each): the program headers, .text (1,707,335 of 151,034,132 bytes) and 81,661 of 489,126 symbols differed - function addresses - besides every .debug_* section. The commit under proof (37117fe001c, a value moved between options modules) showed the same kind of difference in crane (.text 6,984,301 bytes, 69,661 symbols) and in libwhatwg_full.a's Zig object (lib_exports.o: .text, .data.rel.ro, 80,477 symbols), while every ReleaseSafe executable of the same build - both WPT runners, repl, the release console, gc_bench - was the SAME PROGRAM (only debug sections differed) and the same commit on macOS left crane's code untouched (2 anonymous constants renamed). The batch-0 measurement fits: base (cold) and its rebuild in one mirror had two different crane hashes.

**Fix**: For a Debug artifact on Linux, do not compare bytes or sections across builds: (1) compare its compile command before and after (`zig build --verbose`, cache digests masked) - identical commands but for the declared inputs is the proof that the build asked for the same thing; (2) run its gates (crane: `crane-check`, check-linux; the library: what links it). A section comparison of the release artifacts of the same build carries the rest. To check whether a Debug difference is the commit's, build the SAME tree twice in two fresh caches and compare those first.

**Takeaway**: **Two Debug builds of one tree differ in code on x86-64 Linux: prove a Debug artifact by its compile command and its gates, and take a byte difference in it as noise until the same tree, built twice, says otherwise.**
