# Architecture: An argument must survive every later argument's conversion

**Date**: 2026-10-16
**Lesson**: Arguments convert in order and any conversion can run script, so what an earlier argument converted to must stay valid until the operation runs; a slice into the engine's memory taken at conversion does not.

**Why**: WebIDL converts an operation's arguments one after another, and converting a dictionary, a sequence, a string or a number calls Get, @@iterator, toString or valueOf - user script. That script can detach the buffer an earlier argument refers to (`buffer.transfer(0)`), which frees its backing store. A conversion that hands the operation a `[]const u8` over that store is correct on its own and wrong as soon as a later argument converts.

**What Happened**: `convertAllowSharedBufferSource` returned `.byte_slice` over the backing store, read when the input converted. `TextDecoder.decode(input, options)` then converted `options`, whose `stream` getter transferred the input's buffer, and decode() read the freed store: 10,000 bytes of whatever the allocator had put there since (a test that filled a new 10,000-byte buffer with 'Z' in the getter decoded 10,000 'Z'). encoding/textdecoder-arguments.any.js showed FAIL, not CRASH: nothing unmapped the freed block. BufferSource had been made a reference for WebCrypto's sake a fortnight earlier; AllowSharedBufferSource, which only TextDecoder read, kept the slice.

**Fix**: `convertAllowSharedBufferSource` makes a reference, as `convertBufferSource` does: an ArrayBuffer or SharedArrayBuffer struct whose `js` is the object, or a view whose `js` is the view - the argument's own handle, kept in the value (`bufferHandleIsKeptInValue`) and released by `freeConvertedArg` once the call returns, whether the value is an argument, a dictionary member or a sequence element. The impl copies at its spec's step: decode() step 3 "push a copy of input" is `engine.getCopyOfAllowSharedBufferSourceBytes`, which reads a detached buffer as empty. `asBytes()` on a value converted from script is `error.BytesHeldByEngine`, so no impl can read a slice that might be stale. tests/v8/allow_shared_buffer_detach_test.zig is the red through the binding; allow_shared_buffer_source_test.zig pins the reference, a dictionary member detached by a later member's getter, and the stale address the old slice would have kept.

**Takeaway**: **What an argument converts to must outlive every conversion after it - each can run script. Hold a reference to the object and read it at the algorithm's step; never hand the operation a view of engine memory taken while converting.**
