# Architecture: A stream source that calls script keeps itself alive across the call

**Date**: 2026-11-02
**Lesson**: When a stream's underlying source calls into script, the script can cancel that same stream, and cancelling clears the controller's algorithms, which frees the source. So the source must keep itself alive until the call returns.

**Why**: Crane frees a source when the controller drops it: `ReadableStreamDefaultControllerClearAlgorithms` calls the source's `deinit` right away. In the spec, an algorithm is a closure, and clearing it only drops the controller's reference to it. A step that is already running keeps what it closed over, and runs to its end. Gecko does the same with reference counts: `ReadableStreamDefaultControllerCallPullIfNeeded` and `CancelSteps` each take a `RefPtr<UnderlyingSourceAlgorithmsBase>` to the controller's algorithms before calling them (dom/streams/ReadableStreamDefaultController.cpp). Blink's algorithms are garbage-collected objects that its GC traces.

**What Happened**: `ReadableStream.from(iterable)`'s pull algorithm calls `IteratorNext`, which runs the iterator's `next()`. In from.any.js "reader.cancel() inside next()", `next()` calls `reader.cancel()` synchronously. The cancel steps call the iterator's `return()`, then clear the algorithms. That freed `FromSource` and its Iterator Record while `next()` was still on the stack. When `next()` returned, `iteratorNextValue` read `record.kind`, and the pull then read the source's realm for its reaction. Both are use-after-free reads, on every run. The ReleaseSafe runner does not fill freed memory, so the stale bytes usually still held the old values and the file passed. It crashed only when the record had been the last live slot of its DebugAllocator bucket page, which is then unmapped. A sweep showed EXC_BAD_ACCESS at 0x16d460021: `record.kind` at offset 0x21 of a page-aligned record. The address looked like a stack address, and it misled the first reading (see "A fault a few bytes past a page boundary is a freed bucket"). A Debug unit test whose realm allocates through the testing allocator crashes every time, because Debug overwrites freed memory: all 5 cases crashed, one with "upcast of misaligned address 0x5555555555555555" when the async-from-sync continuation read the freed record's `iterator`.

**Fix**: `FromSource` became reference-counted (`refs`, `retain`, `release`, the PipeState shape). The controller holds one reference, which `deinitSource` drops. `pull` and `cancelSource` each take one of their own before calling the iterator and drop it with a `defer`. Each of them also copies the controller's allocator and the source's realm into locals before the call. Test: tests/v8/crashes6_from_source_reentry_test.zig. It covers an async iterator, a sync iterator through the async-from-sync continuation, a getter on the result object, a throw after the cancel, and a cancel from inside `return()`. Every realm in it allocates through the testing allocator.

**Takeaway**: **Hold a source across each call it makes into script; the script can clear the algorithms that hold it. Clearing an algorithm drops a reference; it does not end a step that is still running.**
