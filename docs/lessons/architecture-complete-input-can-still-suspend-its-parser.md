# Architecture: Complete input can still suspend its parser

**Date**: 2026-10-08
**Lesson**: Receiving every response byte does not finish parsing. A navigation parser and its loader must survive stylesheet waits until actual EOF or cancellation.

**Why**: Parser input completeness and parser execution readiness are independent. The tokenizer can pause at a script end tag while a stylesheet fetch still blocks that script, even when the whole response has arrived.

**What happened**: Real script-blocking stylesheet fetches exposed a stack-only complete-input parser. It returned at a blocked classic script, destroyed its tokenizer/tree/adapter, and eagerly ran "the end". The stylesheet later finished, but the document no longer had a continuation. The focused `dw-navigation-stylesheet-blocker` RED reported three failures, events `[DOMContentLoaded, sheet-inline]`, missing remaining markup, and readiness `complete`. Six upstream execution-timing files changed from an ordinary styling assertion failure to a timeout with no subtests.

**Fix**: Generalize the existing document-owned written parser for navigation, iframe src and srcdoc, and popup input. Keep the script-created flag separate from ownership: navigation starts with complete input and an undefined insertion point; close only supplies EOF to script-created input. Document owns one parser reference, and every pump retains another through callbacks and insertion-limit restoration. Only consumed EOF detaches the association and runs the guarded readiness/deferred-script/loading steps. Open, stop, removal, and destruction cancel without old completion events. Check realm liveness, document generation, parser association, and parser epoch before delayed pumps and after executed blocking scripts.

A loader descriptor is borrowed during initiation. Mandatory retain/release callbacks produce one owning acquired loader stored in the parser; its release runs once after EOF or cancellation unwinds. The WPT run's loader context is heap refcounted and saves its relevant realm. Harness completion can release the run's reference before parser EOF; it cannot invalidate the parser's reference. Release never calls script or testdriver. No engine-owned document root belongs in that context, because document → parser → loader → document would make the cycle permanently reachable.

The parser also owns its base URL and original response bytes and embeds its decoding state. A meta encoding change after a stylesheet wait must not read a caller's expired body or decoder stack. Parent-encoding and Content-Type slices are consumed during initial sniffing, rather than retained.

**Design precedent**: The existing written-parser design follows WebKit [HTMLDocumentParser::insert, finish, and shouldDelayEnd](https://github.com/WebKit/WebKit/blob/main/Source/WebCore/html/parser/HTMLDocumentParser.cpp) and Blink [HTMLTreeBuilder::Trace and Detach](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/html/parser/html_tree_builder.cc). The same lifetime applies to complete input. HTML's [script end-tag wait](https://html.spec.whatwg.org/multipage/parsing.html#scriptEndTag) and [the end](https://html.spec.whatwg.org/multipage/parsing.html#the-end) are separate stages.

**Takeaway**: **Preserve the owned parser across every wait; loader, original bytes, decoding state, and EOF belong to that same lifetime.** A nested event-loop spin is not a substitute: Crane's loop rejects reentrant pumping and has no suspended JavaScript-task operation.

**Validation**: Root's focused native run passed 736/736 tests. The three-test top-level RED became 3/3 GREEN at about two seconds, and all six upstream timing files returned to OK with their known CSS assertion failure instead of timing out with no subtests. The six child lifecycle probes passed, including HTTP/srcdoc EOF, late raw-byte encoding switch, open, stop, and removal, with no crashes or ownership violations. Their sequential waits take about 13.7 seconds, so the fixture declares the standard long timeout; the original ten-second budget timed out after four passes. Existing written-parser controls were unchanged. Full native/build/browser checks, timers x3, and matching memory comparisons remain pending with the integrator; focused GREEN alone does not establish those gates.
