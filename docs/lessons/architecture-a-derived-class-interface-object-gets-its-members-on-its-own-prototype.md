# Architecture: A derived-class interface object gets its prototype members defined on its own prototype object

**Date**: 2026-11-21
**Status**: 2026-11-21 - not used in the V8 adapter: the user ruled "I want to make this the responsibility of the js engine protocol" - the adapter owns the receiver and steps 10-11, and the V8 adapter keeps Chrome's FunctionTemplates and order (prototype read before the definition checks). The design stays the way for an adapter whose API hands a constructor no new.target (JavaScriptCore's C API); its code is lane/blk7 history 95d5ec936..b425276bc, its account tmp/plans/lane-blk7-handoff.md ("for the JSC/other adapters").
**Lesson**: To give an interface a [[Construct]] that makes no receiver (HTML's [HTMLConstructor] reads NewTarget.prototype only at step 10), make its interface object a derived class from a V8 extension, define the interface's prototype members straight on the class's own prototype object, and point the template function's `prototype` at it - a class's `prototype` can never be given an existing object, and copying a template-made one costs every realm a copy and an orphan.

**Why**: V8 makes an API function's receiver before its callback (builtins-api.cc HandleApiCallHelper<true> -> ApiNatives::InstantiateObject -> JSFunction::GetDerivedMap, a [[Get]] of a Proxy NewTarget's "prototype"), and no public API skips it - Chrome fails custom-elements/HTMLElement-constructor-customized-builtins.html for that reason. Only a derived class's [[Construct]] makes no receiver (ECMAScript 10.2.2 step 3). But ClassDefinitionEvaluation defines the class's `prototype` as a fresh object, non-writable and non-configurable: no Set, DefineOwnProperty or API call can replace it with the template's prototype object, which every wrapper the instance template makes inherits from.

**What Happened**: Lane blk6's design note for this (option (b)) said the class's `prototype` would be "the FunctionTemplate's prototype object". That is impossible as written; lane blk7 found it before writing code.

**Fix**:
1. The class comes from a v8::Extension (registered once at the platform start; ExtensionConfiguration on every Window context path; V8 never installs extensions into the snapshot). Extension functions are not user JavaScript (Script::Type::kExtension), so Function.prototype.toString prints "function HTMLElement() { [native code] }" and stack traces hide their frames, as for an API function. One class literal per interface, so each has its own SharedFunctionInfo and name; a `native function` declared inside an IIFE hands the context its factory without a global.
2. The template for such an interface skips ReadOnlyPrototype, so the template function's `prototype` stays writable until the swap.
3. The first version COPIED the template-made prototype object onto the class's (C++, each descriptor field read as an own property so script's %Object.prototype% cannot interfere). The cost window rejected it: every realm paid each property's descriptor and definition, and the template-made object stayed as garbage until a major collection (realm.iframe-elements +50% time, +3.7M instructions per realm; load.news +2.2 MB). So createTemplate keeps an [HTMLConstructor] interface's prototype members (accessors, constants, operations - the same FunctionTemplates and attributes) in a per-isolate list instead of on the PrototypeTemplate, and the realm defines them on the class's prototype object in the template's order; only what the realm adds to the template function's prototype object (`constructor`, @@toStringTag, an iterator, @@unscopables) is copied after them. A context without the extension gets the members on the template function's own prototype object. Note what stays: an object's accessor property takes functions, so the members' functions are made when the interface object is built, where a template-made object would make them when script first reads them.
4. Every wrapper is made after its realm builds the interface object (template_registry.ensureInterfaceObjectBuilt), and an interface under an [HTMLConstructor] one builds its parent first, so V8's Inherit links a child's prototype object to Q, never to the old P.
5. Pin the shapes first (tests/v8/html_constructor_shape_test.zig: toString, name, length, own keys with kinds and attributes per interface, both chains, element prototypes, snapshot-restored and fresh realms).

**Takeaway**: **A class's `prototype` is fixed at creation: when a class must stand in for a template's function, define the members on the class's prototype object and re-point the template to it - never try to re-point the class, and never copy a template-made object per realm.**
