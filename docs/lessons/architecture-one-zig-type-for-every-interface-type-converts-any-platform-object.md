# Architecture: One Zig type for every interface type converts any platform object

**Date**: 2026-10-17
**Lesson**: Every WebIDL interface type is `*runtime.Instance` in Zig, so the conversion of an interface-typed argument, attribute value, dictionary member or sequence element could not say WHICH interface the value had to implement - and accepted any platform object. The impl then read one interface's state as another's.

**Why**: WebIDL 3.2.15 converts V to an interface type I by "1. If V implements I, then return ... 2. Throw a TypeError." A conversion keyed on the Zig type alone can only do step 1 for "some interface". The receiver was brand-checked (it knows its interface: the template's), and a union's arms were checked by their names, but a plain interface-typed position had nothing to check against. Overload resolution did ask the type - but only at the distinguishing index, and only when two or more overloads have the argument count, so an overload chosen by count alone (FormData's three-argument `append`) was never checked at all.

**What Happened**: `fd.append('name', new URLSearchParams(), 'filename')` must throw a TypeError (xhr/formdata/append-formelement.html, set-formelement.html). Crane handed the URLSearchParams to FormData as its Blob; `FormData.entryFile` read URLSearchParams' state as a Blob's, and long single-process runs segfaulted intermittently in `normalizeMimeType` at 0x0. The same hole let `div.appendChild(blob)`, `new StaticRange({startContainer: blob, ...})`, `new MouseEvent('x', {relatedTarget: blob})`, `new MessageEvent('m', {ports: [blob]})` and `walker.currentNode = blob` through - 9 of 11 subtests of crane/bindtype-wrong-interface.html failed on main.

**Fix**: Codegen names the interface of every interface-typed position, beside `byte_string_arguments` and `byte_string_members`: `interface_arguments` (function, argument index - 0 for a setter's value -, interface), `constructor_interface_arguments` (ConstructorArgs variant, index, interface) and `interface_members` (member, interface). The name goes through typedefs (WindowProxy is Window) and through nullable, sequence, FrozenArray and record types to the elements' interface; a union is not listed (its arms carry their names). The binding converts a `*runtime.Instance` position only through `conv.fromV8ValueAs(T, I, ...)`, which asks `instance.stateAs(I.State)`; converting one with no interface is a **compile error**, so a position codegen does not cover cannot convert silently. "The platform object V is" - for a union's arm dispatch, BodyInit, structured serialization and the protocol's `convertToPlatformObject` - is a separate function, `conv.platformObjectOf`, which says nothing about the interface. An instance whose vtable has no ancestry now implements nothing (every generated vtable has one; only test mocks lacked it). tests/v8/interface_type_conversion_test.zig, tests/v8/interface_type_tables_test.zig (every generated position covered), tests/codegen/interface_arguments_test.zig, crane/bindtype-wrong-interface.html. Blink does the same per position (NativeValueTraits<IDLInterface>: V8PerIsolateData::HasInstance(T's WrapperTypeInfo, value)); WebKit's converter asks JST::toWrapped and throws on null.

**Takeaway**: **When one Zig type stands for many IDL types, the conversion cannot check what the type does not say: have codegen name the IDL type at each position, and make an unnamed position a compile error, never an unchecked default.**
