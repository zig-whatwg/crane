# Architecture: A release rule read off the converter belongs to every caller of the converter

**Date**: 2026-10-17
**Lesson**: `setterValueLeavesHandle` knew that a nullable value which converted to null made nothing from its handle, but only the attribute setter asked it. Arguments, dictionary members and sequence elements kept the handle of every null or absent optional. And the dictionary rule's member allowlist had no case for a callback function, so every dictionary with one kept its argument's handle.

**Why**: The ownership rules live in predicates written beside the first caller that needed them. A value-level rule is a fact about the CONVERTER: `conv.fromV8ValueAs`'s optional branch answers null for null and undefined (and an optional callback for a non-function) before it converts anything, so a null optional refers to nothing, at whichever call site asked for the conversion. Written as a setter rule, the argument path, the dictionary member loop and the sequence loop never asked it. The dictionary rule was the same shape: `argHandleIsCopied(dictionary)` held every member to an allowlist of member types "that cannot alias the dictionary's handle", and no member can, since each is read through a Get of its own. An unlisted member kind keeps the whole dictionary's handle. The sequence member was the first unlisted kind found (workers2), and the callback function was the second.

**What Happened**: `new WritableStream({}, {highWaterMark: 0})` kept two 16-byte Globals per call (lane snapleak saw them in leaks --atExit over fetch/api/). The first was the strategy's own handle: QueuingStrategy's `size` is `?callbacks.QueuingStrategySize`, a function pointer. The second was the Get handle of the absent `size`, which converts to null. ReadableStream's and TransformStream's strategies took the same path, as did `addEventListener(type, null)` (a `??*CallbackWrapper` given null). Over a Crane test making each of them 200 times in a window and in a dedicated worker, an in-process main runner reported 5,613 leaks, every stack proportional to N, in both realms. The report had placed the leak in worker realms only, but the realm was not the cause: the argument's shape was.

**Fix**:
1. `memberHandleIsSafe` accepts a callback function member (`isCallbackFunctionType`). It adopts the handle Get made for it, never the dictionary's. Blink does the same: it reads the dictionary as Locals, and a callback member keeps a reference of its own (callback_function_base.h).
2. `conversionLeavesHandle(T, value)` is the setter's rule, generalised by the converter's branches: a copied type never answers; an `any`, `object` arm or buffer source decides by its value; a null optional leaves the handle; an Opt not passed leaves it; otherwise the payload decides; the default is kept. `convertArgReleasingWith`, the dictionary member loop's general branch and `releaseElementHandle` ask it, and `setterValueLeavesHandle` delegates to it.
3. Pinned by tests/v8/dictionary_callback_member_handle_test.zig: the predicates and their defaults, plus V8's live handle count over 64 calls of each shape against a control.

**Takeaway**: **A release rule proven from the converter's branches belongs to the converter: give every site that converts the same way the one predicate, not just the site that first needed it.**
