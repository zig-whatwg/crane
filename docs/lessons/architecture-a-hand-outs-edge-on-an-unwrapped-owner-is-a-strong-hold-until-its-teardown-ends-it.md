# Architecture: A hand-out's edge on an unwrapped owner is a strong hold until the owner's teardown ends it

**Date**: 2026-11-22
**Lesson**: `engine.traceChild(owner, child)` on an owner script never wrapped cannot hang an edge on a wrapper, so the V8 adapter wraps the child and holds that wrapper STRONGLY until the owner gets one. Every owner that hands a child out must end that hold in its own deinit (`engine.forgetTracedChild`), whatever made the hand-out - and native code should not make hand-outs it does not need.

**Why**: The generated [SameObject] caches end their waits in the destruction chain (`dom.same_object_cache.end`), and HTMLElement ended its ElementInternals' (`internals_traced`). The two children an element keeps by hand in its rare data - element.style's CSSStyleProperties and its shadow root (`node_rare_data.keptHandOut`) - assumed the owner was wrapped ("the edge goes with the owner's wrapper") and never forgot theirs. `runtime.gc.releaseOwned` then ran the child's destructor and left its storage to a wrapper that could never be collected. The realm's end freed it all, so no leak checker saw anything.

**What Happened**: Lane tpc measured edit4's delete-join row growing ~1 KB per operation with A04 (typing style recorded across a merge), linearly past the undo history's 1,000-step bound, and `--check-leaks` clean. gc_bench's `--live-types` census after collections and an idle loop named it: nodes identical with and without A04 (the history's 7,000), CSSStyleProperties 2,003 without A04 at every K, 4,003 with it after 2x1,000 joins and 11,003 after 2x8,000, with 5,003 HTML elements alive. A04's record (`overrides.recordAt -> specifyingDepth -> style_values.declarationOf -> HTMLElement.get_style`) read element.style on elements no script had touched; each read wrapped a style object and parked it in `wrapper_cache.edges_before_wrap`. Only that table's amortized prune (a doubling watermark) or the slab reissuing a dead owner's address dropped the entries - so a task's first K operations kept K, and later tasks only ~1,000 more.

**Fix**:
1. `node_rare_data.keptEndHandOut(holder, kept, owner)` - `engine.forgetTracedChild` when the kept child's traced flag is set, safe in any teardown, the collector's included - called from HTMLElement's and Element's `deinitOwn`, never from the Browser's exit sweep (the engine is gone there); `keptSlot(kept)` names the member once for the hand-out and its end.
2. Editing reads the style attribute natively (`style_values.inlineBlockOf` / `inlineItem` / `inlineCssText`, from `dom.style.inline_style.blockOf`), as Blink's editing reads `Element::InlineStyle()`: a read makes no CSSOM object and no wrapper at all. Writes still go through CSSOM's setProperty.
3. Tests: tests/html/mem1_kept_edge_teardown_test.zig - a native element.style read on an unwrapped element is freed with it (red 0/10 before), a delete-join loop past the undo bound keeps no style object past its element, editing's reads make none.

**Takeaway**: **An edge drawn for an owner with no wrapper is a root, not an edge: every hand-out needs its owner's teardown to end it, and a census of live objects BY INTERFACE after collections - not a leak report - is what finds the ones that do not.**
