# Architecture: V8's thread isolation key reaches only threads made after it

**Date**: 2026-11-08
**Lesson**: On x86-64 Linux with memory protection keys, V8 tags trusted memory with a key that only the thread that allocated it, and threads created later, may read - so the platform that allocates it must be made first in `main`, before any thread, and a platform made later must give V8 no thread-isolated allocator.

**Why**: libplatform's DefaultThreadIsolatedAllocator calls `pkey_alloc(0, PKEY_DISABLE_WRITE)` inside `NewDefaultPlatform` (V8 13.1.203 src/libplatform/default-thread-isolated-allocator.cc). V8's ThreadIsolation (src/common/code-memory-access.cc) then write-protects the JSDispatchTable and other trusted memory with that key. A new thread inherits its creator's PKRU; a thread that already existed keeps Linux's initial PKRU, which denies all access to keys 1-15, and faults on its first read. Apple silicon has no PKU, so macOS never shows it.

**What Happened**: On server1, the first x86-64 Linux host (2026-11-07), every "two Browsers on two threads" test and tests/v8's platform_start_once crashed - 33 tests, SEGV in `JSDispatchTable::PreAllocatedEntryNeedsInitialization` - because the first Browser's thread started V8 lazily while the other already ran. `--no-memory-protection-keys` made them pass, but turns off a hardening Chrome keeps. Chromium's content main calls `gin::GetThreadIsolationData().InitializeBeforeThreadCreation()` before it starts any thread, and gin's `V8Platform::GetThreadIsolatedAllocator` returns nullptr until that ran; Node's NodePlatform never overrides it, so V8 runs there without thread isolation.

**Fix**: The engine protocol's `initializeBeforeThreadCreation()` (lane linux1): the V8 adapter makes its platform - and so the key - on the calling thread, and V8 starts later on any thread. `CranePlatform::GetThreadIsolatedAllocator` returns the backend's allocator only for a platform made that way, nullptr otherwise (no key, no fault). Every process entry that starts V8 calls it first: crane, repl, wpt_runner, gc_bench, the snapshot generator and the Crane test runner's `main`. The fallback keeps a test of its own: build.zig runs tests/v8's platform start tests a second time with CRANE_TEST_ENGINE_EARLY=0, which makes the runner skip the call - V8 then starts on one of eight threads that all existed before it.

**Takeaway**: **Per-process state that threads inherit at creation belongs to the first lines of `main`, before any thread exists - and the fallback when a process skips it must be the safe one (no key), never a key some threads cannot read.** A crash that appears only on one CPU family is worth checking against PKU, MTE and CET before blaming the code under test.
