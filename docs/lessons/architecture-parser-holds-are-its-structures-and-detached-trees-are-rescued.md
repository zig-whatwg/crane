# Architecture: A parser's holds are its own structures, and a detached tree is rescued through its root

**Status** (2026-10-09, lane nodeholds): generalized to any holder in src/dom/node_holds.zig ([Holds on nodes are a chain on the node](architecture-node-holds-are-a-chain-on-the-node.md)). The parser is now a "scanning" holder of that facility: `ParserRegistry` became `node_holds.Registry`, the removing-steps hook and the tree walks moved there (hostOfRoot now knows shadow roots too), and the kept-roots container uses `node_holds.putRoot` / `clearRoot`. The parser's holds and rescues are unchanged.

**Date**: 2026-10-08
**Lesson**: The live HTML parser holds natively exactly the nodes its structures name - the stack of open elements, the head and form element pointers, and an element wrapped at its creation until its first insertion attempt - and makes no wrapper per node. When script (or a failed insertion) detaches a tree containing a held node, the parser roots that tree's ROOT, one wrapper, from a fixed collectible Document member until it is released.

**Why**: Row 10's persistent parser wrapped every node it created, traced it from the Document, and retained it twice more per insertion. Tree edges then made every one of those wrappers permanent: a wrapper, a cache entry, a private parent edge and a Set entry per parsed node for the document's whole life, marked by every major GC. A live parse of 2,500 sections went from 335.9 to 594.0 ms and page load by about 65%. Blink and WebKit hold the parser's nodes natively: `HTMLConstructionSite::Trace` visits `open_elements_`, `head_` and `form_`; WebKit's `HTMLElementStack` records own their nodes with a RefPtr. Neither wraps anything.

**What Happened**: Crane has no tracing of native objects, so the design (tmp/plans/parser-holds-design.md) rests on two facts of its collector, pinned in tests/v8/parser_holds_invariants_test.zig: the collector frees a node only as a parentless root or inside one (`treeOwns`), and wrappers in a tree are upward-closed and linked both ways. So a held node is safe while its tree's root is the parser's Document or a node whose wrapper the parser rooted. The only ways a held node leaves its Document's tree are a removal and a failed insertion. `html.parser_holds` registers one DOM removing-steps callback at process start; it acts on the removal root only, asks each live parser of the Browser (a `ParserRegistry` supplement of the BrowserScope) whether that root is a host-including inclusive ancestor of a held node - an O(stack depth) walk, because the stack is normally a parent chain - and a parser that says yes rescues the root into `document-parser:kept-roots`. Template contents are reached through their host, so removing a template on the stack rescues the template.

A discarded parser (document.open, abort) keeps its stack, pointers, pending holds and rescues until it is RELEASED, not until it is detached: abort step 4 pops an old parser's stack after a readiness listener replaced it, and Blink's `HTMLConstructionSite::Detach` keeps the stack "because HTMLConstructionSite might be on the callstack". An attempt to drop the hold set at detach needed a special case for exactly that, which is the sign it was wrong.

**Fix**:
1. `DocumentParser.nodeCreated` creates the DOM node and nothing else; `protect()` roots only the Document; the per-parser bag, its epoch guard and the adapter's per-node `holds` are gone.
2. The removing-steps callback rescues a detached tree's root; a failed element insertion rescues the root of the tree the element is left in, unless that is the Document.
3. `parser_dom_mutation.insert` holds the moved node and target parent only for a real move (a node with a live parent), not for every fresh insertion.
4. A synchronously constructed custom element is held from its creation, before its attribute reactions run, to its first insertion attempt.
5. Rescue reserves its container index from the registry before any engine allocation, so a reentrant rescue cannot take it, and `release()` clears this parser's slots only while the Document and its realm are usable.

**Measured** (7 alternating paired rounds, target 9717346413 / base 0ad1972542 / lane tip 8864c97b18, medians): live parse of 2,500 sections 544 / 1,053 / 517 ms; page load 695 / 1,231 / 680 ms; DOMParser 309 / 346 / 319 ms; removal-heavy parse (12,505 removals) 4,473 / 4,636 / 4,442 ms; summed heap over 31 heavy files 492,032 / 501,387 / 491,418 KB. Holds and rescue alone took the live parse from 994 to 577 ms; the rest was the adapter's side tables (a `generations` hash map and a `node_map` per node - now fields on the TreeNode, generation-checked), found by profiling rather than guessed.

**Takeaway**: **Hold what your own structures name, natively, and pay for a wrapper only at the moment a held node leaves the tree its owner keeps - one wrapper for the detached root, never one per node; and let holds end when the holder is released, not when it is detached.**
