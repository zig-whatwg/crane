# Architecture: An instance of a template with own properties is never "unmodified" - V8 will not drop its wrapper in a young collection, for any embedder

**Date**: 2026-11-14
**Status** (2026-11-14, the same batch): the make-and-drop rows came back over the bar for these shapes (650,000 dropped Events ended at 198 MB against main's 88 MB), and the integrator ruled that a wrapper V8 will not drop in a young collection is held by a weak `v8::Global`, as before the batch. The cache decides it once (wrapper_cache.zig `heldByWeakHandle`: born with an own property, or changed by the binding), pinned by a test that asks V8 template by template. The last sentence of "What Happened" described the tree before that ruling: the account does not pace these shapes' collection. It also tells V8 only 112 bytes of an Event's 1.2 KB (lesson debugging-a-figure-that-explains-a-result-must-be-printed-by-the-code-that-produced-it.md).
**Lesson**: V8 drops a wrapper held by a droppable traced reference in a young-generation collection only while the wrapper is an "unmodified API object", and its test is that the object's map is still its constructor's initial map. An object made from a template that has any own property - a `[LegacyUnforgeable]` attribute such as `Event.isTrusted` - never has that map, so its wrapper waits for a full collection. That is true in Blink too, and no placement of the property changes it.

**Why**: V8 makes an object from a template in two steps (15.7.112.43 src/api/api-natives.cc:351-356, `InstantiateObject`): `JSObject::New(constructor, new_target, ...)` gives it the constructor's initial map, then `ConfigureInstance` adds the instance template's properties, which moves the object to another map. The test a young collection applies is `JSObject::IsUnmodifiedApiObject` (src/objects/js-objects.cc:3152-3168; called from src/handles/traced-handles.cc:519-533): a JS API object with no elements and no identity hash whose map equals `constructor->initial_map()`. WebIDL requires an unforgeable attribute to be an own property of every instance, and both Blink and Crane put it on the interface's instance template (Crane: src/runtime/engines/v8/interface.zig, `if (unforgeable) instance_tmpl else proto_tmpl`). Blink makes each wrapper by cloning a per-context boilerplate made by that same instantiation (third_party/blink/renderer/platform/bindings/v8_per_context_data.cc:96-117, Chromium 157.0.8103.51), so a Blink `Event` wrapper has the same non-initial map. Chrome does not feel it: its Event object lives on the C++ heap, whose growth V8 counts, so the full collection that takes the wrapper comes on time.

**What Happened**: Lane wrap1 batch 3 moved every non-node wrapper from a weak `v8::Global` (which lets any dead wrapper go in a young collection) to a droppable `v8::TracedReference` (Blink's shape). The batch's own pin said a dead Event's wrapper is dropped by a scavenge; it was not - 1,000 dead Events were still cached after four young collections, while 1,000 dead URLSearchParams (no own property) were gone. The first reading was "isTrusted is added per object; move it to the instance template as Blink does", and the integrator ordered that fix. Reading interface.zig and api-natives.cc before building showed that Crane already does that, and that the instance template is exactly what makes the map differ. The interfaces affected are Event and every interface that inherits from it, Window, Location and Document (`location`); only events are made in volume. The instruction was withdrawn; the batch measures the make-and-drop rows instead, and what paces the full collection is the account of what the instances hold (v8_wrapper.cpp, "What the instances behind non-node wrappers hold").

**Fix**:
1. Before promising that a wrapper shape is collected by young collections, check its interface for own properties on instances: `[LegacyUnforgeable]` members, and anything the binding sets on the wrapper after it is made (a private property for a traced child, an expando). Each makes the wrapper a root in young collections.
2. Pin the behaviour with a test of the shape itself (tests/v8/wrap1_platform_anchor_test.zig, "the cache's rule for a weak handle is V8's own answer, template by template"), not with one representative interface.
3. For such shapes, make sure something the collector counts grows with them, or nothing asks for the full collection they wait for.
4. When an instruction says "do it the way the browser does", read the browser's code and the engine's before building: here the browser's way was already in the tree, and it was the cause.

**Takeaway**: **"Unmodified" means "still on the constructor's initial map", and an instance template with own properties moves every instance off it at birth. A wrapper of such an interface is collected by full collections only - in every embedder - so account for what it holds.**
