# Workflow: A PGO profile from another configuration is filtered, not forced

**Date**: 2026-11-04
**Lesson**: Chrome's profiles describe Chrome's V8 configuration; applied to Crane's (no i18n, the system libc++, a standalone tree), the parts that cannot match are taken out by GN argument rather than by changing V8: rewrite clang profile names for the tree, and drop the builtins whose CSA graphs differ from V8's builtins profile.

**Why**: Both kinds of PGO key their data to Chrome's build. Clang's IR profile names a function by its mangled name - which carries libc++'s inline namespace (Chromium's `std::__Cr`, the system's `std::__1`) - and a file-local one by `<source path>;<name>`, where Chrome's path is `../../v8/src/...` and a standalone V8's `../../src/...`. V8's builtins profile (tools/builtins-pgo, x64.profile for arm64 too) carries a hash of each builtin's CSA graph, recorded where V8_INTL_SUPPORT and with it static roots are on (BUILD.gn: `v8_enable_static_roots` needs `v8_enable_i18n_support`); without static roots every builtin that compares against a root has a different graph.

**What Happened**: The official build's mksnapshot stopped on `--abort-on-bad-builtin-profile-data` ("Rejected profile data for CallProxy due to function change"). Run by hand with `--warn-about-builtin-profile-data`, it listed 130 of the 768 profiled builtins; three more (StringFastLocaleCompare, StringPrototypeToLowerCaseIntl, StringToLowerCaseIntl) do not exist without Intl. Dropping only the 130 still trapped: with every remaining hash matched, `--reorder-builtins` runs (embedded-data.cc skips it unless `all_hash_matched()`), and BuiltinsSorter maps an unknown name to builtin 0 (`name2id[...]`), so `CHECK_EQ(builtin_density_map_[id], 0)` failed. With both groups dropped, 635 builtins keep Chrome's hints and the reordering runs. For clang's profile, rewriting the text form (`llvm-profdata merge --text`; `../../v8/` -> `../../`, `gen/v8/` -> `gen/`, `St4__Cr` -> `St3__1`) and indexing it again gave a 69.5% match over V8's own 61,277 functions (read from the bitcode's function_entry_count).

**Fix**: scripts/build-v8-official.sh `profile` (the rewrite) and `builtins_profile` (the mksnapshot --warn pass, the filter, `v8_builtins_profiling_log_file`). Measure the match before trusting a profile: `pgomatch`.

**Takeaway**: **Fit a borrowed profile to the build - names rewritten, entries the build cannot match removed - through the build's own arguments, and measure what still matches; never turn the safety check off or patch the code to make a profile apply.**
