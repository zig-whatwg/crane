# Architecture: Fix the event loop that runs, not the spec model beside it

**Date**: 2026-10-03
**Lesson**: requestIdleCallback and "a task is runnable" were both briefed against `src/html/event_loop/` - its `IdleCallbackManager`, its `Task.isRunnable` TODO - and neither file is on the path a window's tasks take. The loop that runs them is `src/browser/event_loop.zig`, and the task it runs is `runtime.EventLoopTask` (`src/streams/internal/event_loop.zig`), which had no document field at all.

**Why**: `src/html/event_loop/` is a spec-shaped model: task sources, a Zig microtask queue with checkpoint callbacks, an idle callback manager, `isRunnable`. It compiles, it has tests, and `impls/Window.zig` even imported its `IdleCallbackManager` - so it reads as the event loop. Nothing drives it: `EventLoop.init(.window, ...)` appears only in its own tests, its microtask checkpoint has no caller, and its root.zig says so in capitals. The Browser pumps `browser/event_loop.zig` (`Browser.runEventLoopBlocking` -> `runOnceBlocking`, which the WPT runner's `waitForCompletion` calls), workers pump the V8 adapter's `V8EventLoop`, and the microtask checkpoint is `engine.performMicrotaskCheckpoint`.

**What Happened**: The placeholder rIC stored its callback in the dead manager, so `new Promise(r => requestIdleCallback(r))` never settled; implementing the manager would have changed nothing. `Task.isRunnable` treated every non-null document as fully active, but no live task carried a document, so wiring the TODO alone would have dropped nothing. The same question from the integrator - is IndexedDB's transaction cleanup, installed into `microtask.zig`'s callbacks, on the live checkpoint? - had the same answer for that slot: dead (the live cleanup turned out to run through `src/html/microtask_checkpoint.zig` on the agent's afterMicrotaskCheckpoint hooks).

**Fix**: Trace from the pump to the task before designing: `tests/wpt_runner/wpt_browser.zig waitForCompletion` -> `Browser.runEventLoopBlocking` -> `browser/event_loop.zig runOnceBlocking` -> `runQueuedTasks` -> `runtime.EventLoopTask`. The idle period went into `runOnceBlocking` (step 2d), the document into `runtime.EventLoopTask` (`document`, `document_generation`) with the check in `runQueuedTasks`, and the per-Window lists into `impls/Window.zig` behind a `dom.idle_periods` hook.

**Takeaway**: **Before wiring a step into "the event loop", follow the runner's pump to the task type it actually runs. `src/html/event_loop/` is a model nothing drives; a fix there compiles, passes its own tests, and changes nothing.**
