# Architecture: A legacy platform object needs a proxy only for its named properties

**Date**: 2026-10-11
**Lesson**: Every NodeList, DOMTokenList and other legacy platform object was wrapped in a JS Proxy so that `Reflect.ownKeys` answers in WebIDL's order. Only interfaces with named properties need that: V8's own order is already WebIDL's for an object with only an indexed interceptor. The proxy cost every read and changed [[Set]] and [[DefineOwnProperty]] away from the spec. "Named properties" means the binding's, not just the IDL's: CSSStyleDeclaration has Crane-defined ones.

**Why**: WebIDL 3.9.6 orders a legacy platform object's keys as supported indices, then supported names, then own string keys, then symbols. V8's KeyAccumulator collects an object's elements, then the indexed interceptor's indices, then own string keys, and only then the named interceptor's names (keys.cc, CollectOwnPropertyNames). So only the named step is out of place. An object with no named getter also has no own elements, because the indexed definer rejects every array index (3.9.3 step 1). Its native order is therefore WebIDL's. Meanwhile a Proxy has no inline cache. Every `list[i]` went through Runtime_GetPropertyWithReceiver and JSProxy::GetProperty instead of LoadIndexedInterceptorIC. Every `i in list` ran a `has` trap that looked up `Reflect` on the global and called it. And the traps were not transparent. The `set` trap called Object.defineProperty, which threw even for a sloppy-mode `list[0] = x`. The `defineProperty` trap's Reflect.defineProperty swallowed the definer's rejection, so `Object.defineProperty(list, "0", ...)` did not throw.

**What Happened**: dom/nodes/NodeList-static-length-getter-tampered-indexOf-*.html each call Array.prototype.indexOf over a 100-element static NodeList 5e6 times, about 1.5e8 HasProperty-plus-Get pairs. A gc_bench profile put 55% of each pair in the `has` trap's Reflect forwarding. Unwrapping the indexed-only interfaces made that loop 3.8x faster in the Debug build (13.7 s to 3.6 s for 5e6 elements). It also fixed what webidl/ecmascript-binding/legacy-platform-object/DefineOwnProperty.html checks on a DOMTokenList.

**Fix**: template_registry.zig's `legacy_platform_objects` names only the interfaces with named properties: HTMLCollection, HTMLFormControlsCollection, HTMLOptionsCollection, NamedNodeMap, Storage, Plugin, PluginArray, MimeTypeArray, and CSSStyleDeclaration. CSSStyleDeclaration was first unwrapped from its IDL alone, which has no named getter. But Crane's binding gives it camelCase CSS properties (call_namedItem / call_setNamedItem). V8 runs an object's named setter interceptor before a prototype's accessor, so `style.cssText = ...` went to the named setter. The A/B caught it: content-security-policy/style-src/style-src-inline-style-with-csstext.html. tests/v8/indexed_property_semantics_test.zig pins the key order, for-in, assignment and definition semantics on both kinds. It also checks that no unwrapped interface has a named getter, using the binding's own predicate.

**Takeaway**: **A wrapper that exists to fix one internal method costs every operation that passes through it. Wrap only the objects whose behaviour actually needs the fix, decide that from what the binding installs (not from the IDL alone), and check that each trap is as transparent as the target it forwards to.**
