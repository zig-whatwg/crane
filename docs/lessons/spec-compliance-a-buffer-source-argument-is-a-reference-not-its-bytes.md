# Spec Compliance: A buffer source argument is a reference to its object, not its bytes

**Date**: 2026-10-02
**Lesson**: WebIDL makes a BufferSource or ArrayBufferView argument "a reference to the same object", and each spec copies the bytes at its own step; a binding that copies at conversion reads them too early, and one that slices the backing store reads freed memory.

**Why**: The tempting design converts a buffer argument to bytes once, in the binding, so the impl has a plain `[]const u8`. That freezes the bytes BEFORE the operation's own steps run, and those steps can run script first. WebCrypto's encrypt, sign and digest normalize the algorithm (its `name` getter runs script) at step 2 and "get a copy of the bytes held by" the data at step 4; 41 WPT sites alter the plaintext or transfer its buffer inside that getter and expect the change to be seen (or the transferred buffer to read as empty). A slice into the backing store instead of a copy is worse: the transfer frees it under the impl.

**What Happened**: `typedefs.BufferSource` had no conversion at all - the generic union path found no arm for an ArrayBuffer or a typed array, so every BufferSource argument was a TypeError (all of SubtleCrypto). The first design for it (an owned copy at conversion, the way BodyInit's BufferSource arm is copied) was reversed once the WebCrypto lane traced the step order. Meanwhile ArrayBufferView arguments converted to a CLONE of their handle that the IDL value owned: three streams impls disposed it themselves, every other impl leaked it, and the argument's own handle leaked too - three Globals per `crypto.getRandomValues(view)` call counting the context the type was assumed to retain.

**Fix**: `conv.convertBufferSource` / `convertArrayBufferView` return the handle they were given as the value's `js` (an ArrayBuffer gets a struct with no bytes), never a clone and never a slice; a SharedArrayBuffer or a view over one is a TypeError. The value owns that reference until it is freed: `freeConvertedArg` releases it (an argument once the call returns, a dictionary member or sequence element with its container), `bufferHandleIsKeptInValue` / `keptArgumentHandle` let the conversion paths release a handle the value does not keep (null, not passed, a copying union arm, a failed conversion). Impls read the bytes at their own step with `engine.getCopyOfBufferSourceBytes(realm, source.jsValue(runtime.JSValue).?, allocator)`; `asBytes()` on an engine-backed value is `error.BytesHeldByEngine`. A view RESULT is the binding's, like a JSValue result: an impl returning a view it keeps or was given returns it over a hold of its own (`withJsHandle`). The three streams impls stopped disposing the argument; `byobRequest.view` returns a hold. tests/v8/buffer_source_argument_test.zig pins the shapes, the predicates' defaults and the live handle counts against a control call.

**Takeaway**: **Convert an argument to what the spec says its IDL value IS - for a buffer source, a reference - and let the algorithm take its copy at its own step; a conversion that does the algorithm's work early changes what script can observe.**
