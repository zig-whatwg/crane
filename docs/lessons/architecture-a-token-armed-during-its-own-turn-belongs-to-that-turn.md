# Architecture: A token armed during its own turn belongs to that turn

**Date**: 2026-09-30
**Status** (2026-09-30, later): the fix is real, but it is NOT the sweep-only `WebSocket.InternalState.deinit` crash. On a 330-file sweep-prefix list that reproduces that crash, six single-process runs each crashed 1/6 on main, 4/6 with this fix, and 3/6 with this fix plus flakes' Selection pin (Fisher p ~0.15 for 7/12 vs 1/6). None of those processes logged an arena, slab or stale-child detector event. "Consistent with" below was a hypothesis the counts refuted: see tmp/plans/lane-hardening-handoff.md, item 1.

**Status** (2026-10-01): that crash's cause was found: `WebSocket.get_url` returned the socket's own url string, which the binding frees after every getter call, so InternalState.deinit freed it twice (666db2c53; [A fault in Allocator.free's memset is a double free](debugging-a-fault-in-allocator-free-s-memset-is-a-double-free.md)). The DebugAllocator printed "Double free detected" just before each crash.
**Lesson**: The WebSocket pump's token had an ownership rule - "armed: the scheduled turn owns it; not armed: the socket's teardown does" - and the end of a turn broke it: it freed a token the socket had given up during the turn without asking whether the turn had armed the next one first.

**Why**: A turn runs script. The script can call `close()`, which arms the next turn against the same token, and then end the socket (end its realm), whose teardown detaches the token. Both happen inside one turn. The turn's end saw `cancelled` and freed the token - while the turn armed a moment earlier still pointed at it. When that turn fired it wrote `armed = false` into freed memory and, if the reused bytes read as `cancelled`, freed it again. The token came from `page_allocator`, so "freed" meant a page unmapped, and "freed again" meant unmapping whatever the page had become since - a DebugAllocator bucket, say, whose next small free then faults in its memset. That is consistent with the sweep-only crash in `WebSocket.InternalState.deinit` - a free of a 32-byte URL string whose bucket page was no longer mapped: a victim, far from the cause.

**What Happened**: The ownership comment was right and the code enforced it in `detach` (free only when neither armed nor in a turn) and in the turn's start (free only when cancelled). The turn's end had a bare `if (cancelled) destroy`. Nothing exercised arm-then-detach inside one turn until the rule was pulled out into `src/websocket/pump_token.zig` with a fake timer: the test that arms and detaches in one turn crashed in `beginTurn` on its first run (`Segmentation fault ... self.armed = false`).

**Fix**: `PumpToken.endTurn` frees a detached token only when it is not armed; an armed one is freed by the turn it armed (`beginTurn`). The pump reads the token after every dispatch and touches nothing - Instance, state, connection - once it says the socket went; a turn whose realm has ended (retired, no engine context) stops instead of re-arming forever. Tokens come from `c_allocator`, not a page each.

**Takeaway**: **An ownership rule with more than two states must be checked at every exit, not just the obvious ones - and the exit most likely to be wrong is the one that runs after arbitrary script. Extract the rule into a type small enough to test with a fake timer.**
