# Codegen: A special operation is found by its metadata, not its name

**Date**: 2026-10-11
**Lesson**: The binding decided which function was a legacy platform object's indexed or named getter, setter or deleter by guessing from function names, and every guess was wrong somewhere; codegen now records the special operations in `Meta.special_operations` and the adapter binds from that table alone.

**Why**: WebIDL 2.5.6 lets a special operation have any identifier, or none, and an identifier makes it a regular operation as well. A name says nothing about whether a function is special. The adapter's guesses were `call_item` and an anonymous `call_getter(u32)` for the indexed getter, any `set_item` or `call_setter` for the indexed setter, `call_getNamedItem`, `call_namedItem` and a DOMString `call_getter` for the named getter, and `call_setNamedItem`, `set_namedItem` and a DOMString `call_setter` for the named setter. No deleter was ever bound.

**What Happened**: Storage's `getter DOMString? getItem(DOMString key)`, `setter setItem` and `deleter removeItem` matched none of the guesses. So `localStorage[k] = v` made an ordinary property, the map stayed empty, and `length` read 0: webstorage/ had 115 subtests passing and 1,176 not. NamedNodeMap's REGULAR `setNamedItem(Attr)` was taken for a named setter, so its named properties claimed to be writable and `attrs.id = x` made an expando. SVGNumberList's `getter getItem(unsigned long)` was never bound. HTMLSelectElement's regular `namedItem` counted as a named getter, and only a missing `getSupportedPropertyNames` kept it from being bound. When codegen began re-exporting HTMLOptionsCollection's inherited `call_namedItem`, the name guess took its indexed `call_setter` for the named setter, and the build broke. The audit also found two IDL special operations that no browser has: TouchEvent's `getter getModifierState` and the named getter XMLDocument inherits from Document. Following golden rule 2, codegen records neither.

**Fix**: `src/webidl/codegen/special_operations.zig` computes each interface's table: its own special operations, then for every variety it lacks the derived-most one its parent has (3.9), and [LegacyOverrideBuiltIns] / [LegacyUnenumerableNamedProperties] from it or any ancestor. It writes `pub const special_operations: webidl.SpecialOperations = .{ .named_getter = .{ .function = "call_getItem" }, ... }`, giving each anonymous operation `.implemented = @hasDecl(XImpl, ...)` because its delegate is gated, and writes nothing for an interface with no special operation. An heir re-exports the functions it inherits. Anonymous operations get one delegate each, numbered per keyword (HTMLFormElement's `call_getter` and `call_getter__1`), instead of a union-taking "overload". `interface.zig specialBinding` checks each function's shape at comptime and is the only predicate the handlers use. The proxy's set trap takes its "has a named setter" flag from the same table, where it used to compare the constructor name with "Storage". tests/codegen/special_operations_metadata_test.zig pins the table, including the default of no entry; tests/v8/special_operations_binding_test.zig pins `specialBinding` for the interfaces the audit named.

**Takeaway**: **The binding map's names say a function is bound, never what it is. When the binding needs to know a member's role (special operation, overload, [CEReactions]), codegen states it in a table beside the delegate, from the IDL, with an explicit default for "none".**
