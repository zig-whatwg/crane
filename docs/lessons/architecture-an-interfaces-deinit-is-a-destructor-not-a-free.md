# Architecture: An interface's deinit is a destructor, not a free

**Date**: 2026-10-24
**Lesson**: `interfaces.X.deinit(child)` runs a platform object's destructor chain and leaves its slab slot and state block issued; an owner that frees a child no wrapper owns must free it whole (`runtime.Instance.deinit`), or the slot stays with the Browser until it ends.

**Why**: Freeing a platform object is two obligations: its type's teardown (the vtable destructor, which the generated `interfaces.X.deinit` is) and its storage (`runtime.gc.releaseStorage`: the state block back to the arena, the slot back to the slab). `Instance.deinit` and the collector's `gc.onObjectFreed` do both; the interface's `deinit` does only the first, because it IS what they call first. A wrapped child gets its storage back from its wrapper's teardown. A child nobody ever wrapped has no such teardown: whoever tears it down is the only one who can return its storage.

**What Happened**: Lane unwrapped1's per-type slab histogram found one AbortSignal per testharness subtest outliving its page in a WPT runner process: 1,975 slots after the first of ten dom/ files, 13,676 after Range-compareBoundaryPoints (whose 9,313 AbortControllers WERE freed by the next page), 14,463 after all ten. A count of the signals whose state was gone (`_internal == null`) matched the leftovers exactly: every one had been torn down, none returned. testharness.js makes an AbortController per test (`Test._abortController`, aborted at cleanup) and never reads its signal, so the signal is never wrapped; the controller's teardown freed it with `interfaces.AbortSignal.deinit` (since eea7c2b08, 2025-12). `leaks --atExit` saw nothing: the Browser's end frees the slab. A native page-churn test showed it on the first page too: 300 controllers collected in the page left 300 signal slots.

**Fix**:
1. AbortController frees the signal no wrapper owns with `runtime.Instance.deinit(signal)` - in its deinit and its init's errdefer. WebKit's controller holds `Ref<AbortSignal>`, Blink's traces `signal_`: a full owning reference either way.
2. The one case where the controller's branch meets a signal with a wrapper behind it - both wrappers collected together and the controller's teardown first, or a teardown hold's release order - now frees the slot before the signal's own finalizer. That finalizer must skip it on the slot's generation (`wrapper_cache.slotReissued`). tests/v8/abort_signal_slot_reuse_test.zig forces that order (a hold, an arranged release) with an impostor AbortSignal in the freed slot AND state block, speaking through an abort algorithm's drop step: green, and red with the generation comparison removed.
3. tests/html/abort_signal_page_storage_test.zig churns pages per kind of signal (a controller's never read or collected in the page, read and listened to, any(), timeout() fired and pending, abort(), Request and fetch, pipeTo, a frame's any() of the page's signals) and requires the AbortSignal and AbortController slots to be the first page's at every page.
After: the AbortSignal slots at each of the ten files' ends are the page's own (= its controllers), none torn down; the process ended at 3,984 live slots instead of 17,897.

**Takeaway**: **A destructor chain is not a free. Whoever tears down an object no wrapper owns must also return its storage - `runtime.Instance.deinit`, never `interfaces.X.deinit` alone - and a slot count per type per page, with a count of the torn-down ones, names such an owner at once.**
