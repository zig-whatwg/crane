# Testing: Stamp the allocator's reports with the journal, and read every getter twice

**Date**: 2026-10-01
**Lesson**: A sweep log's "Double free detected" names no file, and WPT reads few getters twice. Two cheap harnesses close both gaps: run each chunk as ONE single-process runner with its stderr piped through a filter that prefixes every allocator report with the chunk journal's record count, and generate one probe page per interface that gets an instance and reads every getter on its prototype chain twice, then stringifies it twice.

**Why**: The runner's children share one stderr, the DebugAllocator writes its report unbuffered while the runner's own progress lines are buffered, and the fast allocator keeps no stack traces - so a report in a sweep log is only "somewhere in this shard". And the seam's returned-alias bugs (a getter handing the binding memory it still owns, a stringifier returning a literal) fire on the FIRST read of a value the test reads only once, or only when a test happens to stringify: WPT's 0.1 worklist stringifies no DOMMatrix, no CSS Typed OM value and no Selection.

**What Happened**: The seam batch swept main-21edba80f's runner in 60-file chunks, `wpt_runner --from-file=<chunk> --parallel=1` with `2> >(stamp journal.jsonl)`. Its 6 reports came out as `J=12` (4, messageevent-constructor - the record count is the file whose teardown freed twice), `J=36` and `J=1`; the two odd ones paired sandbox_030/031 and submit-file/text-plain, which share nothing but `localStorage` in an opaque-origin frame: Window.get_localStorage freed its backend in a `catch` AND in the `errdefer` above it. Alone, neither file reproduced; the pair did, every run. The sweep also reproduced the frozen baseline's numbers (1,363 blocking, +2 subtests of 1,293,150), so the single-process chunks change nothing they measure. The probe (1,262 pages, one per generated interface) crashed 21 interfaces on main - every stringifier stub that returned the literal "[object]" and every CSS Typed OM type inheriting one - and none on the fixed tip.

**Fix**: Scratch, not tools (they are throwaway queries): a 15-line Python stamp filter (`J=<lines in the chunk journal> <line>` for lines matching Double free / does not match free size / Invalid free / panic), a bash chunk driver taking one `crane-measure.sh` token per chunk, and a generator writing `crane/sm-probe/p-<Interface>.html` into chat's served tree only (deleted after). Attribution: `J=N` is line N (the file just recorded, freeing at its teardown) or N+1 (the one running) of the chunk's worklist.txt; run the candidates alone and in pairs, then with `CRANE_LEAK_TRACES=1` and stderr in its own file for the stacks.

**Takeaway**: **An allocator report you cannot attribute is a report you cannot fix: stamp it with the journal count. And a returned-alias bug waits for its second read - read every getter twice on purpose instead of waiting for a test to.**
