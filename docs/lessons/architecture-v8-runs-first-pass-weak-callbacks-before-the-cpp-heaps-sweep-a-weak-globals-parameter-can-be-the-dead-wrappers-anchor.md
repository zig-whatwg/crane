# Architecture: V8 runs first-pass weak callbacks before the C++ heap's sweep - a weak Global's parameter can be the dead wrapper's anchor

**Date**: 2026-11-16
**Lesson**: In V8 15.7.112.43 a first-pass weak callback can read the cppgc object its dead wrapper pointed at, in a young collection and in a full one, so a weak v8::Global needs no callback record of its own: its parameter is that object.

**Why**: A young collection does not collect the C++ heap. A full collection marks it, then runs every first pass, and only then starts the C++ heap's sweep: src/heap/heap.cc:2344 `InvokeFirstPassWeakCallbacks()`, then :2346-2355 `CppHeap::CompactAndSweep()`, under V8's comment that the sweep's start "has to be called *after* all other operations that potentially touch and reset global handles". Marking's end frees nothing (src/heap/cppgc-js/cpp-heap.cc `FinishMarkingAndProcessWeakness`). V8's own API foresees the use: `WeakCallbackInfo<T>` derives from `cppgc::internal::ConditionalStackAllocatedBase<T>`. It is an internal order all the same, not a documented promise.

**What Happened**: The wrapper cache held each wrapper V8 will not drop in a young collection by a weak Global armed with the adapter's generic arm: a 48-byte record from malloc, a node in a process-wide map under a mutex at every arm and death, and a node in a per-thread map until the finalizer ran. Lane wrap1's idea was the cache's record as the parameter, which needed the anchor's address in the record (32 -> 40 bytes for every wrapper), because its comment assumed a dead anchor "may be swept already". Reading heap.cc showed it is not. Lane wrap2 armed the Global with the anchor, which already names the record: the record stays 32 bytes, the arm allocates nothing, and the first pass severs the anchor in every collection, which made lane wrap1's "anchor traced" bit and its `cpp_weak_processed` flag unnecessary.

**Fix**: When a first pass needs something of the dead object, look for a C++-heap object that already names it before adding a field or a side record. Then hold the reading to the engine version: a `static_assert` on V8's major and minor version beside the citation, a test for both collection kinds with and without a stack scan that keeps the anchor, and a mutant run that shows the test fails when the step is skipped.

**Takeaway**: **Read where the engine runs your callback before assuming what is already freed there. An internal order you rely on gets a version assert with its citation, so an engine update fails the build until someone reads it again.**
