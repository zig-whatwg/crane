# Architecture: A deferred finalizer needs a safe point inside the task, not only between tasks

**Date**: 2026-11-11
**Status (2026-11-12, lane v8up b7)**: the safe points stand; the queueing moved. The record now joins the agent's queue in V8's FIRST pass, so a finalizer no longer waits for the next collection to run a pending second pass (architecture-a-dead-wrappers-finalizer-is-queued-in-the-first-pass-a-second-pass-is-a-collection-late.md).
**Lesson**: Moving a finalizer out of the collector to "the next safe point" is only half a design: say which safe point one long task reaches, and measure a one-script loop that makes and drops objects before calling the move free.

**Why**: The queue that took Zig finalizers out of V8's second pass (lane v8up b6) ran them at the pump and when a forced collection returned - "the moments they ran before". That was true only between tasks. V8 posts a collection's second pass as a task (15.7.112.43 src/handles/global-handles.cc:892-901), and when the NEXT collection begins before that task ran, V8 runs the pending pass first (src/heap/heap.cc:1509-1511, `Heap::CollectGarbage`: "Ensure that all pending phantom callbacks are invoked"). In one long script that was where every finalizer ran: one collection late, in the middle of an allocation. With the queue they all waited for the pump, a task away, each keeping its native state.

**What Happened**: The filtered RED/GREEN of the queue passed. The cost step found it: 300,000 `new Event('x')` dropped in one script ended at 392.4 MB instead of 168.0 MB (release consoles, chat.local), and gc_bench's unpumped Event loop kept 1,120 B of state per Event instead of 565 B; kept wrappers and pumped loops were unchanged. The full native step then failed the test that pins exactly this (tests/html `rc9_document_tasks_test`: "600 dropped documents in one script: the slab grew by 425850 slots"). The first explanation - "a collection for external memory runs its second pass at once" - was written from memory and was wrong: `Heap::UpdateExternalMemory` collects through `CollectGarbageWithRetry`, which passes no callback flags (heap.cc:7021-7038, 2132); its own test said so (0 queued when the report returned), and the source, fetched at the pinned tag, named the real path in two greps.

**Fix**: `v8_ExternalMemoryAccounter_Update` runs the queue when V8 returns: the host's external-memory report is made only at the agent's own safe points (the binding exit to script at DOM-algorithm depth zero, the microtask checkpoint), inside a task. That bounds everything in the reported figure (the documents test passes again). It does NOT cover objects outside the figure - the Event loop makes no report and still ends at 392.5 MB - so the binding exit itself has to become the safe point (queued for the integrator's ruling).

**Takeaway**: **When work leaves a callback for "later", list every place the callback used to run - including the ones the engine reaches by itself inside a task - and give each a safe point; then prove it with a one-task churn loop's peak (the five-mark `event` reading, gc_bench without `--gc` and without `--loop`), not with a test that pumps. And read the engine's mechanism at the pinned tag (`raw.githubusercontent.com/v8/v8/<tag>/src/...`, grep by line) before naming it in a comment or a test.**
