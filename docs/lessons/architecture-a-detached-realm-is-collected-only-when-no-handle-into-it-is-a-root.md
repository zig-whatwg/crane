# Architecture: A detached realm is collected only when no handle into it is a root - find the roots with a heap snapshot, not by reading code

**Date**: 2026-10-01
**Lesson**: Keeping a removed frame's Window alive for exactly as long as script holds its WindowProxy (HTML "destroy a child navigable"; Blink's `DisposeContext(kFrameIsDetached)`) works only if, from the frame's detach on, nothing Crane holds into the frame's context is a strong `Global`. Every kind of strong hold has to be found and turned into an edge from the realm's global object - and each kind was found by measurement, none by reading.

**Why**: V8 collects a context when nothing reaches it. Any one strong handle to any object of the frame - a wrapper, a callback, a retained value - reaches its map, its constructor and so the native context. A strong hold that the frame's own objects reach back to (the frame's global holds the XHR, the XHR's handler closes over the frame) is a cycle through a root: never collected until the page ends.

**What Happened**: The realm-end split (lane realms2, A-FULL step 6) detached a frame's realm instead of freeing it: script activity stopped, the context handle and intrinsics weak, the wrapper cache's strong entries kept from the global object (`v8_Context_RetainOnGlobal`). The fl- deviation flipped (`closed` true, `document` answers), and frames with plain children were collected - but html5lib_write alone went 14 -> 22 native contexts, and Crane probes kept frames. Each remaining root was named by one of two methods:
- `CRANE_HEAP_SNAPSHOT=<path>` + a retainer-path walk from `(Global handles)` to each `system / NativeContext` (a 60-line scratch script over the snapshot's nodes/edges arrays): eight contexts were held through `HTMLHeadElement`/`Attr` wrappers - torn-down nodes' wrappers that `markAsCleanedUp` held strongly until the page ended.
- A probe page making one removed frame per kind of object, each dropped, a WeakRef per frame, and the kinds whose frame survives listed: event handlers and listeners stored on frame objects whose closures reach the frame (`xhr.onloadend = () => { w.done = true }`) - `engine.CallbackFunction` Globals outside `callback_registry`; every `same_object.Pin`; a finished FileReader's `result` (`engine.retainValue`).

**Fix**: torn-down nodes' wrappers weak (`markAsCleanedUp`); callback handles tagged with the realm whose API stored them (`takeCallbackFunction` - the current realm, since V8 runs an API function in its own context) and weakened at detach (`v8_Context_WeakenTaggedHandles`); Pins only for pending activity, everything else `same_object.Traced`. Retained values (`FileReader.result`, `NavigateEvent.info`, transition promises, `xhr.response`) are still roots: they need a traced-value operation.

**Takeaway**: **When a lifetime depends on "no strong handle into X", enumerate the handles by measurement - a heap snapshot's retainer paths from (Global handles), and a one-kind-per-frame WeakRef probe - before believing any list made by reading code.**
