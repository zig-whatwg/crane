# Architecture: A wrap mark must say when the last wrapper went - and a sweep must wait for a tree's root

**Date**: 2026-10-24
**Lesson**: A page's end kept the slab slot of every node, document and owned child that WAS wrapped once but had no wrapper left when its owner tore it down - a removed frame's whole document, every wrapped node of a detached wrapped tree whose entry the sweep reached before its root, every attribute map script read - because the only proofs of "unreachable" were "never wrapped" and a cache entry that was already gone.

**Why**: A platform object's storage goes back when the last thing that can reach it is done: its owner's teardown when no wrapper can reach it, else its wrapper's end. Three exits were missing, invisible to `leaks --atExit` (the Browser's end frees the slab):
- **The wrapper went first.** The finalizer of a wrapper whose instance the host keeps (a tree's node, a window's document) let only the wrapper go (`finalizeEntry`'s ENGINE-OWNED branch) and left the sticky wrap mark. The collector takes a removed frame's realm whole; its end then tore the document down, found every wrapped node marked, and kept their slots - no entry was left to return them. The window's document itself had no storage path at all (`Window.deinitOwn` ran `interfaces.Document.deinit`).
- **The sweep reached a child before its root.** `WrapperCache.deinit` walks in hash order. A tree-owned child's entry let only the wrapper go (its root frees it); the root's teardown later freed the child but left a wrapped node's storage to its wrapper - whose entry was gone. In the other order the child's slot went back INLINE, mid-sweep, where the next allocation of any type took it.
- **A destructor ran as a free.** Element tore its NamedNodeMap down with `markCleanupStarted` and the interface's deinit: the wrapper's end saw "started, never completed" and returned nothing. The same class as abortsig1's AbortSignal: a URL's query object (made with every URL; testharness.js makes URLs on every page), a MessageChannel's unread ports, XHR events no listener saw, the page load's iframe HTMLCollection, a window's Location and History (the Location taken out of its cache unsevered first). The URL's call was through an alias (`const URLSearchParams = interfaces.URLSearchParams`), which a grep for `interfaces.X.deinit(` missed.

**What Happened**: Lane pageretention1's page-churn tests (tests/html/page_retention_test.zig, one Browser, slots per vtable per page) were red per page at bbb64bb6e48: Window/Location/HTMLCollection +1 each; 50 detached wrapped trees +25-30 nodes of each type; two removed frames +2 Document/html/body (untouched: +2 Document), and with templates +20 DocumentFragment; attribute maps +25; ten sync XHRs +20 Event, +20 ProgressEvent. The census's `wrapped`/`torn down` columns named the class at once: every leftover was torn down, and all but the events were wrapped. The kept [SameObject] children and parsed templates the brief suspected were flat: their getters' hand-out wraps the child (engine.traceChild), so their wrappers freed them.

The WPT runner told the same story at scale (Debug runner with a per-type slot histogram, CRANE_HEAP_GC=1, each list run twice in one process: what one pass of pages leaves behind): hashmaps1's ten dom/ files +1,211 slots a pass (Text 578, div 172, ... - detached wrapped trees), the template-element directory +1,314 (URLSearchParams 456, Location 190, History 74, frames' documents), a browsing-the-web subset +1,055 (URLSearchParams 351, Location 179, Document 84, html/head/body ~60 each). A last exit showed only in a diagnostic log of Node.deinitNodeByType's storage branch: the documents of frames' RETIRED realms, torn down by the deferred teardown queue after their realm lost its engine, kept every slot because a retired realm cannot ask a wrapper cache - though the wrap mark already proved nothing reached them (head 45, html 37, body 37 on six frame-loading files).

**Fix**:
1. `instance_lifecycle.wrapper_gone` (a reserved bit): the V8 adapter sets it when it finalizes the LAST engine object of an instance the host keeps - collected, `!wrappedElsewhere`, not a realm's global - and `markWrapped` clears it. `provablyUnwrapped` means "no engine object bound NOW"; every reader stays safe because wrapped nodes are upward-closed and one collector cycle. Inside a teardown the finalizer hands an already-torn-down instance's slot to the coordinator. The wrap_tracking contract says so; unsupported engines keep everything.
2. `WrapperCache.deinit` sets a tree-owned entry aside (its own pending link: no allocation) until the walk ends, then severs and defers each whose root's teardown freed it; the started branch defers too inside a teardown.
3. `runtime.gc.releaseOwned(child)`: destructor once, cleanup marked complete, storage now / after the teardown / at the wrapper's end. Used by KeptChild (`releaseOwned`), Element's NamedNodeMap, Window's Location/History, URL's query object and MessageChannel's unexposed ports (safe across threads: a port's peer reaches it only through its own end's owner record, cleared under the channel's mutex); Window tears its document down through Node's teardown (`dom.node_creation.destroyRoot`); XHR events and the load's HTMLCollection use `runtime.Instance.deinit`. A Window's own slot is left for a follow-up: raw pointers across realms (opener, MessageEvent.source, ...) read a torn-down Window safely today and would read whatever took a returned slot.
4. Node.deinitNodeByType's retired-realm branch releases a provably unwrapped node (`ctx.agent == null or provably_unwrapped`).
After: dom/ +1,211 -> +11, template-element +1,314 -> +191, browsing-the-web +1,055 -> +179, the six frame files +129 -> +54 - every remainder a Window but one template (the Window is a follow-up: its raw cross-realm holders become generation links first).
Precedent: WebKit's JSDOMWrapper holds `const Ref<ImplementationClass> m_wrapped`, released with the wrapper - after it the node is its tree's alone.

**Takeaway**: **"Was it ever wrapped?" is the wrong proof once wrappers can die before their objects: track "is a wrapper bound now", clear it only when the adapter finalizes the last one, and let a sweep decide a tree-owned node's slot only after the walk that frees its root. Audit destructor-only frees by what they call, not by spelling - aliases hide them.**
