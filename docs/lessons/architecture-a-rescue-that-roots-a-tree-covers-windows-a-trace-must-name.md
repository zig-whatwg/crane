# Architecture: A rescue that roots a tree covers windows a trace must name one by one - list where a held object is between its owners

**Date**: 2026-11-09
**Lesson**: When a strong "rescue" (a root kept until its holder lets go) is replaced by tracing from the holder, every moment the held object is reachable from NO traced owner becomes an identity hole: a native list moved out for wrapping, a parser replaced while it still runs on the native stack. Enumerate those windows before deleting the rescue, and give each a traced owner.

**Why**: A rescue keeps its tree whatever happens to the holder's own reachability: a MutationRecord's rescue edge waited strongly in the wrapper cache until the record was wrapped, and a parser's rescue stayed in its Document's kept-roots array until the parser was released. Tracing keeps a held node only while some marked object names it in its Trace. Blink gets the in-between moments for free - its holders are GC objects and its C++ stack is scanned, so a record list in a local HeapVector or a replaced parser still unwinding are traced. Crane's holders are native Zig objects reached only from a wrapper's anchor or from another holder's trace; a record taken out of its observer's queue but not yet wrapped, or a parser document.open() replaced, is reached from nothing.

**What Happened**: The wrapper redesign's P6 deleted node_holds' chain and rescues (refcount step 9b) and made holders trace (`VTable.trace_held_nodes`, a HolderAnchor per holder wrapper; the Document traces its parser). Two windows surfaced in review, not in a test failure: (1) `takeRecords()` and notify step 6.4 move the observer's records out of the queue into a local list and then wrap them one by one - an allocation in between can finish a collection that finds the unwrapped records nowhere; (2) a custom element's connectedCallback runs during the parser's insertion and may call document.open(), which replaces the active parser while the old one is still on the native stack, working on its stack of open elements - the Document traced only `active_parser`. The integrator asked for a test of each; tests/html/wr6_parser_trace_test.zig's "old parser" case reproduces (2) (an expando on an element held only by the replaced parser's stack).

**Fix**:
1. MutationObserver and IntersectionObserver keep a `delivering` slice for the length of `createSequenceOfPlatformObjects` and trace it beside their queue.
2. A parser links itself into its Document's `parsers_on_stack` for the length of its outermost call (`protectForCleanup` / `ActiveCall.deinit`, when the call holds the Document), and the Document's trace walks that list beside `active_parser`.
3. Before deleting a rescue, list every place the held object is between owners (moved out of a container, handed to a callee, replaced but still running) and pin each with a red test with every other edge off.

**Takeaway**: **A rescue roots through every gap; a trace keeps only what some marked owner names. Before swapping one for the other, find each moment the held object has no traced owner - a native list moved out for wrapping, an owner replaced while still on the stack - and give it one.**
