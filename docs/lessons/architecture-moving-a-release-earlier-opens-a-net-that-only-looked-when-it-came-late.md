# Architecture: Moving a release earlier opens a net that only looked when the release came late

**Date**: 2026-11-12
**Lesson**: A stopgap that acts "when the release arrives" depends on WHEN it arrives. Before moving a release to an earlier point, list everything that reads the moment of that release - above all nets that fire only at one end of a lifetime - and run the whole native suite, not the files of the mechanism you changed.

**Why**: Refcount step 7a's net frees a detached tree that only its own pending work still holds (an `<img>` whose image update is pending) when a wrapper's release finds the tree's realm ENDED: `endedRealmNet` on a release, `node_wrappers.endRealm` for releases still pending at the realm's end. A release that arrives while the realm is alive is declined (`instance.ctx.hasEngine()`), and nothing looks at that tree again: it stays to the agent's end. Until lane v8up b7 a node wrapper's release in a short script almost always arrived late - V8's second pass ran at the next collection or the pump - so the net caught it at the realm's end.

**What Happened**: b7 queued every finalizer in V8's first pass, node wrappers' releases included, to free dead wrappers' native state a collection earlier. tests-v8 (1,841 tests) and the finalizer files of tests-html passed. The full native gate failed ONE test, deterministically: tests/html `parser_implied_end_tags_test` - "4 node(s) alive at the agent's end" (html, head, body and an `<img src=x>` in a tree `document.open()` had replaced). 15 of 15 runs with the early release, 0 of 15 without; the image case alone and the other ten cases without it both passed - it needs the pending image update AND a collection after the tree's wrapper died, inside the same script. The hole is older than the change (a pump between the collection and the realm's end opens it on main too), but the change made it the common case.

**Fix**: A node wrapper's release keeps its second pass (v8_wrapper.cpp `nodeWrapperSecondPass` says why); every other finalizer is queued by the first pass. The cost is one row (dom.clone-node ends 33 MB higher: a dropped tree waits one more collection). Closing the hole itself is step 7b's (the realm's end lets its pending work's references go) or the node redesign's: reported to the integrator, not patched around in the adapter.

**Takeaway**: **When a change moves a release, a finalizer or a notification earlier, find every consumer that acts on its ARRIVAL TIME - nets that fire "at the realm's end", sweeps that take "what is still pending" - and decide for each whether it still sees what it needs. And gate a lifetime change on the whole native suite before measuring anything else: the one test that pins the dependency is in a directory the mechanism's own tests never touch.**
