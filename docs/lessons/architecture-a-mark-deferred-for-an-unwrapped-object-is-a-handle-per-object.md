# Architecture: A mark deferred for an unwrapped object is a handle per object - cost a mechanism on the unwrapped path too

**Date**: 2026-11-23
**Lesson**: A mechanism that marks an object's wrapper must be costed for the object that has no wrapper yet; "the mark waits until it is wrapped" is a strong handle, a map entry and a key for every such object.

**Why**: `engine.traceValue` / `traceChild` on an owner with no wrapper keep the value in the realm's wrapper cache (`WrapperCache.deferEdge`: a strong `v8::Global`, 32 bytes of V8's handles, an entry in `edges_before_wrap` and an allocated key) until the owner is wrapped or dies. That is right for a rare edge and wrong for anything that happens to nodes script never sees. Most nodes are never wrapped.

**What Happened**: Refcount step 8's first trace-time build (lane rc8, e1c26d48d) kept a listener node's wrapper out of young-generation drops by setting a private property on it (`noteNodeHoldsValues`), because the walk that traces a node's listeners enters held subtrees only. It was called for every node that got a registered observer - including the TRANSIENT registered observer DOM "remove" step 15 gives each node removed under a subtree `MutationObserver`. Those nodes are usually unwrapped, so each removal made a waiting handle. The lane's targeted runs were green; the Linux gate caught it in a test that did not name it: `wrap1_platform_anchor_test`'s MutationRecord shape read 48.0 B of V8 handles per kept record against 16.5. The lane had "re-checked" the mark an hour earlier and reported that it stays - the reason was right, the check looked at the wrapped path only (the integrator, 2026-11-23 8:55 PM ET: "Check every new mechanism's cost on the unwrapped path as well as the wrapped one").

**Fix**: The property is gone. A node that keeps values gets a wrapper slot that is not droppable (`engine.keepNodeWrapperInYoungCollections`; V8: a default `TracedReference`, a root in a scavenge): decided where the node is marked if it has a wrapper, and where the wrapper is made if it has none - the adapter's wrap asks `runtime.lifetime.keepsValues` (one field read). Nothing is written on a wrapper, so elements with listeners keep their type's one hidden class, and an unwrapped node costs one bit. Pinned by V8's handle bytes per node removed under a subtree observer (0), and by the young-collection drop counter for nodes marked before and after they were wrapped.

**Takeaway**: **Before a mechanism touches a wrapper, ask what it does to the object with no wrapper - and measure V8's handle bytes per object on that path; a "deferred until wrapped" edge is a per-object handle, so decide at the wrap from a bit on the object instead.**
