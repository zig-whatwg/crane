# Spec Compliance: An engine's ordinary operation on an object with interceptors asks the interceptors again - a step that ignores named properties cannot delegate to it

**Date**: 2026-11-13
**Lesson**: WebIDL writes a legacy platform object's internal methods as its own steps followed by "then the ordinary algorithm, with THIS descriptor". The descriptor is the point: [[Set]] step 2 computes it with named properties ignored (LegacyPlatformObjectGetOwnProperty(O, P, true)). An implementation that finishes the method by calling the engine's ordinary operation on the object (V8's `Object::Set(context, key, value, receiver)`, or `Reflect.set(target, ...)`) hands the question back to the engine, which asks the object's interceptors for its own descriptor - named properties included. The step's "ignore" is lost.

**Why**: Crane's legacy platform objects with named properties are a Proxy around an API object with interceptors. The proxy's "set" trap handled "Receiver is the proxy" itself and delegated "Receiver is another object" to the target's ordinary [[Set]]. For `heir = Object.create(collection); heir.named = "foo"`, V8 found the collection's named interceptor on the way up, read the property as read-only (no named setter) and refused the write, so `heir.named` stayed the element. The spec's ownDesc for that name is undefined, the walk continues up the prototype chain, and the value becomes the heir's own property.

**What Happened**: Lane wrap1 batch 2 moved the trap off the page's `Reflect.set` onto `Object::Set` with a receiver, an exact translation, and then read the trap against WebIDL 3.9.2 step by step for the numbered comments. Step 2's `true` argument had no counterpart in the code. dom/collections/HTMLCollection-as-prototype.html "HTMLCollection as a prototype and setting own properties" had failed for that reason since the trap was written (wpt.fyi 2026-11-13: Firefox and Safari pass; Chrome fails the same way, its objects being API objects whose named query interceptor V8 asks on the prototype chain).

**Fix**:
1. Implement the tail of the method yourself when the spec passes it a descriptor: OrdinarySetWithOwnDescriptor is short (ES 10.1.9.2). Find ownDesc where the spec says (a real own property: `HasRealNamedProperty`; a supported index: the object's own descriptor for an array index; never a supported name), walk the prototype chain for an accessor or a read-only data property, then do steps 2.b-e on the Receiver with its own [[GetOwnProperty]], [[DefineOwnProperty]] and CreateDataProperty.
2. When you translate a call from one API to another (script's Reflect to the engine's), re-read the spec step it stands for. An exact translation keeps the old deviation.
3. Test a legacy platform object as a PROTOTYPE: an heir's assignment over a supported name, over a supported index and over an unsupported index, and `Reflect.set` with a Receiver that has a read-only property, an accessor, and a writable one.

**Takeaway**: **"Then the ordinary algorithm with this descriptor" is not "then call the ordinary operation": the engine recomputes the descriptor from the interceptors. Where the spec's descriptor differs from the object's own answer, write the ordinary algorithm's steps out.**
