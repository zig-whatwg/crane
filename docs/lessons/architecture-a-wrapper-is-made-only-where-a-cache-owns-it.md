# Architecture: A wrapper is made only where a wrapper cache owns it

**Date**: 2026-11-02
**Lesson**: `wrapInstanceAsV8Object` answers a wrapper every caller BORROWS from the realm's wrapper cache. In a context the context manager does not know, there was no cache to take it, and the wrap made one anyway: a `Global<Object>` nobody disposed, an instance marked wrapped for good, and a node bound to a wrapper no cache would clear.

**Why**: The ownership of a returned handle is a contract of the function, not of each call. "Borrowed from the cache" holds only on the paths where the cache took the handle. A path that makes the object and skips the cache step (no realm data for the context, or none with a cache) silently turns a borrowed answer into an owned one that no caller releases - and nothing fails: the wrapper is a real object, script can use it, and the instance's [wrap_tracking] mark makes every conservative teardown path keep its slot.

**What Happened**: Lane v8state1 surveyed tests-v8's per-test process state (tests/test_runner, report mode, batch 1). Two tests left `engine.live_object_globals` behind: microtask_dropped_end_test (0 -> 2) and teardown_gc_window_test (0 -> 1); `leaks --atExit` had named `v8_ObjectTemplate_NewInstance` as the root (lane engown1). To find the callers, a diagnostic build panicked, with a stack trace, wherever the wrap path made a wrapper no cache would take - with the launcher at batch 1, each such test died alone and its stack landed in the launcher's log, while every other test ran normally. Across all 1,684 tests exactly two sites hit it: a body read dropped at its realm's end (`realm_finalizers.drain` runs after `removeContextByKey` took the realm out of the manager; `Response.get_body` -> `createReadableByteStream` -> `retainValue` -> `relevantWrapper` wrapped the stream and its controller) and node tracing's `drawTreeEdges` wrapping a parent in a bare test context. The realm-end code already said what it expected: "a wrap answers undefined and makes no wrapper".

**Fix**: Before making the object, `wrapInstanceAsV8Object` requires the context's realm data and its wrapper cache, and answers `error.NoWrapperCache` otherwise; `conversions.instanceToV8Checked` turns it into the OWNED undefined every caller already handles for "no template". Blink likewise makes a wrapper only in a world with a DOMDataStore to hold it (`DOMDataStore::SetWrapper`). RED: tests/v8/wrap_needs_cache_test.zig (a bare context: one leaked `Global<Object>`, the instance marked wrapped).

**Takeaway**: **When a function's answer is borrowed from a container, every path that makes the answer must put it in the container first - or make nothing. A panic-with-stack in a diagnostic build, run one test per process, names every caller of such a path in one run.**
