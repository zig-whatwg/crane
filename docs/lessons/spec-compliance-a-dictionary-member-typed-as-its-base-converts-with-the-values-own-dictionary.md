# Spec Compliance: A dictionary member typed as its base dictionary converts with the value's own dictionary

**Date**: 2026-11-14
**Lesson**: When a spec types a dictionary member as an abstract base dictionary (Report's `ReportBody? body`), converting the member with its declared type gives an object with no member; convert the value with its own dictionary - the one the algorithm that made it names - as the engine that ships the dictionaries does.

**Why**: WebIDL 3.2.18 converts a dictionary member with the member's declared type. ReportBody has no members, so a literal conversion turns every report body into `{}`. The Reporting spec knows this and leaves it open ("how to polymorphically initialize body?", §4.3). Each reporting spec makes its body as its own dictionary ("Let body be a new CSPViolationReportBody, initialized as follows") or as "a new object containing" named properties (HTML's and Fetch's COEP bodies).

**What Happened**: Lane rep2 made Report and ReportBody the spec's dictionaries (w3c/reporting#284, the user's ruling of 2026-11-14), replacing the interfaces of the 2026-11-05 ruling, which structured clone refused (the COEP reporting files post reports from workers and frames, and timed out). WebKit, the one engine that merged the dictionaries (326027@main), declares body in its own Report.idl as a union of the body dictionaries, so each body converts with its own dictionary, and its ReportingObserver.cpp picks that dictionary per body class. WPT checks the result: content-security-policy/reporting-api/report-body-dictionary.https.html asserts the CSP body's keys are all eleven CSPViolationReportBody members in lexicographical order. Crane could not take WebKit's union: WebIDL allows at most one dictionary in a union, and Crane's generated optional members cannot say "present, and null" (codegen-a-returned-dictionary-cannot-carry-a-present-null.md), while CSP initializes `sourceFile`, `lineNumber` and `columnNumber` to null.

**Fix**: dom.reporting converts each report itself, through `engine.createDictionaryObject`. It picks the body's dictionary by report type (and "coep" by its body's `type`), takes the member list from codegen's struct for that dictionary (inherited dictionaries first, each one's members in lexicographical order), and writes a member when the record's body - the JSON its generator wrote, with exactly the members its spec initializes - has it, null included. The bodies no spec writes as IDL became dictionaries in specs/supplementary/report-bodies.idl under WebKit's names (COEP) and Chromium's (the COOP access body), so every body converts the same way.

**Takeaway**: **A base-typed dictionary member is polymorphic in practice: convert the value with the dictionary its maker names, read the member order from the generated struct, and let the made value - not Zig's optional - decide which members exist.**
