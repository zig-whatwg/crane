# Architecture: A collected tree is freed between tasks, a slice at a time

**Date**: 2026-10-09
**Lesson**: The second pass of a weak callback runs wherever the next collection lands - inside script, more often than not - so a collected root's subtree teardown there is a pause in whatever script that is. Queue the root on its agent and free the tree from the event loop between tasks, a bounded number of nodes at a time, re-checking ownership when the slice reaches it.

**Why**: V8 posts a non-forced collection's second-pass callbacks as a platform task, but runs any still pending at the start of the next collection (`Heap::CollectGarbage`: "Ensure that all pending phantom callbacks are invoked"). A script that allocates while trees die - wrapping a new tree's nodes - collects inside itself, and the previous trees' teardown runs there, all of it: `Node.deinit` walks the whole subtree. Browsers never pay that inline: WebKit frees by reference count as it goes, Blink's Oilpan sweeps lazily and concurrently.

**What Happened**: Lane nodeholds saw a replaced 10,000-node tree freed inside the next round's timed loop. Lane defertd's crane/dt-teardown-pause-sync.html (10 rounds in one task: replace a ~10,000-node tree by innerHTML, then walk and wrap every element, 100 a timed unit) on main 3eb0c1e8c2, base and tip interleaved, medians of 5: one root a round, timed walk 1,054 ms with a largest gap of 134 ms; 769 roots a round, 948 ms and 136 ms; against 573 ms and 1.1 ms with TestUtils.gc() between rounds outside the walk. With the queue: 788 ms and 41 ms, 802 ms and 58 ms (what is left is the collection's own per-wrapper bookkeeping, about 6 us a wrapper in Debug); crane/ed-qsa-timing's iterate 2,037 -> 1,548 ms. Freeing a tree in slices is not free of its own cost: the forced-collection control went 2,650 -> 2,825 ms in all, because the descendants' wrappers now finalize while their nodes still live (the long ENGINE-OWNED path) instead of after their root freed them (the short reissued-slot path).

**Fix**: `runtime.gc.DeferredTeardown`, one per agent on its AgentHost, handed to the engine as `AgentOptions.deferred_teardown`. V8's second pass queues a collected node (`wrapper_cache.queueCollectedNode`) instead of tearing it down; the event loop runs `runSlice` between tasks (512 nodes a slice, up to 4 ms a turn on the window loop, and down to 25,000 queued nodes whatever waits); `dom.tree_teardown.freeDescendants` frees a root's descendants leaves first through Node's destruction hook, and the root goes last through its own deinit. Every check `finalizeEntry` made is made again when the slice reaches the node: one wrapped again, back in a tree or freed by someone else is skipped, and a root wrapped again mid-way keeps a whole, smaller tree. The realm's end (`context_manager.removeContextByKey`, before its coordinated teardown) drains its own items, `requestGarbageCollection` and critical memory pressure drain all, the agent's end asserts the queue empty and closes it. Past 100,000 queued nodes the second pass frees what it queued plus a slice, inline.

**Takeaway**: **A teardown's cost lands where it runs: put a collected tree's teardown on the event loop, between tasks and in slices, and re-check ownership when it runs.**
