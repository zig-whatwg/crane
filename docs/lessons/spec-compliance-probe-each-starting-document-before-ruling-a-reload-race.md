# Spec Compliance: Probe each starting document before ruling on a reload race - the initial about:blank answers differently

**Date**: 2026-11-08
**Lesson**: A reload that meets a navigation in flight has two answers in the browsers, decided by the document being reloaded. A loaded document's reload ends the navigation. The initial about:blank's location.reload() leaves the navigation alone. Probe both with a slow response before choosing a rule.

**Why**: HTML gives one answer for every case: "attempt to populate the history entry's document" step 5.1 abandons a reload's population while the navigable's ongoing navigation is a navigation ID. Chrome 156, Firefox 159 and Safari 27 follow that step only for the initial about:blank. Chromium's LocalFrame::Reload returns while the DocumentLoader has no history item, as a frame's initial empty document has none before its first navigation commits. WebKit's NavigationScheduler::scheduleRefresh returns for that document's empty URL. For a loaded document all three end the navigation in flight (WebKit's NavigationScheduler::schedule stops the provisional load). navigation.reload() splits even for the initial about:blank: Chrome and Safari end the navigation, Firefox keeps it.

**What Happened**: html/semantics/embedded-content/the-iframe-element/iframe-loading-lazy-reload-location-reload.html failed 1 in 5 runs on both sides of an A/B, and in generation 210's sweep it failed with "got about:blank". Crane does not model lazy loading, so the iframe's src navigation starts at insertion. The test's location.reload() of the initial about:blank then raced it: the reload's population (HTMLIFrameElement.navigate with a traversal entry) ended the src navigation unless the src's finalize was already queued. A diagnostic line showed "committing=true" in all 30 passing runs. Alone it passed 50/50, and 50/50 under --load=4. A Crane test with a 1 s src failed 3/3 with the sweep's message. The probe page used an eager iframe whose src took 1.5 s, a loaded iframe navigated to it, and an idle initial about:blank, each with location.reload() and navigation.reload(), opened in the background in each browser.

**Fix** (lane flaky5): History.reloadWindow, the location.reload() hook, does nothing while the document is its navigable's initial about:blank and the navigable's ongoing navigation is an ID. This is decided at the call, where Chromium and WebKit decide it. A loaded document's reload, and navigation.reload(), keep the browsers' majority. crane/flaky5-initial-about-blank-reload-keeps-navigation.html pins both of location.reload()'s cases.

**Takeaway**: **Before ruling on how a reload meets a navigation in flight, probe the browsers once per starting document - initial about:blank and loaded - and once per API (location.reload, navigation.reload), with a slow response that makes the race deterministic: one rule rarely covers all four.**
