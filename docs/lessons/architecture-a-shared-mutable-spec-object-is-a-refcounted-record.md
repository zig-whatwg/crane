# Architecture: A shared, mutable spec object is a reference-counted record its sharers hold

**Date**: 2026-10-12
**Lesson**: When a spec says two objects share one value that can change - an origin, whose domain document.domain sets - give every sharer a reference to one record, not a copy each and not a walk to whoever made it.

**Why**: HTML says "origins can be shared, e.g., among multiple Document objects", and the domain of a shared origin is mutable. An initial about:blank document's origin IS its creator's, a srcdoc document's its container document's, a javascript: URL's document's its initiator's, a new Document()'s the associated Document's. A domain set through any of them is every one's. A per-document copy cannot carry that mutation, and a lookup that walks to the creator only works in one direction and only while the creator is still there to walk to.

**What Happened**: Crane kept the domain as a buffer on each Document and serialized origins everywhere else. Window's same-origin-domain check walked from an inheriting document to its creator to read the creator's domain (a stated deviation: a domain set IN the about:blank document set only that document's). html.origin_domain read the domain through the access-checked Window.document getter, whose own check it served. contentDocument read the container document's own null slot when the container was an inherited about:blank document (review S1), and new Document() had no origin to take at all: Document's InternalState.origin was an unused `?*anyopaque`, so its domain getter returned "" (row 22 Q7/Q8). Each fix in the old model added another special case.

**Fix**: dom.origin_record.OriginRecord (lane xorigin): one record per origin, a plain reference count, the domain inside it. A Document holds one reference from construction (its `origin` construction argument, else a record of its own); every inheriting document is made with its creator's record (the navigable's next-document origin, set around each commit); a queued navigation's initiator snapshot holds a reference too, so it outlives a source document torn down before the task runs. Security checks read the record through hooks (dom.document_origin, dom.global_settings), never an IDL getter. Same origin-domain asks identity first: one record on both sides is one origin, opaque or not. The count is not atomic because every holder is on its Browser's one thread (docs/instances.md); builds with runtime safety assert that on every retain and release. Design from WebKit (SecurityOrigin is RefCounted; an inheriting Document shares its owner's SecurityOriginPolicy, which document.domain mutates).

**Takeaway**: **Shared and mutable in the spec means one reference-counted record held by every sharer. Copies diverge on the first mutation, and walking to the creator breaks the moment the mutation comes from the other side or the creator is gone.**
