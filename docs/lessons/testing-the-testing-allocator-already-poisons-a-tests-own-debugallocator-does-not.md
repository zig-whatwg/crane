# Testing: std.testing.allocator already poisons what a test frees; the DebugAllocator a test makes for itself does not

**Date**: 2026-11-05
**Lesson**: Under Zig 0.17, std.testing.allocator is a SafeAllocator whose free writes 0x55 over every small allocation, but a test's own `std.heap.DebugAllocator` writes nothing, so a read after a free passes only through the allocator a race test chose so its threads would not take turns.

**Why**: Zig's test runner, and Crane's copy of it, make `testing.allocator_instance` per test as `SafeAllocator.init(page_allocator, .{ .check_write_after_free = true })`. SafeAllocator's `free` then runs `overwriteFreed`, a `@memset(bytes, 0x55)` over any allocation in a bucket (one under 3/4 of a bucket, 12 KiB with 16 KiB pages). When the bucket is released, and at `deinit`, `checkFreed` panics "write after free" if a byte has changed. A larger allocation goes back to the page allocator, which unmaps it. `std.heap.DebugAllocator` is the 0.16 allocator, kept as deprecated: its small `free` clears a used bit and nothing else, and a slot is never handed out again. tests/AGENTS.md tells a race test to give each Browser its own DebugAllocator, so that the threads do not serialise on the shared allocator, and 77 sites in 50 files did. Every one of them read stale bytes as live ones.

**What Happened**: Lane crashes8 found that the WPT correctness runner's DebugAllocator hid two service-worker use-after-frees, and it fronted that allocator with a Poisoning. Its lesson said "DebugAllocator/SafeAllocator never poisons", and the next brief (poison2) set out to add poisoning to std.testing.allocator. Reading SafeAllocator.zig and the runner's init (`check_write_after_free = true`, tests/test_runner/runner.zig) showed that the testing allocator already poisons. A probe on chat.local confirmed it: a struct read after `destroy` gave 0x5555555555555555 through std.testing.allocator, and its old 0x1122334455667788 through `DebugAllocator(.{ .stack_trace_frames = 0 })`. The gap was the private allocators, which cover the threaded paths the two use-after-frees were on. An earlier lesson had even recorded the 0x55 faults (testing-zig-017s-testing-allocator-faults-on-what-016s-left-readable.md).

**Fix**:
1. `tests/test_runner/poisoning.zig`: one std-only Poisoning, shared by the WPT runner and the tests. `poisoning.DebugAllocator(config)` is a drop-in for std's, with the same `.init`, `allocator()` and `deinit()`, and it writes 0xdd over each block of 32 KiB or less before freeing it. A test reaches it as `@import("root").poisoning`, because the Crane test runner exports it.
2. Every test-made DebugAllocator becomes the drop-in (a type swap), and tests/infra/test_allocators_test.zig fails any file that makes a bare one.
3. `CRANE_POISON_FREES=0` turns poisoning off for one run, in all three places it happens: SafeAllocator's `check_write_after_free`, the drop-in, and the launcher's `MallocScribble=1`, which covers the C++ side.
4. tests/test_runner_fixture/poison_fixture.zig pins this with real processes. Each read after a free fails by name, and each passes with the switch off.

**Takeaway**: **Before you add poisoning, read the free path of the allocator the read actually goes through. Zig 0.17's testing allocator already writes 0x55 over what a test frees; a test's own DebugAllocator writes nothing, so put the poison there.**
