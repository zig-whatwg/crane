# Architecture: What an algorithm needs only while it runs belongs to its run, not to every object it runs on

**Date**: 2026-11-15
**Lesson**: State a specification gives an object but defines as empty or null outside one algorithm (an event's path and currentTarget, outside dispatch) is kept by that algorithm's run - a local of its frame the object points at meanwhile - and state only some objects ever have (an event's relatedTarget keep, a touch target list) is a block made for those objects; neither is storage in every object.

**Why**: A field in the state is paid by every object for its whole life; a local of the algorithm is paid only while the algorithm runs. An inline-capacity list (`infra.List`, four items inline) makes that worse without showing it: the field reads as "a list", and its four inline items - each of which had a four-pointer inline list of its own - were 848 of the 1,024 bytes of every Event, dispatched or not. The browsers had the answer in their headers: WebKit's Event has one weak pointer to an EventPath that is a local of the dispatch, Gecko's WidgetEvent one raw pointer to the dispatch's local chain, Blink's one traced pointer to a collected path; and the related target is a member of MouseEvent and FocusEvent, not of Event, in Blink and WebKit.

**What Happened**: Lane wrap1 measured a kept Event at 1,445 - 1,658 B resident and found the state was the cost. Lane ev1 moved the path to `dom.event_dispatch.DispatchPath`, a local of EventTarget's dispatch with 32 items inline (WebKit's count), then the currentTarget and its slab generation to that same object (DOM's dispatch step 8 makes currentTarget null outside dispatch), the relatedTarget's keep (the kept instance with its generation and realm, and the counted hold: 56 B of zeros in every event without one) to a block made the first time an event keeps a relatedTarget, and the event's touch target list to one pointer. The state went 1,024 -> 176 -> 88 B, and a kept Event 1,508 -> 656 -> 579 B resident (chat2.local, production gc_bench, the slope between 200,000 and 400,000 kept): what is left is the wrapper's side - its cache entry, weak record and handles - and 136 bytes of state. No safety check changed: the same `KeptInstance`, `RefHold` and full-width generations, in a different place. The one new failure mode - the keep's block cannot be allocated - is closed in the safe direction: the event then has no relatedTarget, never an unkept one.

**Fix**: For each field of a per-object state ask three questions, in this order: (1) does the specification define it as empty or null outside one algorithm? Then it is that algorithm's local, and the object keeps at most a pointer to it for the algorithm's length (cleared on every exit: test each one). (2) Do only some objects ever set it? Then it is a block of its own, made on first use and freed at teardown, with its failure mode stated and tested. (3) Is it a list type with inline capacity? Then count its real bytes (`@sizeOf`), and pin the state's size in a test so the next field is a decision.

**Takeaway**: **Before a field goes into a per-object state, read what the browsers keep on that object and where they keep the rest: what the spec makes empty outside an algorithm lives in the algorithm's frame, what only some objects have lives in a block of their own, and `@sizeOf` the state is pinned by a test.**
