# Architecture: An object a V8 snapshot holds and the runtime replaces is kept twice

**Date**: 2026-11-19
**Lesson**: Re-making at run time what a V8 startup snapshot already holds does not replace the snapshot's copy: the isolate keeps the snapshot's templates for its whole life, and every restored context keeps every object it deserialized - so put in the snapshot only what the runtime uses as it is, and make the rest on first use.

**Why**: V8's context serializer sends every TemplateInfo, SharedFunctionInfo, Name and AccessorInfo a context reaches to the STARTUP object cache (src/snapshot/context-serializer.cc ShouldBeInTheStartupObjectCache), which every isolate restored from the blob deserializes and holds as a strong root. And a native context's template-instantiation caches (src/objects/templates.cc CacheTemplateInstantiation) are context fields, serialized with it: each maps a snapshot template - alive in the startup cache - to the function the context instantiated from it. An interface object you replace on the global is therefore still reachable from the context, with its prototype and every operation's function.

**What Happened**: Crane's snapshot held every interface object (~1,140) in both of its contexts, and interface_bindings.registerAllTemplatesOnly made every template again at an isolate's first realm and replaced every interface object of every restored realm (lane tmpl1, tmp/plans/tmpl1-measure.md). Measured with blob variants and V8's heap object statistics after a forced GC: the isolate carried 1.42 MB of snapshot templates it never used (every template-side type exactly halved without them), an iframe realm retained 1,233 KB where 373 KB was its own (perf_bench: 1,388 vs 451 KB per frame), the idle page's footprint was 5.6 MB larger, and every Context::New in the agent (a plain utility global, a worklet realm) deserialized the default context and copied its ~1,140 interface objects onto the new global. Comments in the code called the snapshot's callbacks "stale" - they were not (external references resolve them); the copies were simply never used.

**Fix**: Blink's model (Chromium v8_context_snapshot_impl.cc, idl_member_installer.cc, wrapper_type_info.cc, v8_per_context_data.cc): a plain default context; the Window context made from Window's instance template, whose exposed constructs are lazy data properties of the TEMPLATE; the templates that context was made from attached with SnapshotCreator::AddData and taken back once per isolate with GetDataFromSnapshotOnce (the same TemplateInfo, so GetFunction answers from the restored instantiation cache); every other template made on first use; an interface object built on its first read or first wrap. Exposure ([Exposed], [SecureContext]) is decided when a construct is installed, never installed and then deleted.

**Takeaway**: **Before snapshotting an object, ask whether the runtime uses it as it is. If the runtime re-makes or replaces it, the snapshot copy is not garbage - V8 keeps it (startup object cache, instantiation caches) - and you pay twice. Measure with a blob variant and object statistics after a forced GC, and look for the type counts halving.**
