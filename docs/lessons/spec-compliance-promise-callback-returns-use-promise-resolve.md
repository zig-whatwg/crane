# Spec Compliance: Promise-returning callback functions split between WebIDL 3.2.24 (Streams) and PromiseResolve (Navigation/ViewTransition/Locks)

**Date**: 2026-11-25
**Lesson**: WebIDL 3.2.24's new-promise wrapping (`NewPromiseCapability` + `Resolve(V)`, +2 ticks) is required by WHATWG Streams' `TransformStream` start/cancel microtask invariants, while Navigation, ViewTransition, and Web Locks follow the Chrome+Firefox 2-of-3 browser majority (`PromiseResolve(%Promise%, V)`, 0 extra ticks).

**Why**: In WHATWG Streams, `TransformStream`'s `errors.any.js:253` and `general.any.js:379` (no user `cancel()` callback) require `startPromise` (`a promise resolved with startResult`, WebIDL 3.2.24.1, +2 ticks) to settle *after* the default `cancelAlgorithm` (`createResolvedPromise(undefined)`, 0 extra ticks), whereas `cancel.any.js:79` (user `async cancel()` calling `controller.error()`) requires `TransformerCancelCallback`'s returned `%Promise%` to settle *after* `startPromise` (also +2 ticks, matching WebIDL 3.2.24 and Node.js; Chrome 158, Firefox 161, and Safari 27.2 do not ship `transformer.cancel()` yet). Meanwhile, Chrome 154+ and Firefox 157+ pass all 8 `navigation-api/ordering-and-transition/*-intercept-reject.html` variants (Safari 27 fails) because their bindings pass a same-realm `%Promise%` through unchanged with `PromiseResolve` (0 extra ticks), as live probes of Chrome 157 and Firefox 159/161 also confirmed for `ViewTransition` and `LockManager`.

**What Happened**: In batch B6, switching all Promise-returning callbacks unconditionally to `PromiseResolve` broke `streams/transform-streams/cancel.any.js` (-4 subtests), and switching `streams_js.promiseResolvedWith` to `PromiseResolve` fixed `cancel.any.js` (+4) but broke `errors.any.js` (-8) and `general.any.js` (-4).

**Fix**: Parameterized `engine.invokeCallbackFunctionToPromise` with `comptime resolution: engine.PromiseResolution` (`.webidl` for literal WebIDL 3.2.24, `.promise_resolve` for ECMAScript `PromiseResolve`), generated `invoke` (`.webidl`, used by Streams) and `invokePromiseResolve` (`.promise_resolve`, used by Navigation, ViewTransition, and LockManager with golden rule 2 citations) on all Promise-returning callbacks, and kept `streams_js.promiseResolvedWith` on WebIDL 3.2.24.1 (`createResolvedPromise`).

**Takeaway**: **Keep WebIDL 3.2.24 (`.webidl`, new promise) as the default for Promise-returning callbacks (required by WHATWG Streams' `TransformStream` microtask invariants) and opt stated golden-rule-2 call sites (`Navigation`, `ViewTransition`, `LockManager`) into `.promise_resolve`.**
