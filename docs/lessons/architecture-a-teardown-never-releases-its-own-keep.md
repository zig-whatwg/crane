# Architecture: A teardown never releases its own keep - the keep went with the wrapper first

**Date**: 2026-11-06
**Lesson**: A platform object's teardown runs only after the wrapper that carried its counted keep is gone - collected, or with its realm's end - so releasing its own keep there ends a keep that no longer exists. End a registration's keep at the step that ends the registration (a script call, or the environment's unloading document cleanup), and let the teardown release nothing.

**Why**: `engine.keepPlatformObjectAlive` counts on the wrapper cache entry. While the count is non-zero the wrapper is held, so nothing collects it - except in a detached realm: `WrapperCache.detach` keeps the held wrappers by an uncounted edge from the realm's global object, and when the collector takes the global it takes them too. `finalizeCollected` then unlinks the entry, count and all, and runs the instance's teardown. A teardown that calls `releasePlatformObject` finds no entry: the "released what it did not keep" error. A realm's end is no better - the cache is tearing down and the release is a silent no-op - so the release in the teardown is never right.

**What Happened**: Lane coi2 batch 2. The Debug runner logged "releasePlatformObject on ReportingObserver ... with no keepPlatformObjectAlive left to end" dozens of times per COEP reporting file: the tests make observers in frames (`new frame.contentWindow.ReportingObserver(...)`), observe(), and remove the frames at cleanup. `Observer.deinit` -> `disconnect` released the registration's keep. BroadcastChannel had the same shape (its constructor's keep, released in its teardown when not closed): 31 lines over the 251 COOP/COEP/reporting files, 25 and 6. Both browsers end such holds with the environment: Blink's ActiveScriptWrappableManager keeps no wrapper whose ExecutionContext is destroyed (ScriptWrappableIsActive: IsContextDestroyed), BroadcastChannel::ContextDestroyed closes the channel, Gecko clears the global's mReportingObservers in UnlinkObjectsInGlobal.

**Fix**: Each owner keeps a `kept` flag apart from its registration; observe() (or the constructor) keeps once, and disconnect()/close() and an unloading document cleanup step (dom.unloading_cleanup, installed by the impl's installHooks) release once, while the realm's cache still counts. The teardown clears the flag and releases nothing. tests/html/coi2_keep_release_test.zig: a removed frame, a page the Browser replaces, a page navigated in place, script disconnect/close twice - with slab counts, since FinalizationRegistry callbacks do not run in the unit-test Browser.

**Takeaway**: **A keep ends at the step that ends the hold - a script call or the environment's cleanup - never in the object's teardown, which only runs once the wrapper carrying the count is gone.**
