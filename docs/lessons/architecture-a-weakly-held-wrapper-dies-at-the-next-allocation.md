# Architecture: A wrapper the cache holds weakly can die at your next allocation

**Date**: 2026-10-03
**Lesson**: The wrapper cache hands out its own `Global<Object>*`, and holds it weakly. Until the caller reads it into a Local or clones it, anything that allocates on the V8 heap can run a collection that takes the wrapper, and the first-pass callback empties that very handle.

**Why**: A V8 weak handle keeps nothing alive. Between two hand-backs of one platform object, script may hold nothing of it: the dispatch algorithm holds the event's instance, not its wrapper. Once the handle has been looked up, any of these can allocate: making a string (`String::NewFromUtf8`), a Private, a Set or an Array, or reading a global property that materializes an interface object. Each can start a scavenge. The collection takes the unreachable wrapper, and `unlinkCollected` Resets the handle the caller is still holding. The next `handle->Get()` returns an empty Local.

**What Happened**: `workers/semantics/structured-clone/dedicated.html` crashed in a main round sweep with `panic: member call on null pointer of type 'v8::Object'`, a UBSan report from `v8_Object_SetPrototype` (v8_wrapper.cpp:7339). It never crashed alone. Replaying its 12-file shard prefix in one process crashed 3 runs in 24. The stack went through `wrapInstanceAsV8Object`'s cache-hit path. That path reset the cached wrapper's prototype on every hand-back: it called `v8_GetGlobalPrototype`, which allocates, and only then `SetPrototype(cached_wrapper)`. An instrumented runner logged `v8_Global_IsEmpty(cached_wrapper)` after the lookup and again after `v8_GetGlobalPrototype`. In every crashing run (4 of 4) the handle was live at the lookup and empty after the call, and the object was a MessageEvent being converted for a listener. The earlier files left no stale state behind. They only grew the heap, so a scavenge landed in that window more often.

The reset was also wrong on its own terms. An object a constructor makes takes NewTarget's prototype (WebIDL "internally create a new object implementing the interface"). Resetting it to `globalThis[name].prototype` turned a `class MyEvent extends Event` instance into a plain Event the first time it reached a listener (crane/c5-subclass-wrapper-keeps-prototype.html: 0/3 before, 3/3 after).

**Fix**: On a cache hit, `wrapInstanceAsV8Object` returns the cached wrapper and does nothing else to it. Same prefix: 0/24. Its doc now states the contract: the returned handle is BORROWED and weak, so take your own reference before you allocate. `protocol_support.relevantWrapper` already clones it on the next line. The C++ helpers that take a value handle and allocate before reading it have the same window: `v8_Object_SetPrivateRef` (used by `recordSameObjectEdge` on the first read of every [SameObject] attribute, whose child wrapper is new, weak and unreachable), and `PrivateRefUpdate`, `PrivateSetUpdate` and `RetainInPrivateArray`. Read every handle into a Local first, then allocate.

**Takeaway**: **A `Global*` from the wrapper cache is a weak reference you are borrowing. Read it into a Local, or clone it, before the next thing that can allocate. To trace an empty-handle crash, log `IsEmpty` on the handle before and after each call in between: the call that empties it is where a collection ran.**
