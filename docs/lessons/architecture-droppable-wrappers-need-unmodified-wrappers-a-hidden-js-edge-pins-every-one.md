# Architecture: Droppable wrapper references need unmodified wrappers - a hidden JS edge property pins every one

**Date**: 2026-11-09
**Status**: 2026-11-09 (lane wr1 batch 5) - confirmed: with node tracing's JS edges turned off (runtime.lifetime's test-only `tree_edges`) and the wrapper redesign's walk keeping trees, 2,000 of 2,000 lone dropped `createElement('div')` wrappers are dropped in scavenges (tests/v8/wr8_young_generation_test.zig); with the edges on, 0 (pinned as a known red until P7 deletes them).
**Lesson**: V8 drops a droppable TracedReference in a scavenge only when its wrapper is still an "unmodified API object", and a binding that writes any property on its wrappers - even a private symbol for its own bookkeeping - makes every wrapper modified, so droppable references free nothing.

**Why**: 13.1.203 `TracedHandles::ComputeWeaknessForYoungObject` (src/handles/traced-handles.cc) makes a young traced node weak only if `JSObject::IsUnmodifiedApiObject` holds (src/objects/js-objects.cc): the object's map is still its constructor's `initial_map`, it has no elements and no identity hash. `Object::SetPrivate` is `DefineOwnPropertyIgnoreAttributes` (src/api/api.cc) - a map transition like any expando. The same holds for an instance template with its own properties: `ApiNatives::InstantiateObject` makes the object from the initial map and then `ConfigureInstance` adds them. Blink can drop wrappers because it keeps its DOM tree edges in C++ (Node::Trace); a binding whose tree edges are JS properties cannot.

**What Happened**: The wrapper redesign's P4 made node slots non-droppable TracedReferences, and dropped wrappers lived until the next full collection (perf pair memory 1.178). The plan was to fold P8 in: droppable slots plus an EmbedderRootsHandler (Blink's BlinkRootsHandler). Built and tested (tests/v8/wr8_young_generation_test.zig), it dropped 0 of 2,000 dropped `createElement('div')` wrappers in scavenges. Every node wrapper gets a private upward edge at its wrap (wrapper_cache setNode: `drawTreeEdges` to the parent, `drawDocumentEdge` to the node document for a root). A probe on the binding's own wrapper shape (`v8_test_NodeTemplateWrapperDroppable`) separated the causes: a bare HTMLDivElement template instance IS dropped, also after `SetPrototype(globalThis.HTMLDivElement.prototype)` (that is the template function's own prototype, so no transition); one private property keeps it; a Document's template instance is never dropped (its [LegacyUnforgeable] members are instance properties).

**Fix**: Keep the droppable references and the handler (they are what Blink does), but know they take effect only once node tracing leaves JS properties (the redesign's P5 walk and P7 edge removal). Until then the choice is a weak slot (P2's semantics) or the non-droppable traced slot's memory cost. Probe the engine's own answer on the exact wrapper shape before designing around a GC feature.

**Takeaway**: **A GC feature keyed on "unmodified" objects is defeated by any property the binding itself writes. Before relying on droppable wrappers, prove on the real wrapper shape that the engine would drop it - and list every property the binding adds at wrap time.**
