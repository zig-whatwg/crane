# Architecture: An engine API with an embedder half appears when the embedder registers it

**Date**: 2026-10-18
**Lesson**: WebAssembly.compileStreaming and instantiateStreaming were missing from every realm, and WPT's wasm/webapi/ blocked 15 files, because V8 defines them only on an isolate whose embedder has set a WasmStreamingCallback - not because Crane failed to bind its IDL.

**Why**: The WebAssembly Web API's IDL is a `partial namespace WebAssembly`, which reads like something the bindings should add. But V8 owns WebAssembly (docs/lessons/architecture-v8-owns-webassembly-and-it-finishes-work-only.md), and for these two members it owns the JavaScript half too: `WasmJs::Install` (13.1 wasm-js.cc:3459, run for each new context, never into a snapshot) adds both functions when `isolate->wasm_streaming_callback() != nullptr`, does `Promise.resolve(source).then(...)` itself, and calls the embedder's callback only with the fulfilled value and a `WasmStreaming` to feed. Every browser splits it this way: Blink's v8_wasm_response_extensions.cc, SpiderMonkey's ConsumeStreamCallback (Gecko FetchUtil), JSC's GlobalObjectMethodTable::compileStreaming (WebCore JSDOMGlobalObject).

**What Happened**: Generation 156 had wasm/webapi/ at about 800 failing subtests, every file "WebAssembly.compileStreaming is not a function". src/webidl/impls/WebAssembly.zig had call_compileStreaming returning NotImplemented, which suggested writing it - but that impl is never bound (engine_provided_namespaces), and binding the partial namespace over V8's object would have meant re-implementing V8's promise handling, realm choice and instantiation outside the engine.

**Fix**: lane wasmweb1. The protocol gained capability `webassembly_streaming`, the hook `HostHooks.compilePotentialWebAssemblyResponse` (the Web API's steps 2.1-2.8, in html/webassembly_streaming.zig) and three operations on the `WebAssemblyResponseCompilation` it hands over: append bytes, finish (with the response URL, which names the module in stack traces), abort (with a reason, or none). The V8 adapter sets the callback in createAgent, before any realm exists, only for an agent with the hook; it keeps the agent's live compilations, ends V8's side of each at its realm's end unsettled, and frees what the host never ended at the agent's end, before the isolate (whose WasmStreaming it holds) is disposed. JavaScriptCore's public C API has no such hook, so there the two functions stay absent, declared.

**Takeaway**: **Before binding an IDL member onto an engine-owned object, look for the engine's embedder hook for it: the engine defines the member itself once the embedder registers its half, and the design is the engine's split, not a binding.**
