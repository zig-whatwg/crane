# Architecture: An embedder with ICU's data linked in still sets ICU's default locale itself

**Date**: 2026-11-22
**Lesson**: Building V8 with `v8_enable_i18n_support = true` and `icu_use_data_file = false` gives one self-contained binary whose V8 needs no icudtl.dat, but ICU's default locale - what Intl and the locale-sensitive String methods use when a script names none - still comes from the process's LANG / LC_* environment unless the embedder sets it, as Chrome and d8 do.

**Why**: V8 reads the default once per isolate from `icu::Locale::getDefault()` (src/execution/isolate.cc `Isolate::DefaultLocale`, mapping `en_US_POSIX` and `c` to "en-US"). ICU fills that default from the environment (uprv_getDefaultLocaleID). Chrome sets it to the browser's locale before its renderer runs script (base/i18n/rtl.cc `SetICUDefaultLocale`), d8 to its `--icu-locale` right after `InitializeICUDefaultLocation` (src/d8/d8.cc). V8 has no public API for it, so the embedder calls ICU's own C API, which needs ICU's public headers and the defines GN compiles ICU's consumers with (`//third_party/icu:icu_config`).

**What Happened**: Lane icu1 rebuilt Crane's V8 15.7.112.43 archive with ICU (the user's ruling, 2026-11-22: "Rebuild with ICU") so that `\p{...}`, `normalize`, the locale-sensitive case mapping and comparison, and V8's own Intl exist (without ICU `\p{L}` was a SyntaxError, which blocked Puppeteer's injected query handlers and the Monaco editor). With the data linked in, `InitializeICUDefaultLocation` returns true at once (src/init/icu_util.cc, `ICU_UTIL_DATA_STATIC`: "Use bundled ICU data"). Crane's navigator.language is the platform's first preferred language ("en-US"), so without the embedder's step a host with `LANG=de_DE.UTF-8` would format `new Intl.DateTimeFormat().format()` in German beside an en-US navigator. Two more facts the rebuild needed: the archive went into a NEW directory (jsengines/v8/15.7.112.43-icu) beside the first one, because every lane's mirror on a pool host links the shared jsengines/v8 - replacing it in place would have changed the engine under other lanes' A/Bs and cost windows; and Crane's own Intl binding (4,513 lines over CLDR tables) had to go with it, or it would have kept replacing V8's Intl on every Window realm (and workers, which it never covered, had no Intl at all). What ICU costs, measured: libv8_monolith.a +20.1 MB (macOS) and +25.2 MB (Linux); the release console 93.3 -> 107.0 MB (+13.7 MB, nearly all __TEXT: ICU's code and its 10.8 MB of data); an idle page's footprint 12.37 -> 12.44 MB (median of 9 launches each, MallocLargeCache=0) - the data is mapped read-only and costs memory only where a page touches it.

**Fix**: scripts/build-v8-15.7.sh installs ICU's public headers (icu/include/unicode) and the consumer defines read from the compile command of V8's own src/objects/intl-objects.cc (icu/flags.txt); the V8 adapter's build file compiles v8_wrapper.cpp with both; `v8_Platform_StartWithDefaultLocale` calls `uloc_forLanguageTag` + `uloc_setDefault` once, under the start's lock, before any isolate exists, with the platform's preferred language (snapshot_loader.zig `icuDefaultLocale`, sanitized as navigator.language's list is). The build script's smoke program does the same and checks that V8's Intl answers the locale it set.

**Takeaway**: **ICU's data in the binary answers "where is the data", not "which locale": an embedder sets ICU's default locale from its own language setting before the first isolate, through ICU's C API - and a rebuilt engine archive goes beside the old one on shared hosts, never over it.**
