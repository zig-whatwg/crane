# Debugging: An engine upgrade changes the collector's defaults - diff the flags and the heap's configuration first

**Date**: 2026-11-12
**Lesson**: Between two versions of a JavaScript engine the collector's POLICY changes as much as its code: initial limits, the young generation's ceiling, what counts toward which limit, when a space shrinks. Diff those defaults before measuring; they are the first hypothesis for any memory or pause difference.

**Why**: V8 13.1 -> 15.7.112.43 changed, with no API change and no release note the port read: `preconfigured_old_space_size = 32` (flag-definitions.h:2542; new - the heap starts with a 32 MB old-generation and 64 MB global limit that survival statistics no longer shrink, heap.cc:2321, and a top-level context disposal no longer resets, heap.cc:1798); the scavenger's semispace ceiling 8 MB -> 32 MB (13.1 flag `scavenger_max_new_space_capacity_mb`, gone; heap.cc:4844-4860); the new space shrinks on the SMOOTHED allocation throughput, not the current one (Heap::ShouldResizeNewSpace); external memory always counts toward the global limit, and a report no longer advances or finalizes marking (13.1 HandleExternalMemoryInterrupt -> 15.7 UpdateExternalMemory, heap.cc:6987-7040: collect only at a large overshoot); the memory reducer's start delay 8 s -> 30 s. Chrome 157 ships every one of these defaults (gin/gin_features.cc: the matching features are `kFeatureDefaultStateControlledByV8`).

**What Happened**: The port's memory gap (suite geometric mean 1.25 of main) was chased for three batches as a Crane bug. Three of its four mechanisms were these defaults: fewer and later collections, a larger young generation - the same changes that make the port 10% faster. Capping the semispace at 13.1's 8 MB took the suite to 1.05 at a cost of 5-24% time on eight stream, microtask and fetch rows; switching the preconfigured size off made memory WORSE (external memory then waits for a 1 GB initial global limit to shrink).

**Fix**: None in code for the three: they are the engine's time-for-memory trade, reported to the user with the numbers per flag. The diff that would have named them on day one: `diff <(grep -n 'DEFINE_' old/src/flags/flag-definitions.h | grep -i -E 'semi|old_space|heap_size|memory_reducer|external|gc') <(same for new)`, and Heap::ConfigureHeap side by side.

**Takeaway**: **On an engine upgrade, diff the collector's flag defaults and its heap configuration between the two versions - initial and maximum size of each generation, what counts toward which limit, what resets or shrinks them - and check which of them the reference browser ships, BEFORE treating a memory or pause difference as the embedder's bug. Policy the engine changed on purpose is a ruling for the user, not a defect to chase.**
