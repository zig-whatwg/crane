# Architecture: A dead wrapper's finalizer is queued in the collector's first pass - a second pass is a collection late

**Date**: 2026-11-12
**Lesson**: V8's second-pass weak callback is not "right after the collection": V8 posts it as a task, and in a script that does not return to the event loop it runs at the start of the NEXT collection. Work that only has to happen outside the collection belongs on the embedder's own queue, filled in the first pass.

**Why**: Lane v8up b6 moved the Zig finalizers out of V8's second pass (15.7 runs it under DisallowJSObjectModification) onto the agent's queue, and kept the second pass as the thing that queued them. V8 posts that pass as a task (15.7.112.43 src/handles/global-handles.cc:892-901) and runs a pending one first when the next collection begins (src/heap/heap.cc:1509-1511). So a wrapper scavenge k found dead was finalized after scavenge k+1 had begun: the native state of TWO young generations of dead wrappers was alive at once. Main (V8 13.1) had the same delay with half the young generation - 15.7 keeps a 2 MB semispace where 13.1 shrank to 1 MB (Heap::ShouldResizeNewSpace reads the smoothed allocation throughput, 13.1 read the current one), and lets it grow to 32 MB where 13.1 capped the scavenger at 8 MB.

**What Happened**: The perf pair's dom.event-ctor ended at 208 MB on the port against 148 MB on main. Accounted by owner at its end mark (vmmap regions, V8's heap by space, cppgc, the external figure): 113.5 MB of the difference was Event state blocks (main: 70.1 MB) - 2 x 54,000 Events x 1.05 KB against 2 x 23,000. With the record queued in the first pass the same mark read 66.8 MB of state and 153.5 MB in all, and the suite's memory against main went from 1.246 to 1.165 with time 0.982 and instructions 0.993 of the unchanged tip (the finalizers run a collection earlier, on warmer state).

**Fix**: The first-pass callback Resets the handle, does its bookkeeping and pushes the record on the agent's queue (`queueFinalizer`: a list push and one byte stored - no V8 API, nothing of Zig's); no second pass is set. The queue's safe points and rules are unchanged. Two tests pin WHEN the record joins: one scavenge, then the script's next binding exit runs the finalizers with no second collection and no pump; the collection an external-memory report runs is finalized when that report returns. Precedent: Node.js deletes the native object in the first pass (src/base_object.cc:59-71 -> base_object-inl.h:112-114); Blink has no pass (a wrappable is a cppgc object, finalized when its page is swept).

**Not for node wrappers (same batch)**: a node wrapper's release keeps its second pass - an earlier release slips past refcount step 7a's net (architecture-moving-a-release-earlier-opens-a-net-that-only-looked-when-it-came-late.md).

**Takeaway**: **A weak callback's second pass is for work that needs the engine's API inside the collection's own processing. If the work only has to run "after the collection, at my safe point", queue it in the first pass: the second pass arrives a task later, or - in a long script - a whole collection later, and everything the dead object owns stays alive for one more young generation.**
